# ADR 0038: The Agent Teams Loose Ends: Task Tools Offered, Delegation Tools Guarded, Tests Before Code

- **Status**: Accepted — 2026-10-04 (maintainer, in chat: "agents start injects `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`: yes", "widen to delegation tools: yes", "re-order so tests come first: yes", then, after an explanation, "bind Open items only" for the Tier-1 report sections). Closes the open questions ADR 0036 and ADR 0037 left for the maintainer, and one finding of the live team re-run. Builds on ADR 0035 (guards as script files), ADR 0036 (Tier-2 on Agent Teams) and ADR 0037 (the created lane retired).
- **Context**: Prior art searched first: `ClaudeLauncher.planActivation` (the only place the teams variable is set), `READ_ONLY_GUARD_SCRIPT` and its matcher, the suite that pinned the guard's gap (`tests/native-claude-readonly-attempt.test.ts`), the declared delta for `backend-architect` in `registry/hosts/claude/deltas.json`, and the teammate wording of the four teammate-capable bodies. Evidence: the PetPal live-team re-run (session `123266e9`, Claude Code 2.1.289, 1.04 USD, recorded in `host-library/claude/observations/2026-10-04-claude-2.1.288-agent-teams.md`). The lead found the Task tools after `ToolSearch`, built the Assembly Line as three dependent tasks and completed them itself; the two teammates that had a task never loaded the Task tools (they arrive as deferred tools whatever the role's `tools:` list says) and reported "could not mark task completed". Before this ADR: `agents start` set only the teams variable, so a session on a newer model had no Task tools unless the user set the second variable; the read-only guard refused writers and mutating server tools but not `Agent`, `Workflow`, `CronCreate`, `EnterWorktree`, `Artifact` or `SendUserFile` (withheld from a reviewer by its allowlist alone, pinned as a gap); `backend-architect` listed implementation before tests against its own test-first invariant (declared as a delta).
- **Decision**:
  1. **`agents start` sets `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` together with `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`**, whenever teams are on (organization tier by default, `--teams` explicit, `--no-teams` off). Same rules as the teams variable: injected into the spawned process only, never in argv, the prompt or any workspace file. With teams off, neither is set. The lead's body says `agents start` sets it and that a session started any other way needs it by hand.
  2. **The read-only guard widens from writers to anything that hands work or output outside the role**: `Agent`, `Workflow`, `CronCreate`, `EnterWorktree`, `Artifact`, `SendUserFile`, with its own short reason (`<tool> would hand work or output outside this role, and this role only reads and reports.`). The matcher is anchored by the host, so `Agent` does not catch `ListAgents` and `CronCreate` does not catch `CronList`. Coordination stays open: `SendMessage`, `ToolSearch`, `ListAgents`, `SubagentHandback`, the Task and Cron listings. Tools outside the six (`RemoteTrigger`, `Monitor`, `TaskStop`, and any later tool) stay withheld by the allowlist alone; adding one is a one-line change in the script and the matcher, and the attempt suite names the six. The suite that pinned the gap is replaced by real attempts at each tool against both read-only roles as installed, in both layers (allowlist, guard) and through the guard alone when a later edit grants the tool.
  3. **`backend-architect` works test-first in its own steps**: contracts, then a "Test first" step (author the failing tests, run them, keep the failing output the orchestrator asks for), then implement until they pass, then prove. Its declared delta is removed; the invariant is evidenced by `Work test-first: the failing test comes before the implementation`.
  4. **A teammate loads what arrives deferred.** The four teammate-capable bodies (`frontend-architect` and the three agency roles) say that `SendMessage` and the Task tools reach a teammate as deferred tools and name the call (`ToolSearch` with `select:SendMessage,TaskGet,TaskUpdate`), and that without the Task tools the teammate leaves the status to the lead and says so under `Open items`.
  5. **The Tier-1 specialists bind `Open items` in their own body.** `backend-architect`, `code-reviewer` and `repo-index` each state that their report always ends with an `Open items` section (what they could not do or verify, a question for the orchestrator, or "none"), so it no longer depends on the lead's brief template. `Peer messages received` stays a declared delta, with the rationale rewritten: a hub-and-spoke specialist never receives a peer message, so the section would always read none. Tested in `tests/native-claude-tier1-open-items.test.ts`.
- **Consequences**:
  - Positive: a team on a newer model has the shared task list without a manual variable; a reviewer cannot be talked into delegating, scheduling or publishing by a later edit that grants the tool; the specialist's text now matches its core.
  - Negative: a role installed before this change keeps the narrower guard and the old wording until the native roles are installed again (the managed files are refreshed on install); the read-only guard now has two failure reasons to maintain; two environment variables are set for a team, both experimental host switches that may change in a release.
  - Not established: that a teammate can load and call `TaskUpdate` (the host lists the tools as deferred for it; no teammate has tried); `agents start` with both variables in a live session (its dry run and the launcher tests only).
  - Open: widening the read-only guard past the six tools.
