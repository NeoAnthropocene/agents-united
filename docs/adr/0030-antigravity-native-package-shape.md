# ADR 0030: The Antigravity Native Package Shape

- **Status**: Accepted — 2026-10-02 (product owner: "go for the next", the order fixed in ADR 0026: guides, profile and tool policy, native package, install lane; ADR 0026 left Antigravity's own version of this ADR open). Builds on ADRs 0025 to 0029; does not amend them.
- **Context**: Prior art searched: `host-library/antigravity/guide/*.md` (eleven guides, every rule citing a snapshot), `docs/host-primitive-matrix.md`, plan 031 and its addendum (probes on agy 1.2.14), ADRs 0002, 0011, 0016, 0021 to 0028, `registry/agents/` (the origin dialect), `src/core` for the legacy Antigravity lane, `registry/hosts/claude` and `registry/hosts/cline` (the profile and tool-policy format), the installed `agy` 1.2.14 and its `agy changelog`. What the evidence says: Antigravity's documented agent file is the one this repository started from, but a frontmatter `hooks:` key hides an agent from discovery, `--agent` and `invoke_subagent`; a hooks file is workspace-wide; the permission engine and presets exist on macOS and Linux only; workflows are deprecated for skills on 2026-11-01; the docs snapshot (CLI 1.2.11) lags the installed CLI (1.2.14, release notes to 1.2.15).
- **Decision**:
  1. **The profile is pinned to the CLI release line.** `registry/hosts/antigravity/profile.json` takes `version`, `minVersion` and `reviewedAgainst` from the "Antigravity CLI" section of the library's changelog baseline (1.2.11; 1.2.11 is also the release that fixed project-agent discovery). The docs changelog lags the CLI, so `agy changelog` is a second source for the host-update workflow, which is a later slice.
  2. **The catalog is the hooks-page vocabulary.** `tool-policy.json` lists the twenty tools of the hooks page, the names an agent's `tools:` and a hook matcher use. The SDK page's identifiers (`create_file`, `start_subagent`, ...) are recorded in the policy's text only, because no mapping between the two sets is documented. Tools no engineering role should hold (`list_permissions`, `ask_permission`, `generate_image`) are class `meta`, never granted. There is no skill tool: skills are read through `view_file`.
  3. **A native agent has no frontmatter `hooks:`.** The profile's allowed agent keys are exactly the documented frontmatter table. Guards ship as real command hooks in `.agents/hooks.json` (a reviewed script, audit gate, the same three patterns as the Claude and Cline guards).
  4. **Read-only is a promise until a probe says otherwise.** Cline's `tools:` list is host-enforced (observed); Antigravity's is documented only as "permitted tools", and no probe has asked a restricted agent to write. The native agents slice therefore probes enforcement first, and until it does the read-only roles hold no writing tool and a `PreToolUse` guard backs them.
  5. **The orchestrator can be a file-defined main agent.** Unlike Cline, Antigravity applies a main agent through `--agent` and the `/agents` panel, and a main agent reaches workspace specialists by name through `invoke_subagent` (plan 031). The orchestrator therefore ships as an agent file with `mainAgent: true` that names `invoke_subagent` and the exact specialist names, not as a rule and skill.
  6. **No workflows, no permission rules, no user settings.** The package authors no workflow (deprecated; every skill is already a slash command), writes no `command(...)` rule and edits no `settings.json`; presets and rules are the user's.
  7. **Verification and budget.** The native agents slice is the first that needs a real `agy` session. Before it, the maintainer is told which account it spends (the Google sign-in behind `agy`, with its plan quota), the rough cost, and answers; standing permissions for other hosts do not transfer. Anything sandbox-related needs a macOS or Linux run, because the maintainer machine is Windows.
  8. **Specialists are subagent-only, the orchestrator is the one main agent** (added with the native agents slice). The four specialists carry `mainAgent: false, subagent: true`, so they do not clutter the `/agents` panel; the orchestrator carries `mainAgent: true, subagent: false`. Frontmatter holds only `name`, `description`, `tools`, `mainAgent` and `subagent`: `model`, `skills`, `mcpServers` and `commandExecutionPolicy` are left to the host default until their effect is verified or their slice lands. Specialists hold `send_message` because the messaging class is in their cores, and their text says to use it only to answer the invoking agent.
  9. **Native rules carry a valid trigger** (added with the native rules slice). The docs say every `.md` in `.agents/rules/` must start with frontmatter declaring a trigger or it is silently discarded, and the legacy lane installs the registry rules there with none. The native rule is the registry rule's text, generated verbatim after authored frontmatter: `git-guardrails` and `test-driven-development` are `always_on` (the safety and test-first rules), the other four `model_decision` with a description that begins "Apply when", so they cost a pointer until needed. A rule never uses `@[label](path)` (Antigravity-only syntax), and the `always_on` set stays well inside the 20,000-token aggregate. That the legacy files are really dropped is unverified; the install lane decides what happens to the frontmatter-less files already in `.agents/rules/`.
  10. **The guard is a command hook that answers only `deny` or `ask`** (added with the guard slice; contract observed in real sessions). `registry/hosts/antigravity/hooks/` holds `hooks.json` (one hook, `PreToolUse`, matching exactly the shell and editing tools of the catalog) and `agents-united-guard.js` (one dependency-free file, the same four patterns as the Claude guard, tied by a drift test). Installed as `.agents/hooks.json` and `.agents/hooks/agents-united-guard.js` with the command `node hooks/agents-united-guard.js`, because the hook runs with the folder holding `hooks.json` as its working directory. The host treats an answer with no `decision`, non-JSON output and a non-zero exit as a block, so the script always answers; for a call it does not block it answers `ask`, which falls back to the user's permission settings, and never `allow`, which would override a prompt. It covers subagent calls. An existing `hooks.json` of the user is merged by the install lane, never overwritten.
- **Consequences**:
  - Positive: the profile and policy are pinned to the docs tables by tests, so a refresh that changes a key, an event or a tool fails in the host-update PR; the load-bearing finding (no frontmatter hooks) is data, not folklore.
  - Negative: the profile is pinned to a version older than the installed CLI, so some facts are marked observed or unverified until the changelog gap is closed; read-only roles lean on a hook until enforcement is shown.
  - Open: what a `tools:` list enforces; whether `skills:` and `mcpServers:` in agent frontmatter resolve; parallel `invoke_subagent`; a hook's failure mode and whether it sees a subagent's calls; the `agents.json`, `skills.json` and `plugins.json` registries of the release notes; the IDE and 2.0 surfaces; MCP wiring.

## Addendum (2026-10-02, real sessions on agy 1.2.15)

Real sessions settled three items (observations, `host-library/antigravity/observations/2026-10-02-agy-1.2.15.md`). **Decision 4 is settled the other way:** a `tools:` list is enforced by the host, so a read-only role is read-only because it holds no writing tool and needs no hook; a restricted agent could not write while a control with `write_to_file` could. The guard hook remains the extra layer for the roles that hold a shell or an editor. **Decision 5 is confirmed:** the orchestrator, a file-defined main agent, called `invoke_subagent` with `Prompt`, `Role`, `TypeName` and `Workspace`, and the native specialist answered by name; the workspace copy won over same-named agents in the global directory (observed once). **Decision 9 is confirmed:** with the legacy frontmatter-less rules the agent saw none of them, with the native rules it saw the two `always_on` ones. Still open: that the runs of several specs in one call overlap in time (they were created together, the tasks were too short to tell), a hook failure mode and whether a hook sees a subagent call, whether `skills:` and `mcpServers:` in frontmatter resolve, the sandbox on macOS or Linux, the IDE and 2.0 surfaces, and whether the orchestrator follows its full text on a real task.
