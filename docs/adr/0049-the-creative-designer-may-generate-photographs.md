# ADR 0049: The creative designer may generate photographs through an optional image server

- **Status**: Accepted, 2026-10-08; amended 2026-10-09 (the pin, the providers, the rules in a skill). Plan 036 Q2 and Q9. The maintainer's words of 2026-10-08: "For the Photographic image creation needs you can use the MCP. You can give the option to install the MCP and wire an MCP usage skill for image creation ... it will need to wire those new image generation MCPs for Claude agent", and, asked which provider: "Gemini with my AI Studio key." The words of 2026-10-09 are under **Decided by the maintainer** below. **Built in slices**, in the order of ADR 0047: the skill `image-creation` and the install route in `mcp-setup` (S18, merged), then the grant, the lead's offer and, with the amendment, the providers and the skill `image-generation` (S19). **Run live once, 2026-10-09** (Sitting L, `host-library/claude/observations/2026-10-09-claude-2.1.294-designer-h10d-image-route.md`): the maintainer ran the live test H10d in `docs/live-test-protocol.md` with their own Gemini key. H10d1 met its pass line, H10d2 met it but for the rung in the report, and H10d3 did not: the text she had loaded let a file from outside the project through, and the text was corrected. H10d3 was run again on the corrected text (Sitting M, 2026-10-09, `host-library/claude/observations/2026-10-09-claude-2.1.294-designer-h10d3-rerun.md`): no call, nothing left the project; two softer items (asking for the user's word, offering the placeholder) were missing from the text she loads and were added. Sitting N (the closing runs H10d4 to H10d7 and H10d3 again, `host-library/claude/observations/2026-10-09-claude-2.1.294-designer-h10d-closing-runs.md`) covered a path written in a brief, an edit of an earlier output, a provider whose key is not set and a real person's likeness: 27 of 34 pass-line items met, and each miss was a line her loaded text lacked. OpenAI and Seedream have not been called.
- **Context**: Claude cannot make an image (Anthropic's vision documentation), Claude Code has no image tool (`registry/hosts/claude/tool-policy.json`; the Translation Ledger records `generate_image` as unsupported on this host), and the creative designer holds no shell (ADR 0039), so her only route to a raster picture was one that someone supplied, or a placeholder. Plan 036 had decided (Q2) that a generated-image route would be an optional extra, offered when a brief needs photography and none is supplied, never required. The baseline did not show the failure (F2 not seen in H10c: she followed an honest path), so the route repairs no seen defect: it adds a capability the maintainer asked for. Prior art read first: `docs/skill-quality/creative-designer-evaluation.md`, ADR 0041 (routes and optional extras), ADR 0047 (a grant taught by a skill first), Plan 035 D44 to D57 (the lead's provisioning path), `src/core/claude-mcp-routes.ts`, the providers' own documentation and pricing pages, and the source of `mcp-image` (below). The facts that shaped the decision: a server's image result reaches Claude as a path, and a shell-less role cannot move a file, so the server must write inside the project; the image models of all three providers have no free tier; every prompt, and every input photo, goes to the provider; **the server reads any image path a call names and has no check that the path is inside the project**, which matters because the file then leaves for the provider.
- **Decision**:
  1. **One optional server, named `image-gen`**: the `mcp-image` package pinned to **0.18.0**, the number the `latest` tag pointed to on 2026-10-09 (published 2026-10-08; MIT, one maintainer). The first version of this record pinned 0.14.0 by the rule "the newest release older than two weeks on the day it is read"; the maintainer replaced that rule on 2026-10-09 ("Use the latest tag of the package"). It is pinned to the number, not to the floating tag: a floating tag would run an unread release with the user's keys at every start. A newer release is adopted by reading what changed (`npm pack` into an empty folder, a diff of the `dist` files against the pinned version, a search for subprocess, `eval`, network, environment and file use) and changing the reference and its test together. Read for 0.18.0, not run: no install script, no npm provenance, the same three dependencies as 0.14.0, 3 new small modules and 11 changed files against 0.14.0 (reference images, a newer default Gemini model, model names for prompt rewriting that the install turns off), no subprocess, no `eval`, one `fetch` (to BytePlus), file writes only of the image and its folder. The findings are in `mcp-setup`'s Claude reference.
  2. **The user runs the install.** The lead asks which provider keys the user has, prints one command with the placeholders of those providers, and the user runs it in their own terminal, in the `local` scope: the lead never runs it, never asks for a key in the chat and never writes one anywhere. The command sets `SKIP_PROMPT_ENHANCEMENT=true`, so the prompt she writes is the prompt that is sent and recorded and an image costs one call, and `IMAGE_OUTPUT_DIR` inside the project.
  3. **Three providers are wired**, with a key pair each: Gemini (`GEMINI_API_KEY`, the default), OpenAI (`OPENAI_API_KEY`, GPT Image 2.5) and BytePlus Seedream (`ARK_API_KEY`, ModelArk in the AP region). `IMAGE_PROVIDER` names the default and a call's `provider` overrides it; a provider whose key is not set fails with a message for the lead. The facts of each (models, sizes, ratios, reference limits, prices, where the words go) are dated in the skill `image-generation` (`references/providers.md`), and `call-check.mjs` holds the same numbers. Three of them shape what she does: OpenAI publishes no price per image, so its first image is a probe and the user sets the ceiling after reading the charge; Seedream optimises the prompt on BytePlus's side, so the recorded prompt is the prompt sent, not the prompt the model saw; and the default Gemini model of this version (`gemini-nano-banana-2.1`) costs about half, at 1K and 2K, of the model that 0.14.0 called.
  4. **One tool, one role.** `agency-creative-designer` gets `mcp__image-gen__generate_image` and nothing else of that server; no other role gets it. Providers are chosen by a parameter of that tool, not by more tools.
  5. **Not required.** The server is not in any bundle's `requiredMcps` and not in any canonical agent's `mcpServers`, so the doctor, the install gate, the lead's mode counts and the Antigravity MCP sync do not move, and Antigravity keeps its own `generate_image`.
  6. **The how lives in two skills.** `image-creation` carries the sourcing ladder, the go-ahead, the cap of two regenerations, the look at the saved file and the provenance file; `image-check.mjs` is for the roles with a shell. `image-generation` carries the tool: the nine rules a generated picture lives by, the choice of provider, the parameters and their errors, the rule for input images, a go-ahead card, a worked example, sixteen recipes for various cases whose calls a test runs through the checker, and `call-check.mjs`.
  7. **The lead offers it as a choice with its explanation.** When a plan holds a photograph-like asset that nobody supplied, the lead offers **Generate images** beside **Placeholders and image briefs** with `AskUserQuestion`, and the option's description says who pays, which providers there are, where the words go, what the user does themselves and that the team restarts. The go-ahead names how many images, which provider and at which size.
  8. **The floor does not change; a skill carries the rules.** The bullet on generated imagery (finding F8) and the guard on the paths the server reads were proposed to the maintainer; the maintainer chose a skill for both (below). The nine rules are in `image-generation`, in her body and in the lead's paragraph, and the floor is untouched (ADR 0021).
- **Decided by the maintainer, 2026-10-09**: asked about the last open questions of this record, the maintainer answered (a) "Use the latest tag of the package" (the pin, Decision 1); (b) "yes wire other image providers" (Decision 3); and (c), asked about a floor bullet on generated imagery and a guard for the image path, "Create a detailed skill to cover that and make sure subagent can use this skill", with the upstream prompt skill as a "shallow example" to go beyond and "usage prompt examples for various cases" (Decisions 6 and 8). "Make sure subagent can use this skill" was done as follows. She holds `Skill`; the skill is in the `digital-agency` and `full` bundles, so the installer projects it into the project; it is in her skill table; her body restates the hard rules and says to load the skill before any call; the lead's paragraph tells her to load it; and tests pin each of these. A `skills:` preload in her definition is deliberately not used: a teammate does not apply a definition's `skills` in either display mode (`host-library/claude/pages/orchestration/agent-teams.md`, "Use subagent definitions for teammates"), and this team runs as teammates, so the field would do nothing; the skill is loaded on demand and the rules that must hold at once are in her body, which does apply.
- **Consequences**:
  - Positive: she can fill a brief that needs a photograph, within a stated cost and with a record of what was asked, by whom and at what price; the user chooses among three providers with their own keys and may keep Gemini only; a placeholder with an image brief stays a complete deliverable, so nothing is blocked while the server is not connected; the rules a hook would have enforced are written down, taught, tested against the recipes and runnable as a check.
  - Limits: the prompts, and any photo named for editing, go to the provider the call names, under the user's key; each provider's account is billed per image and none has a free tier; a third-party package with one maintainer and no npm provenance runs with the user's keys, so the pin, the read and the refresh rule are the control, and its dependencies are version ranges that `npx` resolves on the day; the server overwrites a file of the same name and creates the folder, so the skill never reuses a name; a running session does not load a server added after it started, so the team restarts; the pinned version calls model names, and providers retire models, so the pin is refreshed when a notice appears; OpenAI's price per image is unknown until measured.
  - **Prose is not enforcement.** A rule in a skill, a role body and a lead's paragraph is followed by a model that has read it; it does not stop a model that an instruction hidden in a page or a file has persuaded to pass `inputImagePaths` with a picture from outside the project, which the server would read and send all the same. What the skill adds is a statement of the rule, a table of which files may go, an executable check (`call-check.mjs`, for a role with a shell: the lead runs it on a plan), a record of every input file in the provenance files, and a live test (H10d3). The only enforcement remains a `PreToolUse` hook on the tool that refuses a path outside the project. The maintainer chose the skill; the hook is not built, and `call-check.mjs` is its logic, so it would be a small slice if wanted. The first live run showed both halves (H10d3, 2026-10-09): she followed the text she had loaded, which let a typed path through in two places, and the permission mode `auto` let the call go with no denial. The text is now one rule in every place she reads it; the hook is still the only thing that refuses.
  - Not established: a call to OpenAI or Seedream; the real Google charge (about 0.05 USD an image by the price table, not read from a bill); that she holds the refusal of an outside path over several runs (one run held it, Sitting M), that she then asks for the user's word and offers the placeholder (added after that run; Sitting N runs H10d3 again), and a path read from a brief (eval 5, H10d4, not run live); how her prompts compare with the providers' guidance; whether the label rule needs a stricter statement; OpenAI's price per image and its organization verification for a given account. Established by the first live run, for Gemini only: the install form with four `--env` values connects through `npx` on Windows with no `cmd /c`; she loads `image-generation` before a call; the reply is a JPEG whatever the file name says and has no `metadata.provider`.
  - Still open for the maintainer: **(a)** the `PreToolUse` hook above, the only enforcement; **(b)** the bullet itself: it is not in the floor, by decision; if a live run shows that the skill is not loaded or not followed, the case for moving it into the floor (ADR 0021) is made by that run (H10d3 showed it loaded and followed, to the letter of a loose text: a case for correcting the text, which was done, not for the floor); **(c)** whether a client that restricts where its material goes needs a per-project list of allowed providers (today the rule is "ask before the first call" and the card names the provider); **(d)** whether the pin refresh joins the host-update routine, since a new release of `mcp-image` appeared on 5, 7 and 8 October 2026 alone.
