# ADR 0049: The creative designer may generate photographs through an optional Gemini server

- **Status**: Accepted, 2026-10-08 (Plan 036 Q2 and Q9). The maintainer's words: "For the Photographic image creation needs you can use the MCP. You can give the option to install the MCP and wire an MCP usage skill for image creation ... it will need to wire those new image generation MCPs for Claude agent", and, asked which provider: "Gemini with my AI Studio key." **Built in two slices**, in the order of ADR 0047: the skill `image-creation` and the install route in `mcp-setup` (S18), then the grant and the lead's offer (S19, this record). **Not run live**: the server needs the maintainer's own key, so the live test H10d in `docs/live-test-protocol.md` is gated and waits for a sitting.
- **Context**: Claude cannot make an image (Anthropic's vision documentation), Claude Code has no image tool (`registry/hosts/claude/tool-policy.json`; the Translation Ledger records `generate_image` as unsupported on this host), and the creative designer holds no shell (ADR 0039), so her only route to a raster picture was one that someone supplied, or a placeholder. Plan 036 had decided (Q2) that a generated-image route would be an optional extra, offered when a brief needs photography and none is supplied, never required; it had proposed probe P2 (a Hugging Face server) to choose the provider. The baseline did not show the failure (F2 not seen in H10c: she followed an honest path), so the route repairs no seen defect: it adds a capability the maintainer asked for. Prior art read first: `docs/skill-quality/creative-designer-evaluation.md` ("Image creation: what holds for Claude"), ADR 0041 (routes and optional extras), ADR 0047 (a grant taught by a skill first), Plan 035 D44 to D57 (the lead's provisioning path), `src/core/claude-mcp-routes.ts`, the Gemini API documentation for image generation and its pricing page, and the source of `mcp-image` (below). The facts that shaped the decision: a server's image result reaches Claude as a path, and a shell-less role cannot move a file, so the server must write inside the project; the Gemini image models have no free tier; every prompt, and every input photo, goes to Google; the generated images carry an invisible SynthID mark.
- **Decision**: (1) **One optional server, named `image-gen`**: the `mcp-image` package pinned to **0.14.0** (MIT, one maintainer, published 2026-09-08). The pin rule is "the newest release older than two weeks on the day it is read", so that others have seen it first (0.15.0 to 0.18.0 were published between 2026-10-05 and 2026-10-08). Its source was read for the pin (entry points, configuration, the Gemini client, the file manager, the security manager, the input validator, the tool handler, the response builder, and a search of every `.js` file for subprocess, `eval`, network, environment and file use); the findings are in `mcp-setup`'s Claude reference. It was not run, because it needs the user's key. A newer release is adopted by reading what changed and changing the reference and its test together. (2) **The user runs the install.** The lead prints one command with placeholders and the user runs it in their own terminal, in the `local` scope, with their own AI Studio key: the lead never runs it, never asks for the key in the chat and never writes it anywhere. The command sets `SKIP_PROMPT_ENHANCEMENT=true`, so the prompt she writes is the prompt that is sent and recorded and an image costs one call, and `IMAGE_OUTPUT_DIR` inside the project. (3) **One tool, one role.** `agency-creative-designer` gets `mcp__image-gen__generate_image` and nothing else of that server; no other role gets it. (4) **Not required.** The server is not in any bundle's `requiredMcps` and not in any canonical agent's `mcpServers`, so the doctor, the install gate, the lead's mode counts and the Antigravity MCP sync do not move, and Antigravity keeps its own `generate_image`. (5) **The how lives in a skill.** `image-creation` carries the sourcing ladder (supplied, licensed, generated, placeholder), the go-ahead that a paid call needs (the number of images, the size, the model, the estimate, where the words go), the prompt, the cap of two regenerations per asset, the look at the saved file, the provenance file beside each image, the never-generate list and the label question; its script `image-check.mjs` is for the roles with a shell. (6) **The lead offers it as a choice with its explanation.** When a plan holds a photograph-like asset that nobody supplied, the lead offers **Generate images** beside **Placeholders and image briefs** with `AskUserQuestion`, and the option's description says who pays, what leaves the project, what the user does themselves and that the team restarts. The go-ahead names how many images and at which size. (7) **The floor does not change.** The rules sit in the skill, her body and the lead's sentence; a floor bullet on generated imagery (finding F8) is proposed below and needs the maintainer's yes (ADR 0021).
- **Consequences**:
  - Positive: she can fill a brief that needs a photograph, within a stated cost and with a record of what was asked, by whom and at what price; a placeholder with an image brief stays a complete deliverable, so nothing is blocked while the server is not connected.
  - Limits: the prompts, and any photo named for editing, go to Google under the user's key; the user's Google project is billed per image (about $0.07 to $0.15 on the default model, twice that on the Pro model, with no free tier); a third-party package with one maintainer and no npm provenance runs with the user's key, so the pin, the read and the refresh rule are the control, and its dependencies are version ranges that `npx` resolves on the day; the server overwrites a file of the same name and creates the folder, so the skill never reuses a name; a running session does not load a server added after it started, so the team restarts; the pinned version calls two Gemini models by name, and Google retires models (the pricing page announced the shutdown of Gemini 2.5 Flash Image for 2026-10-02), so the pin is refreshed when a notice appears.
  - Not established: any live call (H10d is gated); that the server's reply looks as its source says; how her prompts compare with the provider's guidance; whether the label rule needs a stricter statement; the behaviour of `claude mcp add` with several `--env` values on this build for this server (the form is the vendor's own README form and the one used for Firecrawl; `claude mcp add --help` on 2.1.294 lists the option as `-e, --env <env...>` and gives `-e API_KEY=xxx -- npx my-mcp-server` as its own example, so the name before the options and the `--` before the command are right, but the command itself was not run).
  - Open for the maintainer: **(a)** a floor bullet, proposed text: "**Generated imagery**: never present a generated image as a photograph of the client's real product, of a real person, or of a customer, reviewer or endorser; record how each generated image was made and keep the label its placement requires." **(b)** A guard for the one tool: the server reads any image path the call names (`inputImagePath`), so an injected instruction could send a local picture to Google; today the skill's rule and the go-ahead are the only barrier. A `PreToolUse` check that the path is inside the project would close it; it changes the shared guard scripts, so it is a slice of its own if wanted. **(c)** Whether the OpenAI and Seedream providers that the same server offers should ever be wired (they need other keys and the same review).
