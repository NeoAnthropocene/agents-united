# ADR 0069: A Skill is written once and shared; a Host layer only where a Host feature needs it

- **Status:** Accepted by the maintainer, 2026-11-18 ("Yes, shared"), on the findings and recommendation of the lead of that day's session (an AI session). It makes precise decision 6 of [ADR 0025](0025-native-host-packages-and-host-docs-library.md) ("Skills are native per host, upstream first"); it does not change the rest of that ADR.
- **Context:** The method of this project is a shared, host-neutral definition in `registry/core/` and native artifacts for each Host under `registry/hosts/<host>/`. Before the Claude lane of the remaining Bundles is started, the maintainer asked whether a Skill, too, should be written once per Host. [The findings of 2026-11-18](../plan-033-skills-per-host-findings-2026-11-18.md) show: the repository holds 216 shared Skills and a Host `SKILL.md` for seven of them on Claude and one on Cline; each of those is a single entry file, while the Skill's scripts, references and assets stay shared; and the docs libraries of Claude Code, Cline and Antigravity, and the Codex snapshot fetched that day, describe the same format: a folder with a `SKILL.md` whose YAML frontmatter has `name` and `description`. The Hosts differ in the folder they read, in frontmatter beyond those two fields, and in body text that names a Host's own tool.
- **Decision:**
  1. **Shared is the default.** A Skill lives in `registry/skills/<name>/` and is installed unchanged into each Host's Skill folder. Its `SKILL.md` carries `name`, equal to the folder name, and `description`; its body names no Host tool or command.
  2. **A Host `SKILL.md` is the exception.** `registry/hosts/<host>/skills/<name>/SKILL.md` replaces the entry file for that Host, and nothing else of the Skill, only for one of two reasons: the Skill needs frontmatter that only that Host has (for example running as a fork, or limiting tools), or its body must name that Host's tool or command and cannot be worded neutrally. The reason is written where the layer is recorded (the Bundle's binding or its review record).
  3. **A Host-only Skill** exists only for a feature the other Hosts lack.
  4. **Everything else stays native per Host:** agents, hooks, rules, workflows, tool grants and MCP wiring, as ADR 0025 says.
- **Consequences:**
  - Finishing a Bundle's Claude lane means native agents, hooks, rules and workflows; its Skills stay shared, with a Claude `SKILL.md` only under decision 2.
  - One text is kept in step instead of four. The price: a shared body is written for the least capable Host, and a Skill with a Host layer has two entry files that can drift. No test ties a Host `SKILL.md` to its shared one today; one is wanted before the layers multiply.
  - Not verified, and able to change decision 2: whether each Host ignores frontmatter fields it does not know. If all four do, one `SKILL.md` carrying a Host's extra fields could serve every Host and most layers would be unnecessary; if one refuses or mis-reads an unknown field, the layer stays necessary. The libraries read for the findings do not say.
  - Not counted: how many of the 216 shared Skills name a Host's tool in their body today. Those need neutral wording or a layer when their Bundle's lane is built.
  - Nothing behind this decision was observed in a Host session; it rests on the repository and the docs libraries.
