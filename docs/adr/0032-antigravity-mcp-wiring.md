# ADR 0032: MCP Wiring in the Antigravity Native Lane

- **Status**: Accepted — 2026-10-03 (product owner: slice 3 of the Antigravity order, "MCP wiring: merge our server entries into `.agents/mcp_config.json`, same rules as the hooks merge, never write a secret"). Builds on ADR 0030 and ADR 0031 (and its addendum, whose merge pattern it follows).
- **Context**: Prior art searched: `host-library/antigravity/guide/mcp.md` and its snapshot, `src/core/mcp-locations.ts` (discovery only; it listed a wrong workspace path and not the documented one), `src/core/prerequisites.ts` (`getMcpDefinition`, `autoConfigureConfigFile`: the existing server definitions, and a writer that embeds secrets and rewrites the file with `fs.writeJson`, used by tests only), `src/core/antigravity-hooks.ts` and the guard install (the merge pattern), `src/core/doctor.ts` (the Plan 029 A3 audit, which reads names from the installed agents), the registry agents' `mcpServers:` lists (eight names across the registry, names only), plan 031, and the real-session observations. What the evidence says: the docs name one workspace file (`.agents/mcp_config.json`, an `mcpServers` object, `command` or `serverUrl` per server); the registry declares servers by name and the definitions live in code; under the lane the native agents carry no `mcpServers:` frontmatter, so the Plan 029 audit sees no declared server for them; a global MCP server that could not start made every headless session hang (observations, Linux); `agy mcp list` showed only the global servers and prints header values in plain text.
- **Decision**:
  1. **A reviewed catalog, one entry per declared name.** `registry/hosts/antigravity/mcp/servers.json` holds, for each server name any registry agent declares, the entry to write (`command` and `args`, or `serverUrl`; never the legacy `url` or `httpUrl`), the variables it needs and the variables it may use. A test pins that the catalog covers exactly the declared names, that the launch command equals the existing definitions (so the two cannot drift) and that no entry has an `env`, `headers` or `oauth` block.
  2. **No secret, ever; a server that needs a credential ships switched off.** A server with `requiresEnv` is written with `disabled: true`; the install names the variable and the command (`agy mcp enable <name>`), and the doctor treats a server of ours that ships off as healthy. No placeholder is written, because whether the host expands `${VAR}` or passes its environment on to a server is unverified. It also avoids putting a server that cannot authenticate into every session's start-up, given the hang observed with servers that could not start.
  3. **The file is the user's; only named keys are merged.** `src/core/antigravity-mcp.ts` parses strict JSON (a file with comments, a trailing comma, a root or an `mcpServers` that is not an object is never rewritten, and the entries are printed for a hand edit), keeps every other key, the order, the indent, the line endings and the final newline, and removes an `mcpServers` object or a file it created only when nothing else is left.
  4. **A key is ours only while the lockfile records it.** `antigravityMcp` holds, per server, the canonical hash of the entry written (ignoring `disabled`) and the bundles that declare it. A name the user already has is theirs: left alone, never recorded, never removed, and the install says so. An entry of ours that was edited is left (reported, and not removed on uninstall, since it may now hold the user's own values); an older shipped entry is recognised by the recorded hash and replaced, keeping the user's switch.
  5. **`disabled` is the user's switch.** The ownership hash ignores it, so `agy mcp enable|disable` is not drift and a re-install does not undo it. The doctor warns about a disabled server only when this release ships it enabled.
  6. **The lane owns it, refcounted by bundle.** The servers come from the bundle's declared agents (its own roster, not the inherited superset). A server stays while any installed bundle declares it; `agents update` drops a server a bundle stopped declaring; `--no-native` removes every server of ours; uninstall releases the bundle's ownership. No separate flag: it is sticky with the lane, per host.
  7. **The doctor judges only our recorded keys.** It warns when the file is missing or invalid, or a server of ours is missing, switched off (when shipped on), edited, or an older version than the release ships, with the repair command; the user's own servers are never read as drift. `.agents/mcp_config.json` is added to the MCP location registry, so the existing audit and the prerequisite check see what the lane wrote.
- **Consequences**:
  - Positive: the servers the bundles declare reach a workspace without a manual `agy mcp add`, with no credential on disk and a clean removal.
  - Negative: the servers that need a credential are inert until the user enables them; the workspace file lists servers that every contributor's agy will try to start; the lane writes only the workspace file, never `~/.gemini/config/mcp_config.json`.
  - Open (a real session is needed, see the observations): that agy reads the workspace file, that a stdio server receives agy's environment, whether `${VAR}` is expanded, what a failing server does to a headless run, and whether an agent's `mcpServers:` frontmatter resolves.

## Addendum (2026-10-03, one real session on agy 1.2.16; amends decisions 2 and 5, does not change the code)

A headless session in a scratch workspace with a hand-written `.agents/mcp_config.json` (a local stdio probe server that records its environment, a copy of it marked `disabled: true`, and a server whose command is not installed) answered the open items (observations: `host-library/antigravity/observations/2026-10-03-agy-1.2.16-probes.md`). **Confirmed:** agy reads the workspace file in a session, and a stdio server receives agy's own environment, so "set the variable in the environment agy starts from" is right. **Decision 2's choice not to write a placeholder is confirmed:** a `${VAR}` in `env` was not expanded, the server received the literal text and would have broken. **A missing command is harmless:** the run took 10 s and answered normally, so the Linux hang does not follow from a server that cannot start. **Decision 2's mechanism is contradicted once:** the server marked `disabled: true` still started. agy stores the field the same way in its own global file and `agy mcp list` honours it there, so the cause (the workspace loader, or headless mode) is not established. Until it is, a credentialed server shipped switched off (`github`, `firecrawl`, `stitch`, `figma`) may be launched with no credential in every session; it will fail to authenticate, which one observation says costs nothing visible, but it does spawn `npx` on each start. The code is unchanged: the entries still carry no secret and the install still names the variable. **Decision for the maintainer, not taken here:** keep shipping them switched off (inert if the field is honoured elsewhere, a wasted launch otherwise), or stop wiring credentialed servers and print the entry for the user to add once they hold the credential.
