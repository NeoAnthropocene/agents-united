## Proposed decision

Use an **explicit factory-owned native binding** for the new Claude-only worker rather than adding an Antigravity-shaped legacy carrier solely to reach the native planner. Validate its shared pair and required native role, runbook, support/rule references and existing guard file/registration against the complete planned installed set before mutations. Track native-only outputs with bundle-only ownership, normal source hashes, update/remove and doctor behavior. Preserve the existing author-skill binding unchanged in meaning; opt-in absence leaves older bundles alone.

Review/implement the delivery prerequisite (P1) independently, using registry fixtures and full lifecycle proof, then the bounded worker (P2). The worker uses an unchanged four-field contract, a target-host job read by path+hash or supplied in full, a foreground ordinary subagent and a checked hand-back. Root and intent constraints are prose plus deterministic checks, not a new sandbox or first-action hook guarantee. Existing destructive guards keep their real failure limits.

Keep evaluator, main-thread factory orchestration, contract helper, Domain/Organization templates, reader distribution, sync and managed Option A installation as separately reviewed deliveries. The P2 worker may return a checked draft with quality review pending, but **slice 4a is incomplete** until the orchestrator checks its evaluator and the Claude stage has the required authorized evidence. Do not relabel intermediate delivery as a complete factory.

## Alternatives and consequences

A legacy carrier would reuse today's resolver but add a second source and fallback obligations for an unavailable host. Reusing engineering/code-review roles would mismatch their missions. Extending the built-in author-skill fork would conflate a one-skill authoring job with the planned host-parametric role and would not deliver the shared pair. A complete orchestrator/evaluator/helper/template change in one PR would prevent independent review of accepted requirements.

Native-only registration adds a real installer/ownership prerequisite, so it requires missing-edge, collision, package, direct-item, update/remove/doctor and full addon lifecycle evidence. It must not silently expand plugin/global/other-host support. Exact paths, public seams, red cases, fixed inputs, returned-result checks and unavailable prerequisites are in the linked design. No new hook, transport boundary, model run, host baseline change or legacy retirement is selected.

The new decisions for the maintainer are this registration strategy and the P1 → P2 worker-first boundary. Author-skill selection/loading, Option A and Claude → Codex → Antigravity → Cline remain accepted. Approval of this proposal would not authorize publication, merge or paid proof by itself.

Enforcement kind, stated honestly: `check-sync.mjs` is a deterministic script over records, on-disk files and one read-only subprocess (`git -C <checkout> rev-parse --verify HEAD`).
