# ADR 0048: Agent-factory quality review and contributor tooling

- **Status**: Accepted requirements, 2026-10-08; implementation awaits separately authorized Plan 033 slices.
- **Context**: The maintainer supplied answers to the carried Plan 035 questions and requested a recommendation for question 6 during Plan 033's pre-implementation review. The merged foundation remains complete. ADR 0045's four-field Subagent Contract and ADR 0046's accepted workspace source registry remain binding.

Numbering was checked against `dev` and open PRs: ADR 0047 was already reserved by [PR #185](https://github.com/NeoAnthropocene/agents-united/pull/185), so this decision uses 0048. **Publication amendment, 2026-10-08:** #185 is now merged and 0047 exists on current `dev`; 0048 remains the next available decision number.

## Decisions

1. **The factory orchestrator spawns an evaluator subagent to review quality.** Contributor-facing review therefore belongs in the factory, alongside the existing deterministic checks; repository CI remains authoritative for upstream contributions. Evaluation must distinguish artifact quality, completed offline checks and actual host evidence. An evaluator's judgment cannot establish an unobserved runtime guarantee or authorize publication, installation or a paid host run. The evaluator's rubric, native restrictions and result format need their realization review.
2. **Ship the session-report helper.** Package the existing Claude helper and its sanitization support for contributor use, rather than leaving it solely in the maintainer checkout. Its current source is `scripts/hostlib/session-report.ts`, exposed in the checkout through `hostlib:session`. A distributable entry point, runtime dependencies, documentation and installed-package checks remain to be designed and implemented. New Cline, Antigravity or Codex readers require their own reviewed formats and evidence; an unsupported format is explicitly unavailable. Distribution does not include private transcripts or account data.
3. **A contributed subagent includes its basic shared contract as well as its host realization.** Include or reuse `registry/core/<role>.core.md` and its companion `<role>.contract.json`; add the pair when absent. The contract keeps exactly `definition`, `workflows`, `skills`, `hooks`. Host frontmatter, tool grants, guard kind/registration and invocation remain in the host realization. This preserves a common definition for later host ports without making native artifacts translations of a canonical bundle. Compatible existing cores are reused; a host-specific need does not justify silently changing their shared floor. For private Option A drafts, these files belong under the selected source registry's `core/` directory. Artifact-only contributions that add no subagent identify this requirement as inapplicable.
4. **Provide a contributor skill for authoring that basic definition/contract pair.** It guides reuse, authoring and validation against the existing core/contract validators, and identifies the separate host bindings still needed. Creating the pair alone does not make a bundle installable or prove a host realization.
5. **Every Tier-2 Organization Bundle leader has provisioning guidance.** Create separate Domain Bundle and Organization Bundle authoring templates. The Organization template always includes the lead's prerequisite/provisioning responsibility; the Domain template declares its applicable prerequisites. Reuse the existing procedure: check tools in the lead's actual session, distinguish required from optional integrations, obtain authorization before changes, verify the result, and follow that host's observed reload/restart/sign-in route. Existing authorization persists; do not ask for the same approval again. An unavailable optional integration may permit a declared degraded task, while an unavailable required integration blocks its dependent action.

## Consequences

The later slice design must account for evaluator delegation and checked results, the contract helper, both bundle templates and a usable packaged session-report entry point. Keep each implementation PR scoped and reviewed. Authoring templates express shared responsibilities; each host realization supplies its own mechanics, enforcement limits and evidence.

## Sequential host delivery amendment — 2026-10-08

The maintainer chose to author `agent-factory` **one host at a time: Claude → Codex → Antigravity → Cline**. This supersedes the earlier requirement to prove the factory on Claude, Cline and Antigravity together before completing its realization slice. Complete and review the selected host's stage before moving to the next; shared definitions/contracts remain host-neutral, while native artifacts are authored from that host's reviewed inputs. The earlier migration context above records the prior decision round; this explicit factory sequence is the current delivery decision.

Quality evaluation accompanies **each bundle's realization on each host**. The maintainer directs those reviews, an evaluator supplies quality findings, and combining/removing existing skills remains a maintainer approval under ADR 0040. Review the historical 39-skill quality findings when their bundles reach the relevant host stage; do not turn that historical count into a missing-port inventory or a separate blanket rewrite prerequisite. Factory delivery and migration of other bundles have separate scoped PRs.

Each host stage records its bundle/artifact scope, shared floor and declared deltas, native loading/delegation/provisioning, deterministic checks with actual exits, evaluator findings and actual host evidence or `unverified`. Evidence on one host does not complete another host's review. A Claude stage does not wait for unfinished Codex/Antigravity/Cline work, and a later stage does not waive the relevant checks. Codex requires its own reviewed host library/profile/tool policy and native/conformance work before claims of support; choosing its position does not create those inputs or authorize their implementation now. Per-bundle availability still needs its separate catalog/installer contract.

Question 6's lead-intake recommendation remains proposed. This amendment records the sequence and evaluation ownership; it does not start a later slice, host run or skill removal, or alter the reviewed foundation, `AGENTS.md`, Plan 034's hold/baseline, deferred Plan 035 work or Plan 036.
