# ADR 0031: The Antigravity Native Install Lane

- **Status**: Accepted — 2026-10-02 (product owner: "go in order", after the guard hook; the order of ADR 0026). Implements ADR 0026 decision 6 for Antigravity and builds on ADR 0029 (the Cline lane) and ADR 0030 (the package shape).
- **Context**: Prior art searched: `src/core/installer.ts` (the base store copy loops, the compound lane, the sticky per-host record), `src/core/cline-projector.ts` and `claude-projector.ts` (the other lanes), `src/core/hosts.ts` (the `agents` host is "Google Antigravity & Master Library" and is not projection-capable because it is the canonical store), `src/core/doctor.ts`, `tests/native-install-lane.test.ts`, ADR 0029 and 0030, and the real-session observations. What the evidence says: Antigravity's layout (`.agents/agents`, `.agents/rules`) is the canonical store the base install already writes and tracks by hash, so a native file can land on a path the store owns (`orchestrator-engineering.md`, `git-guardrails.md`); the store's rule copies carry no frontmatter and are silently dropped by the host (observed); the store's prefixed agent copies carry a frontmatter `hooks:` key that hides them from discovery (plan 031).
- **Decision**:
  1. **One flag, a third record.** `--native` and `--no-native` now also cover the canonical store: `nativeLanes.antigravity`, beside `nativeLane` (Claude) and `nativeLanes.cline`. It applies when the main library is installed (the default target); a store-less Claude-only install never records it. Sticky across `agents update`, reflected by a dry run.
  2. **The store skips what a native file replaces.** With the lane on, the five native agents and the six native rules are installed as tracked projections (`host: antigravity`, kinds `role` and `rule`, owned by the installing bundle) **instead of** the store copies they replace: the prefixed specialist copies and the coordinator file, and the six frontmatter-less rules. Everything else in the store (the host entrypoint rule, the skills, assets with no native file) is untouched.
  3. **Switching is clean and refuses to lose work.** Turning the lane on clears each replaced store copy first, but refuses (unless `--force`) when the user edited one, and an unmanaged file at a native path is refused like any projection target. Turning it off prunes the projections before the store loops run, so the legacy copies are written back. A store copy's owners are inherited by its native projection, so a bundle installed earlier does not lose its ownership.
  4. **The native projections carry no canonical asset.** A canonical pointer would make the shared lockfile logic create an empty store record for a skipped asset on every install, so the native files are owned by the bundle (`ownedByBundle`) and found by path, like Cline's native-only files.
  5. **The doctor knows the lane.** Native Antigravity files take part in the presence, drift and stale-render checks, with `agents update <bundle> --native` as the repair command, and the legacy frontmatter check no longer asks a native agent for a `model:` key (it leaves the model to the host default, ADR 0030 decision 8).
  6. **Not in this slice: the hooks file.** `hooks.json` is shared with the user's own hooks and needs a merge, not an overwrite, so the guard (`registry/hosts/antigravity/hooks/`) is installed by a following slice.
- **Consequences**:
  - Positive: the standing rules reach Antigravity at last (the legacy copies are dropped by the host), and the native agents are the ones discovered; the lane is opt-in, sticky, drift-checked and removable like the other two.
  - Negative: while the lane is on, the library no longer holds the legacy copies of those eleven assets, so the doctor's agent count and `agents start` rely on the native files (the coordinator keeps the path `agents start` expects); a bundle installed before the flip and not re-installed keeps its legacy copies until its next install.
  - Open: the hooks merge; `GEMINI.md` inside `.agents/rules/`, which the docs would also expect to start with frontmatter and which has no native file yet; macOS, Linux and the 2.0 and IDE surfaces.
