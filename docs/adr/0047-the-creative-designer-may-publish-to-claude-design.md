# ADR 0047: The creative designer may publish to Claude Design

- **Status**: Accepted, 2026-10-08 (Plan 036, after probe P3). The maintainer's words, after reading the probe: "I want to keep the Artifact for agency-creative-designer. This agent is the key subagent that creates the brand or brief aligned key elements. Artifact will help her, but we should give her more tools to produce the creatives." He also asked for another test after skills that teach how to use the Design artifact are added. **Nothing is built yet**: the skill that teaches it is slice S11 of Plan 036 and the grant is S12. The floor line and the lead's sentence below are drafts that the maintainer approves in S12's pull request, because the floor is locked by ADR 0021.
- **Context**: prior art searched first: `docs/skill-quality/claude-design-exploration.md` (option O3 and its cautions, PR 179), Plan 036 Q7 ("the rest only after probes and my yes"), the P3 observation (`host-library/claude/observations/2026-10-08-claude-2.1.294-designer-p3-artifact-probe.md`, PR 182), the Claude tool policy (`registry/hosts/claude/tool-policy.json`: `Artifact` is class `artifacts`, available to subagents, mutating), ADR 0021 (the Contract Floor is locked), ADR 0039 (the native roster), ADR 0041 (optional extras). The facts: Claude Code has no Claude Design API or MCP server; its way in is the `Artifact` tool, whose types Design (a canvas of artboards) and Design System (tokens in list form, a README brand book, a cover) the session's own model fills. With the tool added to a scratch copy of her role, she published a private canvas and a private design system in 2 of 2 headless runs, 0.42 to 0.49 USD each, no permission denial. What she skipped: the skill that holds the placement rule (the feed ad's label sat in the caption zone), reading back or rendering what she published, and her reports carried small slips (a count off by one, README inferences under a sentence that denied them). The tool needs a Pro or higher plan, a signed-in CLI and the Anthropic API, and is documented off by default in the Agent SDK and GitHub Action contexts.
- **Decision**: (1) **One role holds the tool.** `agency-creative-designer` gets `Artifact` (capability class `artifacts`); no other role does. A reader for the front-end role (option O4) stays undecided until probe P4 and a yes. (2) **Publishing is opt-in.** She publishes only when the user asks for a Claude Design canvas or brand book, directly or through the lead. The lead treats it as an optional extra, offers it only when the brief calls for it, and gets the user's go-ahead for each publish. Nothing is published as a side effect of a design task. (3) **Private and reported.** Every artifact is private; she never changes sharing; her hand-back gives the link, the type, what she published and what she did not check (not rendered, not read back, platform specs unverified). (4) **The how lives in a skill.** `claude-design-artifacts` (S11) carries the rules P3 showed she skips (skill first, the type's own instructions, copy verbatim, only token colours, claims to the reviewer, inferences marked, read back and count, say what was not checked); her role body gets a table row and nothing more, so the role stays short. (5) **The floor says what leaves the project.** S12 adds one safety line to the core: client material leaves the project for Anthropic-hosted pages, so she publishes only on an ask and every artifact stays private. (6) **No guard script yet.** `Artifact` is not wrapped in a PreToolUse guard in S12; the re-test (S13) shows whether an unrequested publish ever happens, and a guard follows if it does. (7) **Availability is stated.** Without the tool she says so and writes the files instead.
- **Consequences**:
  - Positive: the maintainer can review and edit her canvases and brand books in the browser, which the SVG files she hands back today do not allow; a design system she publishes is built from the tokens file in the form Claude Design reads (in P3 it equalled the tested converter's output for all 18 tokens), so the maintainer browses what the tokens say; the evidence is already in the repo, not predicted.
  - Limits: client material leaves the project for Anthropic-hosted pages (private by default; sharing stays the user's act); the tool is mutating and outward-facing, so the safety rests on the floor line, the lead's go-ahead, the skill and the re-test, not on a hook; two test artifacts (titles "PetPal Paid Social Set" and "PetPal") exist on the maintainer's account and stay for the comparison; a subscription or API plan without the tool, or the Agent SDK, gets the file fallback.
  - Not established (P3 did not test): an unrequested publish by her; the tool's absence; the maintainer's default design system; how the boards look in the Design editor itself (only the files were measured); a large token set; run-to-run variation (one run each).
  - Open: the exact floor wording and the lead's sentence (S12); whether a guard is needed (S13); the front-end role's reader (O4, P4); whether Cline or Antigravity ever get an equivalent (they have no such tool); whether a Claude-only skill needs a native skill lane instead of a canonical skill whose description says "Claude Code only" (Plan 036 Q9).
