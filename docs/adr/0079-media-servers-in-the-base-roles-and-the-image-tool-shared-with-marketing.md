# ADR 0079: The media servers are declared in the base roles, and the image tool is shared with marketing

- **Status**: Accepted, 2026-11-24, on two choices of the maintainer made that day: the servers go in the base roles, and the image tool is shared with marketing. Supersedes decisions 4 and 5 of ADR 0049; every other decision of ADR 0049 stands.
- **Date**: 2026-11-24
- **Context**: The grants of three agency media roles were written by hand into the Claude native files in commit `d5ff465a` (2026-10-27): the motion designer holds `mcp__higgsfield` and `mcp__klingai`, the sound designer `mcp__elevenlabs` and `mcp__fish-audio`, and ADR 0049 (2026-10-08, amended after Sitting T) gave the agency creative designer, and the digital-agency lead for her pool, the one tool `mcp__image-gen__generate_image`. The canonical agents under `registry/agents/` declared none of these servers, and ADR 0049 decision 5 required that none ever did: the image server was to stay out of every canonical agent's `mcpServers` and out of every bundle's `requiredMcps`, so that the doctor, the install gate and the Antigravity sync would not move. The agent factory's check (`factory-check --artifact`, ADR 0072) compares a native role's server entries with the servers its canonical agent declares, and so it refused `agency-creative-designer`, `agency-motion-designer` and `agency-sound-designer` ("held beyond the canonical servers of the role"). The Tier 1 `marketing-creative-designer` stands on the same canonical agent as the agency creative designer, but it held no image tool: its text said "no image-generation tool is bound in this lane", a decision of the roll-out (2026-11-20), and `orchestrator-marketing` said the same.
- **Decision**:
  1. **The servers go in the base roles.** `subagent-marketing-creative-designer` declares `image-gen` after `stitch` and `figma`; `subagent-motion-designer` declares `higgsfield` and `klingai`; `subagent-sound-designer` declares `elevenlabs` and `fish-audio`; the canonical lead `orchestrator-digital-agency` declares the five after its eight, and the canonical lead `orchestrator-marketing` declares the four hosted servers after its four (decision 10). Every entry stays a name only (`- name: <server>`): a server is referenced by name and never defined inline. This supersedes ADR 0049 decision 5 as far as the canonical agents are concerned.
  2. **The image tool is shared with marketing.** The Tier 1 `marketing-creative-designer` holds `mcp__image-gen__generate_image`, and `orchestrator-marketing` holds it too, so that the designer's tool pool has it (a subagent gets the MCP tools of the main conversation, ADR 0049 decision 4). This supersedes ADR 0049 decision 4, which gave the tool to one role and one lead. The designer's text for the tool is the agency creative designer's, word for word: the sentence about the tool, the paragraph "Generated pictures." with its hard rules, and the rows of the two image skills. The lead says it never calls the tool, passes on only the user's go and does not install the server. The two skills `image-creation` and `image-generation` are added to the skill lists of the `growth-marketing` and `performance-paid-acquisition` bundles, because a teammate loads them on demand and the designer's text names them.
  3. **One tool, not the server.** A writable role receives, for a server in a small table next to the read-only pins in `src/core/claude-projector.ts`, the pinned tool and not the whole server: `image-gen` is granted as `mcp__image-gen__generate_image` and never as `mcp__image-gen`. A server that is not in the table is granted whole, as before. The canonical entry stays name-only, so the table is the one place that says "one tool". The check of the factory accepts the pinned entry as the canonical form because it asks the same function.
  4. **The five are optional extras of the bundles that hold the roles.** `digital-agency`, `full`, `growth-marketing` and `performance-paid-acquisition` list all five (the last two ship the marketing lead and its creative designer), each as `{ name, purpose, optionalForBrainstorming: true, optional: true }` with the purpose taken from the `mcp-setup` references. The doctor's missing-server audit and the install gate leave out a server that an installed bundle lists as an optional extra and none requires, so no missing-server warning and no "not fully satisfied" follow; the doctor's separate check of the entries the Antigravity lane wrote (ADR 0032) still applies. The lead's operating mode still counts six required integrations. The description of `digital-agency` now says "6 required MCP servers and 7 optional extras". The install panel prints the entry of an unmet extra, with its add command when the server is missing on Claude and Claude is a target of the install.
  5. **Antigravity: the four hosted servers are wired; `image-gen` is not.** `registry/hosts/antigravity/mcp/servers.json` has an entry for `higgsfield`, `klingai`, `elevenlabs` and `fish-audio`, each only `{ "serverUrl": <url> }` with no key, header or OAuth block (the sign-in is the host's, through `/mcp`), and the URLs come from the one table in `src/core/mcp-add-commands.ts`, which a test compares with the references. An Antigravity install of a bundle whose roles declare them writes them to `.agents/mcp_config.json`, only while the Antigravity native lane is on (`agents add --native`; with the lane off every server of ours is removed), under the usual rules (merge by name, the user's keys untouched, removed with the last owner). Higgsfield's address is `https://mcp.higgsfield.ai/mcp`: the bare host answers 404. The doctor, for a declared and unconfigured hosted server on Antigravity, prints the `serverUrl` entry and the sign-in through `/mcp`, unless an installed bundle lists the server as an optional extra (decision 4) and no installed bundle requires it; every bundle that holds these roles lists the four as optional extras and none requires them. The test that says "the catalog has an entry for every server the registry agents declare" names one exclusion, `image-gen`: Antigravity generates images itself, through its built-in `image-generator` subagent, and `image-gen` is a stdio server that needs the user's own provider key, which agents-united never writes.
  6. **No stdio fallback for the five, and an add command of the right shape.** `PrerequisiteChecker.getMcpDefinition` returns no definition for the five instead of the fallback `npx -y <name>`, and the code that writes a client configuration skips them. The add command that the doctor and the install panel print comes from one table in `src/core/mcp-add-commands.ts`: for the four hosted servers `claude mcp add --scope project --transport http <name> <url>` with each URL taken from `registry/skills/mcp-setup/references/media-setup.md`, followed by the human sign-in through `/mcp`; for `image-gen` the reviewed command of `registry/skills/mcp-setup/references/claude-code.md`, run by the user from the project folder with their own key. For the image server, on Antigravity the doctor says that no add command is verified; for a hosted server it prints the `serverUrl` entry and the sign-in (decision 5); both apply when its missing-server audit reports the server. A test compares the table with both references. The install panel looks at every host the install targets, the fan-out included (`installTargetHostKeys`), in `agents add` and in the guided install; Claude is a fan-out host, and a panel that looked at the hosts alone never printed its command.
  7. **The two image skills join two bundles.** `image-creation` and `image-generation` are added to the skill lists of `growth-marketing` and `performance-paid-acquisition`, the two bundles that hold the marketing creative designer. This follows from the shared tool: the designer's text names both skills and says that she loads `image-generation` before any call (a teammate applies no `skills` of its own, so a skill that its bundle does not install is a gap), and the skills carry the rules (the go-ahead, the input paths, the provenance record) that decision 2 copies into her text. The skills were already in `digital-agency` and `full`. `mcp-setup` is added to the same two bundles, `growth-marketing` and `performance-paid-acquisition`: the designer's rule for a missing key tells her to stop and tell the lead that `mcp-setup` prints the command, and a bundle that does not install the skill leaves that sentence false. Of the four bundles that extend `growth-marketing`, `performance-paid-acquisition` declares the designer itself and lists `image-gen` itself; the other three (`seo-content-marketing`, `product-led-growth` and `lifecycle-email-marketing`) hold it through their parent, and decision 9 is what they read.
  8. **The tests follow the rule.** `tests/native-claude-image-route.test.ts` pins the new rule (the server declared by name in two canonical agents, listed as an optional extra and never required, held as one tool by four native roles, absent from the Antigravity catalog), and the repository rules test accepts the committed tools line of the three agency media copies and of the two creative designers.
  9. **Optional servers are read through `parentBundle`.** One rule in `RegistryResolver.getBundle`: a bundle's optional MCP entries are its own and those of the bundles it extends, the nearest entry of a name winning; a required entry of a parent is never taken, and nothing is copied into `bundles.json`. The doctor and the install panel read a bundle through that function. The rule moves the optional set of exactly three bundles, `seo-content-marketing`, `product-led-growth` and `lifecycle-email-marketing`, each gaining `image-gen`; a test pins that list, so a change to any other bundle fails it. When this decision was taken, those three installs showed the install panel with one optional line, as `growth-marketing` did; since decision 10 they also inherit the four hosted servers, and the panel of each shows five optional lines, as `growth-marketing`'s does.
  10. **Decisions of 2026-11-24, after the Antigravity check.** What was seen: the maintainer, in an interactive Antigravity CLI `agy` 1.5.16 session, in a trusted throwaway workspace whose `.agents/mcp_config.json` used `serverUrl` entries, through `/mcp`, saw fish-audio and klingai signed in with OAuth and connected (62 and 18 tools), elevenlabs connected after a reload, and Higgsfield answer `Not Found` at `https://mcp.higgsfield.ai` and connect at `https://mcp.higgsfield.ai/mcp`. Separately, the coordinating session probed Higgsfield without authentication: a POST to the bare URL returns 404, a POST to `/mcp` returns 401, and its protected-resource metadata gives `resource = https://mcp.higgsfield.ai/mcp`. Separately, a headless agy session reported no `generate_image` in its main tool list and only an `image-generator` subagent; that is its own report, unverified beyond it, and it agrees with a line of the agy changelog in the host library (images are handed to a built-in `image-generator` subagent). The maintainer's words: "Add catalog entries with the corrected addresses. Also Antigravity orchestrator should have these MCPs. It can natively create the images with image-gen but we an also give the user a chance to select other possibilities. image-gen always will be the first recommended option for the Antigravity Orchestrators when they give the user to select while image creation." Reading, recorded as the coordinating session's and open to his correction: on Antigravity, the host's own image generation, through its `image-generator` subagent, is the first and recommended image option, followed by the `image-gen` MCP server (with the user's key), the hosted media servers that make images, licensed stock, and a placeholder with a brief; "image-gen" is read as the native route and not as the MCP server. Both leads, `orchestrator-digital-agency` and `orchestrator-marketing`, declare the four hosted servers; the marketing bundles that ship the marketing lead list them as optional extras, and the native Claude marketing lead holds them (a lead holds what it declares). The maintainer chose on 2026-11-24 to keep the four hosted servers on the Claude marketing lead too, with one source for every host; none of the Claude marketing roles uses them yet. The Antigravity image-choice paragraph is in the two canonical leads, inside one host section each (decision 11).
  11. **Host sections: a new behaviour in src.** A marked part of a canonical agent body is for one host: a line `<!-- agents-united:host antigravity -->` opens it and a line `<!-- agents-united:host-end -->` closes it (each marker a whole line). One function, `hostSections(body, host)` in `src/core/host-sections.ts`, keeps the inner text and drops the two marker lines for the named host and removes the whole section for every other host. It fails closed: it throws on a host name other than `antigravity`, on a section that is not closed, on a nested section and on an end marker without a start, and every reader of a canonical agent body applies it, so a reader that forgets it fails and does not leak. The readers are the Claude projector (`renderRole`), the Cline projector (`renderConfiguredAgent`), the generic frontmatter projector (`projectAgent`: Cursor, OpenCode, the Codex bridge entry and the Antigravity profile), the store copy of an install (rendered for Antigravity, written as a real file with the hash of the bytes written, never a link into the registry) and the two canonical checks of the factory that read a body (`canonicalGuardrails`, `canonicalDirectives`). A registry test refuses a malformed section in any canonical agent and pins that only the two leads have one. No purity rule applies to the prose of a canonical agent (the core purity rule scans `registry/core` files only and a host section is no exemption there), so none is weakened. The paragraph, in `orchestrator-digital-agency` and `orchestrator-marketing` at the place where each lead plans image work, offers in this order: Antigravity's own image generation through its built-in `image-generator` subagent "when your tools show it" (recommended), the `image-gen` MCP server with the user's own key (not wired by agents-united), the hosted media servers that make images (after the `/mcp` sign-in, on the user's own account), licensed stock, and a placeholder with an image brief. The Claude native lead files are unchanged. The store copy in `.agents/agents/` is the Antigravity copy: `agents` is Antigravity's own layout, and Antigravity has no second path. Other hosts (Codex, through the `AGENTS.md` index, which links the store copy and holds no body) may open it; Codex loads the root `AGENTS.md` and the skills under `.agents/skills`, and reads a file of the store only if the model follows a link, and agents-united writes nothing for Codex but `AGENTS.md` and the store. Cline's launcher tells the model to read the store copy of the coordinator (`.agents/agents/<coordinator>.md`) in its bootstrap prompt, so a Cline session may read the paragraph too; its opening clause makes it conditional. The registry refuses a malformed section when it loads (an unknown host, a nested or an unclosed section, a stray end marker), before any asset is written, and a rendered store copy is guarded like any copy: a reinstall refuses an edited one without `--force`, whatever the install method, and the lockfile lookup uses the same separator as its records. The paragraph names its host for that reason: each section opens with "If you are running on Antigravity:", and the rest reads correctly for any host that opens the copy. Codex is refused as a fan-out host in the CLI while it is under development; an inventory test installs for it and finds exactly `.agents` and `AGENTS.md` at the top level, no marker or paragraph in the index, and the paragraph only in the store copy.
- **Consequences**:
  - Positive: the factory's check accepts the three agency media copies and the Tier 1 designer without a hand-typed difference, because the canonical agent says what the native file holds. The Tier 1 department can generate a photograph through the same route, with the same rules, as the agency. Nothing can reach the whole `image-gen` server by accident when a later version of the package adds a tool.
  - Claude output: the projected (non-native) copies of the motion and sound designers, which the `full` bundle installs, now carry the `mcpServers:` field and the grants `mcp__higgsfield`, `mcp__klingai`, `mcp__elevenlabs` and `mcp__fish-audio`; the creative designer's projection carries `mcp__image-gen__generate_image`. Native files change in two places: `marketing-creative-designer` and `orchestrator-marketing` (the tools line, the text and the roster row).
  - Antigravity output: the base role files name the servers in their `mcpServers:` frontmatter, and an install with the Antigravity native lane on (`agents add --native`, decision 5) writes the four hosted servers to `.agents/mcp_config.json` as bare `serverUrl` entries (nothing for `image-gen`). A first install for Antigravity alone, without `--native`, of a bundle that holds these roles writes no `.agents/mcp_config.json`; its install panel lists the four as optional and, unless an MCP configuration the host reads already has them, not configured, and prints no `serverUrl` entry. The doctor's missing-server audit says nothing of them, because every bundle that holds these roles lists them as optional extras and none requires them (decision 4). In a workspace where the lane is already recorded, an install without `--native` keeps the lane on and the servers stay wired. `--native` adds the entries automatically; a hand-written `serverUrl` entry also connected (`host-library/antigravity/observations/2026-11-26-agy-1.5-media-servers-and-image-skills.md`). Seen on 2026-11-26 with `agents add digital-agency -t antigravity`, with and without `--native`, in fresh folders, with the CLI built from origin/dev. Whether a name-only `mcpServers:` reference in a role file resolves on Antigravity is not established, which already holds for `stitch` and `figma`; the workspace file is what connected. Cline drops `mcpServers` (its ledger row stays `unsupported`), so its agent files do not change; its doctor lists a declared and unconfigured server with the host's wizard route, unless an installed bundle lists it as an optional extra, as these are. Codex has no per-role projection; it gets `AGENTS.md` and the store (decision 11).
  - Limits: OAuth on the hosted servers was seen on Antigravity (decision 10) and not run on Claude Code, Higgsfield's OAuth on Claude included; the Claude command for Higgsfield now names `/mcp` and no Claude session was run. No live image call was made, and the real calls to OpenAI and Seedream stay not established, as ADR 0049 records. The Antigravity image-choice paragraph was not run in a live Antigravity session, and its claim about the `image-generator` subagent rests on the host library and a headless report that is unverified beyond itself. A `--scope local` server still belongs to the folder it is added from. The grant is a statement of what the role may call, not evidence that a server is connected or a provider account is entitled.
  - The `full` bundle's tree no longer says "None" for its prerequisites; it names the optional MCPs. The prerequisite panel of `growth-marketing` and `full` now appears at install, with optional lines only, and never stops the install.
  - Open for the maintainer: a live check that the Tier 1 designer and its lead generate an image with the user's own key; a live sign-in to one hosted server on Claude Code; and a live Antigravity session that shows the paragraph's first option.
