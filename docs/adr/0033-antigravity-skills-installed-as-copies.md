# ADR 0033: Antigravity Native Lane Installs Skills as Copies

- **Status**: Accepted — 2026-10-03 (maintainer decision 1 of the three the real-session probes left open: "copy skills when the native lane is on, with a doctor warning and an install note otherwise"). Builds on ADR 0031 (the lane) and the 2026-10-03 probes.
- **Context**: Prior art searched: `src/core/installer.ts` (`deployFile`: the default method makes each skill folder an NTFS junction on Windows, a directory symlink elsewhere, `fs.ensureSymlink`; the per-file lockfile record already carries a `method`), `src/core/updater.ts` (the copy-mode conflict check keyed on the lockfile's global `method`), `src/core/uninstaller.ts` (`safeRemove` unlinks a link and never follows it), `src/core/doctor.ts`, the observations `2026-10-03-agy-1.2.15-skills.md` (project skills absent from a session) and `2026-10-03-agy-1.2.16-probes.md` probe (b) (the cause: real skill folders were listed, the 36 junctions were not), `registry/hosts/antigravity/profile.json` (`skillInstallMethod`), ADR 0029 (the Cline lane serves skills from `.agents/skills/`), and the open and closed pull requests (#110 to #115 are merged; none touched the install method). What the evidence says: on agy 1.2.16 (Windows, headless) a skill installed the default way is invisible to the host, so every skill the lane relies on is absent from a real session. POSIX symlinks, file symlinks and other agy versions were not tried.
- **Decision**:
  1. **With the Antigravity native lane on, the skills in `.agents/skills/` are real copies, whatever the install method.** `agents add --native` copies them even without `--copy`; an explicit `--copy` behaves as before. Every file of a skill folder (`SKILL.md` and its sidecars) is recorded in the lockfile with `method: 'copy'` and its own hash, so drift is tracked file by file. The other assets of the store (agents, rules, workflows) keep the method chosen by the user: only skills were shown to be invisible as links.
  2. **Without the lane nothing changes in the install**, because the legacy lane serves other hosts that read `.agents/skills/` and no evidence says they need copies. Instead the doctor warns when skill folders under `.agents/skills/` are links (Windows only, since the observation is for junctions), and `agents add` prints a note once, both naming what was observed (agy 1.2.16 did not list them), what was not tried (POSIX symlinks) and the two ways out (`--native`, `--copy`).
  3. **Existing installs migrate on the next install or `agents update`.** A copy is never written through a link (the link points into the registry): `deployFile` unlinks a link at the destination before copying, which removes the link and never the registry (tested: the registry files survive). The lane is sticky, so `agents update` re-runs the install without the flag and with `--force`, and every junction becomes a copy.
  4. **A copy the user edited is not overwritten without `--force`.** Before copying a skill, the installer compares each file the lockfile records as a copy with its recorded hash and refuses with "has user modifications" when they differ, as it already does for agents. The updater's conflict check, which ran only when the lockfile's global `method` was `copy`, now also runs for a symlink-mode install that holds copy-recorded files (compared file by file; a file recorded as a link is never compared, since its bytes follow the registry). This also applies to a plain `--copy` re-install, which used to overwrite an edited skill silently.
  5. **Turning the lane off does not relink by itself.** The copies stay (an edited one is protected as in 4); `--force` relinks them.
- **Consequences**:
  - Positive: the skills a bundle installs are visible to agy 1.2.16 on Windows, with no manual `--copy`; edits to an installed skill stay in the workspace instead of writing into the registry (an edit made through a link lands in `registry/skills/`).
  - Negative: a lane install holds a full copy of each skill (about 36 folders for `software-engineering`), updated only by `agents update`; a registry skill that changes upstream is not seen until then. The default install of every other lane still links, so a user who relies on `agy` without `--native` gets the warning, not a fix.
  - Open (needs a real session or another platform): POSIX symlinks and file symlinks on agy; agy versions other than 1.2.16; whether a copy installed by the lane is listed on Linux and macOS (it is a real folder there too, so it is expected to be, but was not run).
