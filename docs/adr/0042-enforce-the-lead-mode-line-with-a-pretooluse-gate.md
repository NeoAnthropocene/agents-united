# ADR 0042: Enforce the digital-agency lead's mode line with a PreToolUse gate

- **Status**: Accepted, 2026-10-07 (Plan 035, session N2). The maintainer decided to build the hook ("Build it now") after the text rule had held in 3 of 11 checks; the design (block once, ignore teammates, fail open) was decided by the executing session from a probe and is reversible. Not yet seen: the gate on a task prompt that orders a consultation, and on the Sonnet lead.
- **Context**: prior art searched first: ADR 0039 (the native roster), ADR 0041 (the mode counts), Plan 035 D50 (the mode report first, a prose rule that failed in seven of seven runs), `src/core/guard.ts` and `readonly-guard.ts` (the guards as script files), `host-library/claude/guide/agent.md` ("Prose is not enforcement; a `PreToolUse` hook is") and `guide/hook.md`. The lead is asked to open its first message with `Mode: <Fully|Limited> Operational. Callable: ... Missing: ... Extras: ...`. Moving the rule into a section of its own, tying it to the first call other than `ToolSearch`, asking for a search of all six names and naming the section in the `agents start` kickoff did not hold it: 3 of 11 conclusive checks, 0 of 6 live. A probe of a logging-only hook on the lead (`2026-10-07-n2-records/hook-probe.log`) showed that the transcript never holds the call being made when `PreToolUse` fires (0 of 12) and lags seconds behind, that `UserPromptSubmit` fires from agent frontmatter, and that the lead's frontmatter hooks also fire for its teammates' calls.
- **Decision**: (1) **A `PreToolUse` gate on the lead, as a script file** (`agents-united-mode-line-gate.js`, a third guard kind `mode-line` beside `destructive` and `read-only`, installed, refcounted, uninstalled and checked by the doctor through the same machinery; matcher `*`). (2) **It holds the first main-thread call other than `ToolSearch` once per session**, with a message that says what to write; a call that arrives within two seconds is held with it (a message of parallel calls is held as a whole); later calls pass. It does not wait for the line to appear in the transcript, because the transcript cannot show the current message. (3) **There is no way out in the message**: the first version said "if your last message already began with that line, repeat the call" and the lead used that falsely (test 6); the message now says the host cannot see the message being written, so the call is held once whatever the lead wrote, and asks for the line in the same message as the repeated call. The lead's body says so too. (4) **It leaves a call that carries an `agent_id` alone** and fails open on every error (no session id, unusable temp directory, bad input). (5) **It is module-neutral** (no top-level `require`), since a `.js` file in a user's ES-module project would crash and the host lets a crashed hook's call through. (6) **No inline form**: a GLOBAL install, which cannot name a project script, carries the lead without the gate.
- **Consequences**:
  - Positive: the mode line is no longer a request the lead may weigh against its user turn; seen on the Opus lead with the kickoff (test 7): held at 10:57:22, the line written at 10:57:24, the call repeated. One extra model turn per session, about 0.02 to 0.05 USD.
  - Limits: the gate only holds a call; it does not check what the lead then writes. A lead that complies in the same message as its first call is held once anyway and writes the line twice (test 7 shows the duplicate). It cannot be measured headless (`claude -p` skips the frontmatter hooks of a project agent). Every tool call of the session, teammates' included, starts one `node` process for the hook (1 to 2 ms inside the script).
  - Not established: the Sonnet lead and a task prompt with an order; `claude --continue` after a held call; the cost of the missing gate in a global install.
  - Open: a `Stop` hook as a backstop (`last_assistant_message` is reliable there), or a `UserPromptSubmit` reminder (it works from agent frontmatter); whether to give the engineering coordinator a mode line at all.
- **Amendment (Plan 035 N3, 2026-10-07)**: read on two more runs. **G1** (session `55599c5a`, the Sonnet lead, a task prompt that orders a consultation, 0.4768 USD): six `ToolSearch` calls passed, the first `Agent` call was held at 11:21:20, the line was written once at 11:21:22 and the call repeated at 11:21:23, with no duplicate; Emre loaded `SendMessage` after his spawn and answered the shutdown request with an object on the first call. **R1** (session `8e2c3d9e`, the H1 brief on a long first turn, 0.7251 USD): eight `ToolSearch` calls, the first `Agent` call held at 12:29:01, the line once at 12:29:03, the repeat at 12:29:05; Ava, the spawned agent, has no hook error in her record. **The maintainer accepted the duplicate line** (seen once, in test 7, when the lead wrote the line before its first call; not in G1 or R1) and chose no `Stop` backstop and no `UserPromptSubmit` reminder: neither removes the duplicate and each adds a process per event. **The hold looks like a failure to a user**: the host prints it as `Error: PreToolUse:Agent hook error: [node ...]` at the start of every session, and in R1 the held spawn was read as "the spawned agent couldn't use the hook". The host's prefix cannot be changed, so the message now begins "Mode line first. This is an expected one-time hold, not a failure." (a text-only change; whether a JSON `permissionDecision: deny` reads gentler was not tried). Still not established: `claude --continue` after a held call, the cost of the missing gate in a global install, and the gate with all nine teammates running.
