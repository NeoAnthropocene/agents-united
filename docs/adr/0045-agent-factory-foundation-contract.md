## Decision

1. **Reuse the definition, add only permitted affordances.** A Subagent Contract has exactly `definition`, `workflows`, `skills`, `hooks`. `definition` is the stem of an existing `registry/core/<role>.core.md`; the other fields are explicit, unique lists of lowercase hyphenated semantic identifiers, including empty lists. This avoids duplicating the Semantic Core or introducing a second floor. The future contributor declarations live beside their cores as `<role>.contract.json`. The foundation adds a pure, opt-in validator against a caller-supplied core map; no loader, registry entry, factory role or installer consumer is added. It rejects malformed lists, unknown fields, missing definitions and impure definitions through the existing core validator. A list grants permission to use a named affordance; it neither installs, preloads nor enforces it.
2. **The host is an authoring input.** The caller supplies host key, surface and observed version, artifact types, definition/contract, absolute workspace and output root, operation (`create` or `update`), intent (`local` or `upstream`), and evidence/usage budget. Read `host-library/<host>/{sources.json,library.lock.json,guide/,observations/}` and `registry/hosts/<host>/{profile,tool-policy}.json`. Missing or held evidence blocks only the dependent artifact. Do not infer a host from a shell, copy another host's vocabulary, advance Plan 034's reviewed baseline, or clear its security hold. A fourth host needs its own reviewed data and realization/conformance work, not a new shared role; this is a design target, not a live portability claim.
3. **Host realization owns mechanics.** The package binds each declared affordance to its native file/entry point, discovery, tool grants, invocation, prerequisites, guard registration, ownership and evidence (or a declared delta with rationale). Frontmatter, model/effort, tool names, events, matcher syntax, script paths and native formats stay outside the shared contract. The floor stays verbatim; capabilities resolve through the existing host tool policy. A reference-only skill is explicitly identified, and every other shipped skill has a loading role. The host matrix and checklist are in [the foundation specification](../agent-factory-foundation.md).
4. **Separate procedure from scheduling.** A runbook is single-agent decision guidance. A pipeline orders delegated stages and verifies their results. Claude can realize a pipeline as a dynamic JavaScript workflow launched by the main-thread orchestrator; stop between workflows for human decisions, and record a manual runbook fallback when the workflow feature is unavailable. Cline uses a Markdown workflow followed by its lead and configured-agent tools; Antigravity uses a skill runbook plus named native delegation. The latter two are prose ordering, not scripted scheduling guarantees. Realize authors artifacts; sync refreshes audited evidence and proposes adaptation, never implements it. Neither silently publishes or installs. Existing Claude maintainer skills remain entry points.
5. **Keep local creation reversible.** Default to an explicit user-chosen draft directory, separate from managed install outputs. `local` returns draft files and checks with no upstream PR; `upstream` follows the repository's branch/PR procedure when authorized. Never edit managed projections as an authoring source. Licence, attribution and security obligations apply to copied local material too; a private draft does not justify false provenance. Installer/lockfile/doctor semantics await ADR 0046 and are not implemented here.
6. **Reuse quality gates and require evidence.** Repository CI remains authoritative for core/floor, native conformance, skill portability/licence/layout/ratchet and guide citations. A future contributor runbook invokes equivalent available checks and reports unavailable ones as unverified; packaging those tools is deferred. Reuse `docs/skill-intake.md`, ADR 0040, provenance pins and `hostlib:candidates`: copied adaptations carry a supported source/licence and pin, independent work credits inspiration without claiming adaptation. A `not-found` provenance finding gets an owner. Merge/drop of existing skills needs the maintainer's decision. The session reader stays a maintainer tool for now; distributable readers for other hosts are separate reviewed work.
7. **State enforcement by rule and surface.** Each host binding records whether a rule uses a host-enforced tool restriction, a registered script/plugin guard, or prose; its input visibility, failure policy and known gaps; the offline test and live probe. A first-action requirement needs an effective guard before claiming enforcement; lacking the hook or input is an honest gap, not a pseudo-hook. Claude project-agent frontmatter hooks are not measured by `claude -p`, team protection needs settings-level guards, and global mode-line protection is absent. Cline's configured-agent tool list is enforced; its CLI guard plugin may end a run, and IDE extensions have no such plugin enforcement. Antigravity puts guards in workspace `hooks.json`, never agent frontmatter; its tool list supplies read-only restrictions. Protected-branch and pinned/generated-file guards are candidates for slice 5, not guarantees added here.
8. **Follow ADR 0044 for R3.** Readable transcripts without a saved mode prefix remain held; repeated holds during transcript lag are permitted. There is no two-second release or guaranteed one-time hold. ToolSearch/teammate exceptions and I/O fail-open limits remain explicit. Static tests and prior observations do not establish the candidate's live timing. The fresh allowance is 50 USD aggregate, at most 16 headless and 16 interactive prompts, retries included, extra usage off; no Claude run above approximately 85% of its own five-hour quota. Host records supply per-model costs including teammates; unknown cost is pending, never zero. Codex quota is separate. R3 is typed by the maintainer and judged on all eight Plan 035 expectations.

## Consequences

The validator and reference-host tests establish an offline contract without changing a catalog, native artifact or install lane. Identifier closure against host bindings and live behavior are later conformance gates; a structurally valid declaration can still refer to an unavailable skill or hook. The basic contract carries no host matrix or runtime host detection.

Local drafts work without deciding storage precedence, but they are not installable bundles. ADR 0046 records the concrete product options; slice 2 may proceed independently of local installation, while any local installer change waits for that decision. Subsequent development order stays slices 2, 3, 4 (realize, then sync), 5, after foundation review and interactive evidence.

**Maintainer decision, 2026-10-07:** guide upstream contributors to a PR targeting `dev`. The existing default PR template and four artifact proposal forms were checked first. A focused artifact template and `docs/artifact-contribution.md` specify evidence and the proposed `prepare-artifact-contribution` runbook; implementing its workflow/skill is later-slice work. This upstream route does not change decision 7 or resolve local installation.
