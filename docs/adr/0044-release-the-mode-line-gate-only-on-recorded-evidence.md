# ADR 0044: Release the mode-line gate only on recorded evidence

- **Status**: Accepted, 2026-10-07, for the authorized R2 defect fix. Supersedes ADR 0042's two-second release policy. The maintainer authorized a test-first fix in a separate pull request for a violation found in R2. The implementation is verified locally; live behaviour is **unverified**.
- **Context**: prior art read: ADR 0042, the N2/N3 observations, the host's agent and hook guides, `src/core/mode-line-gate.ts`, the native script and its tests, and open and closed pull requests searched for `mode-line`. R2 (`75b89b2c-9b9b-484b-ae23-9df2a515d676`, `n3-regress2`, Claude Code 2.1.292) showed a held Bash call at 13:21:25.563 UTC followed by an allowed Agent call at 13:21:28.915. Both tool calls have assistant message id `msg_011CfnwqeWA8VU9bqtQGSJJd`, and their call timestamps are 3.433 seconds apart. The lead never wrote a mode line. The two-second window did not hold the streamed response as a whole. PR #173 preserves the partial-run evidence; R2 stopped at quota in Tier 2 and does not establish a full-roster regression.
- **Decision**:
  1. Keep the existing `PreToolUse` script and registration. Remove elapsed time as a release condition. A lead call other than `ToolSearch` stays held while a readable transcript contains no assistant text block opening with `Mode: Fully Operational.` or `Mode: Limited Operational.`.
  2. Once the line is seen, save a version-2 completion marker. An old `done` marker may have been created by elapsed time alone, so it is rechecked against the transcript. No sleep or polling loop is added.
  3. The host saves transcripts asynchronously. A compliant response can therefore be held again before its line reaches disk. The message and lead body explain that retry; they no longer promise a one-time hold. A duplicate line remains acceptable under ADR 0043.
  4. Keep the exceptions for `ToolSearch` and calls carrying `agent_id`. An unreadable or missing transcript, unusable marker directory, absent session id or bad input fails open. A readable but delayed transcript is evidence not yet present, not an I/O error.
  5. No `Stop` hook, `UserPromptSubmit` reminder, JSON deny probe, global inline gate or additional host work is added. This checks presence of a mode prefix, not the accuracy of the reported integrations.
- **Consequences**:
  - The automated reproduction holds both streamed calls even beyond 3.433 seconds, and releases them only after the line is saved. Tests cover an old completion marker, delayed transcript writes, CommonJS/ES-module execution, Windows line endings and the existing exceptions.
  - A saved line in an earlier response allows the first call directly. The gate may add more than one repair turn while the transcript lags; its live timing and quota cost are **unverified**. If a host never persists the line into a readable transcript, the lead remains held until that evidence appears.
  - Missing/unreadable evidence still fails open, and a global install still has no gate. These are explicit limits, not proof of enforcement on those surfaces.
  - No further live prompt ran: N3's five-prompt ceiling is exhausted. Any retest requires a new ceiling and a prompt typed by the maintainer.
