# ADR 0036: A Tier-2 Organization Bundle as a Native Package on Claude Agent Teams, with Bundle-Scoped Native Roles and the Comms Law Bound to the Team

- **Status**: Accepted — 2026-10-04 (maintainer, in chat, after a grilling: the pilot roster, the probe-first plan for teammate protection, a ceiling of 5 USD and 10 prompts, then "offer the settings-level guard and warn without it", "two-mode wording in the Tier-2 roles and `frontend-architect`", and "separate agency-only role copies"). Follow-up (2) of the plan 032 close-out. Builds on ADR 0018 and 0025 (native Claude agents), ADR 0035 (the guards as files), Plan 022 and Plan 024 (the comms law) and Plan 016 (the Agent Teams scaffold).
- **Context**: Prior art searched first: `plans/022-subagent-comms-and-hardening.md` and `plans/024-field-test-fixes.md` (the two-mode law: relay by default, team mode only when the brief lists the peer), `src/cli.ts` (`resolveClaudeTeamsPosture`: a Tier-2 bundle starts as a team by default, the switch is injected ephemerally), `src/core/claude-launcher.ts` (the bootstrap prompt names no role), `host-library/claude/guide/orchestration.md` and the Agent Teams page (what a teammate gets from a definition), the Tier-1 native files, and open and closed pull requests for "agent teams" and "digital-agency" (none). Facts that shaped the decisions: only one organization bundle is real (`digital-agency`; the other entry is `mock-organization-under-construction`, a CLI-gate fixture); `registry/core/` held only the five Tier-1 cores; and three of the agency's roles (`marketing-growth-strategist`, `marketing-creative-designer`, `marketing-conversion-specialist`) are shared with the Tier-1 marketing bundles. Real sessions on Claude Code 2.1.288 (`host-library/claude/observations/2026-10-04-claude-2.1.288-agent-teams.md`): a teammate reusing a definition does not get its frontmatter hook (a write went through with no hook record), a settings-level guard does refuse a teammate's `git push --force` and `.env` write, a teammate's `tools:` list holds, and a message to a working teammate is delivered only after its turn ends, as a new turn.
- **Decision**:
  1. **Pilot roster.** The lead (`orchestrator-digital-agency`, `opus` at `medium` like every native orchestrator, ADR 0018 addendum) and three teammates that are the bundle's own copies of shared roles (`agency-growth-strategist`, `agency-creative-designer`, `agency-conversion-specialist`; the personas Ava, Jamileh, Kaan) written from new Semantic Cores; the existing native `frontend-architect` joins the team. The other five roles keep their legacy projections beside them (a mixed install is supported). The full roster is a follow-up.
  2. **Bundle-scoped native role names.** `registry/bundles.json` gains `nativeRoles`, a map from a bundle's canonical agent file to the native role the native lane installs for that bundle instead of the role of the same name. It is validated (the key is one of the bundle's agents, the value is a role name, unique, and not another agent's default name) and ignored with the lane off or for any other bundle. A scoped native role is owned by the installing bundle alone and records no canonical pointer, so Tier-1 marketing keeps its legacy roles, installing both bundles moves nothing of the other's, and removing the agency removes only its own files. The lead's `Agent(...)` allowlist and the roster use the scoped names.
  3. **The comms law bound to Agent Teams.** Each teammate's body and the lead's carry the two-mode law: relay is the default, team mode only when the brief lists each peer, at most two exchanges per pair (an exchange is one message and its reply), one hand-back, `Peer messages received` and `Open items`. The lead spawns teammates with one `Agent` call that sets `name` and `subagent_type`, writes the brief (objective, scope, acceptance evidence, peers, report format), delegates a shared interface contract-first, relays and wakes. Because a message to a working teammate arrives only after its turn ends, the bodies say: do not wait for a reply, carry on from a stated assumption, and report again with `Peer messages received (update)` when a late message arrives. The six shared invariants live in each Semantic Core and the evidence that binds them is `tests/helpers/comms-law.ts`. From the check against the live Agent Teams page the lead also follows the host's own model: the Assembly Line goes on the shared task list (one task per slice, owner and dependencies set, so the host unblocks a task itself) when the lead has the Task tools, which the host provides by default only on Sonnet 4 to 4.6, Opus 4 to 4.7 and Haiku 4.5 (on a newer model they need `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`; without them the line runs through the briefs); a teammate claims only the task its brief names and marks it completed; the lead starts with three to five teammates per tier (the nine types are a menu), waits for them, checks a stuck task (status can lag) and asks a delivered teammate to shut down by name (the team is cleaned up when the session ends).
  4. **A teammate is guarded by the settings-level guard, and the install says so.** A role's own frontmatter hook still guards the lead (a main-thread `--agent` session) and a subagent, but not a teammate. For a native organization-tier install: the install prints an Agent Team note (how to start, that teams are experimental and interactive, why only the settings-level guard covers a teammate, whether it is installed and the command to add it); the existing consent question for that guard (interactive, default yes, never written without consent) names the teammate reason; and the doctor warns while the guard is not in effect. A teammate's least privilege is its `tools:` list.
  5. **No workflow in this package.** The lead holds no `Workflow` tool (its core has no `workflow` class) because the bundle ships none; fan-out is parallel `Agent` calls or a live team. The agency's `workflow-agency-*` skills stay skills (the `pipeline` and `runbook` triage is a separate follow-up).
  6. **`frontend-architect` gets the two-mode wording.** The outright ban on messaging a sibling is replaced by the same two-mode text (maintainer decision). A Tier-1 brief lists no peer, so Tier-1 behaviour is unchanged. The other three Tier-1 natives are untouched.
- **Other hosts (research on 2026-10-04 from the live documentation; nothing is implemented, and none of it was run in a session in this slice):**
  - **Claude Code** (`code.claude.com/docs/en/agent-teams.md`, read in full): an `Agent` call that sets `name` starts an in-process teammate when `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`; a named subagent definition is applied as tools (plus `SendMessage` and, where available, the Task tools), model, effort, `disallowedTools` and body (not skills, hooks, `permissionMode`; `mcpServers` only in split panes); a shared task list with dependencies, mailbox delivery, plan approval, quality-gate hooks (`TeammateIdle`, `TaskCreated`, `TaskCompleted`), one team per session, no nested teams, no resume. The page is newer than the library snapshot (it adds `disallowedTools`, `effort`, plugin scope and the wake of a teammate waiting to retry): a `host-update-sync` refresh is due and is not part of this slice.
  - **Cline** (`docs.cline.bot` team pages, read; unchanged from the library): `cline --team-name <name> "<task>"` or `/team` (CLI, SDK and Kanban, not the IDE extensions); the coordinator gets `team_spawn_teammate` (a new agent with a role and a task), `team_delegate_task`, `team_check_status` and `team_get_result`; state persists as a task board, a mailbox and a mission log under `~/.cline/data/teams/<name>/` and resumes. The docs name **no way to create a teammate from a named role or agent file**, no peer-messaging tool or delivery rule, and nothing on whether hooks or plugins apply to a teammate; on CLI 3.0.68 the team flags are not in `--help` (earlier observation). The equivalent of our roster is therefore a coordinator that carries each role's text into every `team_spawn_teammate` call, which nothing makes it do; the configured agents (`subagent_<name>`) are hub-and-spoke only. Cline's own subagent page calls subagents experimental.
  - **Antigravity** (`antigravity.google/docs` team and subagent pages, read; unchanged from the library apart from two facts): `/teamwork-preview` (paid plans, preview, App 2.0 and the CLI) runs the host's own fixed team (Sentinel, Project Orchestrator, Explorers, Workers, Critic, Challenger, Auditor, Success Auditor) and documents no way for a package to define or replace its roles, so a package cannot depend on it. The package-owned equivalent is custom subagents (`.agents/agents/<name>.md`, `tools:` enforced by the host, observed) invoked with `invoke_subagent`, several at once, inheriting the parent's allowed command prefixes, file scopes and sandbox, with isolation `inherit`, `branch` or `share`. Agents address each other by conversation ID, peers included, and a message to an idle agent re-awakens it with its context kept: a documented peer mechanism, so team mode could be carried by conversation IDs listed in the brief. A misspelled tool name in `tools:` may hang a subagent (a known issue the page lists).
  - **So a Tier-2 native package elsewhere is a different design, not a port:** Antigravity, a lead plus custom subagents with each peer's conversation ID in the brief; Cline, a coordinator rule and skill whose `team_spawn_teammate` calls carry the role text, with no definition reuse and no verified guard on a teammate. Each needs its own probes (does the host deliver a late message mid-turn, do hooks reach a teammate) before a package is written; whether and when is the maintainer's decision.
- **Consequences**:
  - Positive: `digital-agency` runs natively as a live team with a defined law for peer messages, the comms law has real-session evidence, a shared role can have a bundle's own copy without touching another bundle, and the install says where the guard really is.
  - Negative: a teammate's shell and file writes are unguarded unless the user accepts the settings-level guard (a merge into a user-owned file); the settings-level guard is still the inline form, so its block message is the long one; the roles shared with Tier-1 now exist twice (a Core change to one is a decision about both copies); only a pilot subset of the team is native.
  - Not verified when this was written: the corrected late-message wording in a live team, the lead on its pinned `opus`, `agents start` live, the five legacy teammates, a global install. See the observations file for what each real session showed.
  - Open: whether the settings-level guard should use the script file in a project install (ADR 0035 left it inline because the legacy goldens pin it); whether to widen the read-only guard to delegation tools (found in the guard-file slice); batch-migrating the other Tier-1 and Tier-2 roles.
- **Addendum, 2026-10-04 (later, `host-library/claude/observations/2026-10-04-claude-2.1.288-agent-teams.md`)**: on `claude-sonnet-5-5` the shared Task tools are absent by default and are listed as deferred tools with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`, so the lead checks and loads them with `ToolSearch` and otherwise runs the Assembly Line through the briefs (that path was shown to work). Relay mode, the default of the law, was run headless on Claude Code 2.1.289 (teams off): the lead fixed the shared interface in the briefs (contract first), no subagent tried to message a peer, and the reports carried `Peer messages received` and `Open items`. A live team still needs an interactive session (`-p` never spawns teammates); the re-run with the corrected wording is not yet done. Open: whether `agents start` injects `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` for a team.
