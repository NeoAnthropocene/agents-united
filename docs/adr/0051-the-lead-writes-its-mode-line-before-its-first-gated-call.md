# ADR 0051: The lead writes its mode line before its first gated call

- **Status**: Accepted, 2026-10-12. The maintainer, shown the observation of Sitting R and told that the lead could write its line together with its last allowed call so that no hold shows at all, answered "yes, we should do that I think", and added about the same run: "it repeats 3 times the available MCPs and running mode, this is not quite right". Amends where the lead writes its line in ADR 0042 and ADR 0044; the gate itself is not changed. Built in PR 197. **Unverified live (Sitting S).**
- **Context**: ADR 0042 put a `PreToolUse` gate in front of the lead's calls other than `ToolSearch` until its mode line is in the saved transcript, and ADR 0044 made the release depend on that evidence alone, accepting that a response whose own message carries the line is held once, because the host saves a message a moment after it ends. The lead's section said to write the line in "the first message that holds any other call". Every session therefore began with at least one hold, which the host shows to the user as a "PreToolUse hook error", and, since each retry was told to write the line again, with the line more than once. Sitting Q (`314be482`, Claude Code 2.1.296) showed the worst case of that design: six calls held in four messages, the line in the lead's reasoning in three of them, and a lead that stopped and waited for the user (the stop was caused by a sentence of the lead's paragraph on photographs, since corrected). Sitting R (`1269c24c`, the same build, after those corrections) showed its best case: two holds, the Gemini branch of the lead's offer reached for the first time, and the line written twice before the first call and a third time in the last message. The host's save can lag by seconds (ADR 0044 records a hold 2.3 s after the line was written), so a fixed wait would not remove the holds either, and ADR 0044 decided against one.
- **Decision**:
  1. **The line goes one message earlier, with an allowed call.** The lead's first message holds only `ToolSearch` calls (the six integrations, MarkItDown, Stitch). Its second message opens with the line as a text block, then the introduction, and holds one `ToolSearch` that checks for and loads the task tools and `SendMessage` (an allowed call, which the lead's section on the shared task list already asks for). Its first other call is in the third message, when the host has saved the line, so the gate finds it and holds nothing.
  2. **The line is written once.** The mode and the list of what is callable are not stated again in later messages, unless the user asks or the plan depends on an integration that is missing (then the lead says which one and what it changes).
  3. **The gate is not changed.** It remains the backstop for a lead that makes another call first. For that case the message of the hold and the lead's section now say: a hold is not a reason to stop; the line is a text block (reasoning is not text); if you have not written the line as a text block, write it with the repeated call; if you have, repeat the call alone, with no text, and again if it is held again. This replaces "write the line, even if you believe you wrote it", which made every retry write the line again. The false claim that sentence answered (live test 6, Sitting Q) is met by saying what counts as written.
  4. **The expectations for a hold change.** The pass lines of 2026-10-07 for the kickoff and for G1 expect the first call to be held once, the line to be written and the call repeated. Under this decision a session with no hold passes, a hold that the lead repeats is noted, and a line written twice fails H10k.
- **Consequences**:
  - A session that follows the order shows no hook error and one line, followed by the introduction and then the work.
  - It costs one more model round at the start of a session when the lead has nothing to load, since the second message exists to carry the line.
  - It relies on the lead's compliance with the order, as the earlier placement relied on its writing the line at all. The gate catches the failures, and the fallback no longer writes the line again.
  - Limits: the host's save can lag by more than the model's round trip, so the third message can still be held; the lead then repeats the call alone. A lead that wrongly believes it wrote the line (it did so in its reasoning, three times in Sitting Q) repeats the call alone and is held again, and the gate never releases without the evidence (ADR 0044); the message of the hold says what counts as written.
  - Teammates are unaffected: the gate ignores calls that carry an agent id.
- **Not established**: whether the lead follows the order, how often the host's save still holds its first other call, and whether "repeat the call alone" converges (**unverified live (Sitting S)**: H10k2 again, and G1 of Plan 035 N3 again, a prompt that orders a consultation). The full-roster regressions of Plan 035 (R2, R3) were not rerun: the change touches only the first two messages of the lead.
