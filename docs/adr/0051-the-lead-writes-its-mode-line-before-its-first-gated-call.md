# ADR 0051: The lead writes its mode line before its first gated call

- **Status**: Accepted, 2026-10-12. The maintainer, shown the observation of Sitting R and told that the lead could write its line together with its last allowed call so that no hold shows at all, answered "yes, we should do that I think", and added about the same run: "it repeats 3 times the available MCPs and running mode, this is not quite right". Amends where the lead writes its line in ADR 0042 and ADR 0044; the gate itself is not changed. Built in PR 198. **Amended 2026-10-12 after Sitting S: decision 3 is replaced (see the amendment at the end). Unverified live (Sitting T).**
- **Context**: ADR 0042 put a `PreToolUse` gate in front of the lead's calls other than `ToolSearch` until its mode line is in the saved transcript, and ADR 0044 made the release depend on that evidence alone, accepting that a response whose own message carries the line is held once, because the host saves a message a moment after it ends. The lead's section said to write the line in "the first message that holds any other call". Every session therefore began with at least one hold, which the host shows to the user as a "PreToolUse hook error", and, since each retry was told to write the line again, with the line more than once. Sitting Q (`314be482`, Claude Code 2.1.296) showed the worst case of that design: six calls held in four messages, the line in the lead's reasoning in three of them, and a lead that stopped and waited for the user (the stop was caused by a sentence of the lead's paragraph on photographs, since corrected). Sitting R (`1269c24c`, the same build, after those corrections) showed its best case: two holds, the Gemini branch of the lead's offer reached for the first time, and the line written twice before the first call and a third time in the last message. The host's save can lag by seconds (ADR 0044 records a hold 2.3 s after the line was written), so a fixed wait would not remove the holds either, and ADR 0044 decided against one.
- **Decision**:
  1. **The line goes one message earlier, with an allowed call.** The lead's first message holds only `ToolSearch` calls (the six integrations, MarkItDown, Stitch). Its second message opens with the line as a text block, then the introduction, and holds one `ToolSearch` that checks for and loads the task tools and `SendMessage` (an allowed call, which the lead's section on the shared task list already asks for). Its first other call is in the third message, when the host has saved the line, so the gate finds it and holds nothing.
  2. **The line is written once.** The mode and the list of what is callable are not stated again in later messages, unless the user asks or the plan depends on an integration that is missing (then the lead says which one and what it changes).
  3. **The gate is not changed. (Replaced after Sitting S: see the amendment.)** It remains the backstop for a lead that makes another call first. For that case the message of the hold and the lead's section now say: a hold is not a reason to stop; the line is a text block (reasoning is not text); if you have not written the line as a text block, write it with the repeated call; if you have, repeat the call alone, with no text, and again if it is held again. This replaces "write the line, even if you believe you wrote it", which made every retry write the line again. The false claim that sentence answered (live test 6, Sitting Q) is met by saying what counts as written.
  4. **The expectations for a hold change.** The pass lines of 2026-10-07 for the kickoff and for G1 expect the first call to be held once, the line to be written and the call repeated. Under this decision a session with no hold passes, a hold that the lead repeats is noted, and a line written twice fails H10k.
- **Consequences**:
  - A session that follows the order shows no hook error and one line, followed by the introduction and then the work.
  - It costs one more model round at the start of a session when the lead has nothing to load, since the second message exists to carry the line.
  - It relies on the lead's compliance with the order, as the earlier placement relied on its writing the line at all. The gate catches the failures, and the fallback no longer writes the line again.
  - Limits: the host's save can lag by more than the model's round trip, so the third message can still be held; the lead then repeats the call alone. A lead that wrongly believes it wrote the line (it did so in its reasoning, three times in Sitting Q) repeats the call alone and is held again, and the gate never releases without the evidence (ADR 0044); the message of the hold says what counts as written.
  - Teammates are unaffected: the gate ignores calls that carry an agent id.
- **Not established**: whether the lead follows the order, how often the host's save still holds its first other call, and whether "repeat the call alone" converges. Sitting S ran H10k2 and G1 of Plan 035 N3 on this decision and both failed (see the amendment); the amended message of the hold is **unverified live (Sitting T)**: H10k2 again, and G1 again, a prompt that orders a consultation. The full-roster regressions of Plan 035 (R2, R3) were not rerun: the change touches only the first two messages of the lead.


## Amendment, 2026-10-12, after Sitting S

Sitting S (H10k2 `a7acda03`, G1 `7c3e1121`, Claude Code 2.1.296, the build of this ADR; the record is `host-library/claude/observations/2026-10-12-claude-2.1.296-designer-sitting-s.md`) ran the decision and **it failed in both sessions**. In both, the lead's first message held the searches and its second held the `ToolSearch` that loads the task tools, as decision 1 says, with **no text block**: the line and the introduction stood in the lead's reasoning ("Running in Limited Operational mode with Firecrawl and Context7 available ... As Chris, lead of the digital agency team, I'll load the task and messaging tools, then consult Emre read-only"). Its first other call was held, and the message of the hold, as decision 3 had changed it, told a lead that had written the line as a text block to repeat the call alone and never to write the line a second time. Both leads believed that they had written it. G1 made its `Agent` call 11 times in 11 messages, every one held, and then stopped ("Writing the line again would go against my own rule"), and no teammate started. H10k2 was held 13 times in 12 messages, on every read and every skill load; it wrote that it had written the line twice (twice more in its reasoning), told the user that the hook "may be broken" and that they could disable it, and asked the choice of how the pictures are made in prose. The saved transcripts hold no text block that opens with the line, and the installed hook, replayed on each of them, answers "held": it was right, and the lead was wrong.

**The wrong turn** was decision 3, which I took together with decision 1 and which the maintainer had not asked for: a fallback that depends on the lead's own report of what it wrote cannot work for a lead whose failure is a false report (live test 6; Sitting Q, three messages; Sitting R, its first message; Sitting S, both sessions). The old message ("Do this even if you believe you wrote it already") was the safety net for that failure, and it was removed to stop the line being repeated. And decision 1 does not make the model write text before a call: a model that means to go on to a call often keeps its words in its reasoning, so the order is the preferred path and not a guarantee.

**Decision 3 is replaced**: the hook counts the rounds of holds of a session (the calls of one message are one round: calls closer than 0.8 s), and the message of a hold depends on the round and never on what the lead says it wrote. Round 1: write the line as the first line of a text block in the same message as the call you repeat, even if you believe you wrote it (reasoning is not text). Round 2: if your last message opened a text block with the line, the host has not saved it yet, so repeat the call alone, with no text; if it did not, write it. Round 3 and later: the saved transcript has N text blocks of yours and none opens with the line, so write it again, even if you believe you wrote it. Every message tells the lead not to stop, not to ask the user and not to wait, and the later ones not to tell the user that the hook is broken. **The count changes the message and never the release**: only the line in the saved transcript releases a call (ADR 0044), so a lead that never writes it stays held, as before, but is told what the hook sees within three rounds. The lead's section says the same, and tells the lead never to blame the hook or to suggest that the user disable or edit it.

**Consequences of the amendment.** In the usual case of the host's save lagging, the line is written once (round 1 asks for it, round 2 repeats the call alone); in the case of Sitting S it is written at round 1, or at round 3 at the latest. A session can still show up to three red hook errors when the lead does not follow decision 1, which it did not in two of two sessions of Sitting S; it shows none only when the lead does. Not changed: there is no release by count or by time. The maintainer may want another principle (a release after a number of rounds, which ADR 0044 refused), because in Sitting S the gate held two sessions for the whole of their length.
