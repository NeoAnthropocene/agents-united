# ADR 0039: The Whole Digital-Agency Team Is Native, With a Persona for Every Role

- **Status**: Accepted — 2026-10-04 (maintainer, in chat: "digital-agency should ship … go on this bundle carefully … short personas and alias names for the other subagents", then a grilling: "one PR for all five", "agency-only scoped copy" for the frontend architect, "keep `experimental` until a full-roster live run", persona set "Selin, Emre, Defne, Deniz"). After the full-roster live run (session `d2f784af`, 2026-10-04, 3.02 USD, run by the maintainer) three defects it showed were fixed test first (decision 7). Completes the roster ADR 0036 left open (its pilot was the lead plus Ava, Jamileh and Kaan). Builds on ADR 0036 (Tier-2 on Agent Teams, bundle-scoped native roles), ADR 0037 (the created lane retired) and ADR 0038 (the Agent Teams loose ends).
- **Context**: Prior art searched first: `registry/bundles.json` (`digital-agency` roster, `personaAliases`, `nativeRoles`), the nine legacy agents under `registry/agents/`, the three pilot cores and natives, `tests/native-claude-agents.test.ts` (class-derived grants per role), `tests/native-claude-tier2.test.ts` (the comms law bound to every teammate), `tests/core-safety-floor.test.ts`, `tests/native-invariant-coverage.test.ts`, the plan 032 log, and the live run of the pilot (session `123266e9`, ADR 0038). Before this ADR the team had three native teammates and five roles still projected from the legacy lane (content, campaigns, SEO, QA, compliance), the shared Tier-1 `frontend-architect`, and no persona for four roles (the legacy files address them by job title: "the SEO specialist", "the QA Lead").
- **Decision**:
  1. **Five roles get a Semantic Core and a native file.** `registry/core/subagent-marketing-content-strategist.core.md` (Yavuz), `…-campaign-specialist.core.md` (Jale), `subagent-seo-specialist.core.md` (Selin), `subagent-qa-automation-lead.core.md` (Emre), `subagent-compliance-grc-specialist.core.md` (Defne), each authored from its legacy agent and named for its persona in the identity. The repository's own floor test is kept honest: where a legacy agent has a "Safety Guardrails" list or "Primary Directives" list, the core carries those lines verbatim (Yavuz, Jale, Emre, Defne); the role's own boundary is added after them. The native bodies share the two-mode comms law of the pilot, with ADR 0038's wording on deferred tools.
  2. **Class-derived tools, from the legacy frontmatter.** Content and campaigns hold editors and no shell, like the pilot. SEO, QA and compliance hold a shell (the legacy lane gave them `run_command`) and so are guarded as writers; QA also holds `Monitor` and the Task tools (the legacy `manage_task`), and none holds a scheduling tool (Plan 022 H2 stays: the legacy QA agent's `schedule` becomes a recommendation under `Open items`, the lead schedules). MCP servers come from each legacy agent: content `firecrawl` and `markitdown`, campaigns `context7`, SEO `firecrawl` and `chrome-devtools-mcp`, QA `playwright`, `chrome-devtools-mcp` and `context7`. **Compliance holds four explicit read tools of `github` instead of the whole server** (the legacy lane granted all of it): the role reads repository evidence and never writes to GitHub, so least privilege wins over parity; `markitdown` and `context7` are whole servers.
  3. **Every agent of the bundle is a bundle-scoped native role.** `nativeRoles` now maps all nine agency agents to `agency-*` names, so no legacy projection stays beside the native files and Tier-1 bundles (`marketing`, `seo-content-marketing`, `qa-automation`, `software-engineering` and the rest) keep their legacy or canonical roles untouched. A test pins that the map covers every agent of the bundle but the lead.
  4. **Deniz is an agency-only copy of the frontend architect** (maintainer decision). The shared core is persona-free and serves `software-engineering` too, so the copy carries the persona in its own body ("In the digital agency you are Deniz …"), not in the core; its floor is the shared core's, verbatim. The canonical `frontend-architect` keeps its two-mode wording and stays installed by the Tier-1 bundles; the two sit side by side with separate records.
  5. **Personas and aliases for all nine.** `personaAliases` gains `selin-seo`, `emre-qa`, `defne-grc` and `deniz-frontend` beside the existing six, each mapping to the canonical agent file it plays; the lead's persona table names all nine types, spawns each by its lower-case name (`ava`, `kaan`, `jamileh`, `yavuz`, `jale`, `selin`, `deniz`, `emre`, `defne`) and puts each on the Assembly Line by name. Each description names its persona in parentheses, as the lead routes by it.
  6. **The bundle stays `experimental`** until a full-roster live run holds (maintainer decision). The run is done (decision 7): all nine roles delivered in Assembly Line order, with three defects found and fixed; whether the label now changes is the maintainer's call and is asked next, not decided here.
  7. **Three defects of the live run, fixed test first.** (a) *A task owner announces the task to a running teammate, which acts on it at once*: the lead had consulted Ava read-only ("write NO files"), then set her task's owner, and the host delivered a `task_assignment` that she answered by writing her deliverable inside the consultation. The lead's body now says to set an owner only when the work should start and to keep a consulted teammate's task unowned until the consultation is accepted; every teammate's body says that a task assignment does not lift a read-only consultation. (b) *A plain-text shutdown request is refused* (no `request_id`): the lead's body now says to ask with a structured `shutdown_request`. (c) *Unchecked figures*: Ava reported 38 lines for a 29-line file and had not read it back; the five roles without a shell now re-read what they wrote with `Read` before they report and label a figure they did not check as an estimate. The evidence is in `host-library/claude/observations/2026-10-04-claude-2.1.288-agent-teams.md`.
- **Consequences**:
  - Positive: the whole team is native and conformance-tested (floor identity, class-derived tools, guards, comms evidence, invariant evidence, the lead's roster generated from the files); personas are consistent across the lead, the registry and the roles.
  - Negative: six more authored files to keep in step with their cores (the evidence table fails when a body stops stating an invariant); the Cline coordinator rule, the one projector that renders `personaAliases`, now lists four more personas whose legacy agents still address them by title (the Cline and Antigravity packages are the next slices); the QA role no longer schedules recurring runs itself.
  - Established by the live run: all nine specialists run as teammates under their agency-only names, the later tiers of the Assembly Line ran on dependent tasks, every teammate loaded the Task tools and marked its own task completed, the wake path and a relay to a working teammate worked, and a structured shutdown is approved by all nine.
  - Not established: the fixes of decision 7 in a live team (written after the run); `agents start` live; a peer exchange in the nine-role team (the contract was fixed in every brief, so none was needed); the host refusing a blocked task started early; the settings-level guard in a team with a command it names; the MCP-backed modes; the lead on Opus.
  - Open: persona text for the legacy canonical agents (Cline and Antigravity); whether the QA role should get a saved workflow for recurring runs; the `experimental` label.

- **Amendment (Plan 035 S9, taken by the maintainer on 2026-10-07, ADR 0043)**: decision 6 left the `experimental` label to the maintainer. Plan 035 hardened the pilot first (the skills, the session report, the live scenarios H1 to H9, read in M3 and in sessions N1 to N3), and on 2026-10-07 the maintainer decided to remove the label: the bundle carries no `status` (the same as the thirty bundles that are usable and still being hardened), its category text drops "(Experimental)", and README and PROJECT.md stop calling it experimental. Promoting it to `stable` is a separate decision; the defects that are still open are listed in the plan's "Close-out checklist".
