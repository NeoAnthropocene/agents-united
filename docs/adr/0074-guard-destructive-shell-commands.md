# ADR 0074: The destructive guard also blocks the common destructive shell commands

- **Status:** Proposed. The four choices marked "maintainer" were put to him in a question dialog by the orchestrating AI session on 2026-11-19; the rest were decided by that AI session and are his to overturn in review. Built and gated offline; the new guard has not been seen in a live Claude Code session.
- **Planned at:** `689061d` (`origin/dev`). ADR numbers through 0070 were checked on `origin/dev` the same day; 0071 to 0073 are taken on other branches.

## Context

The canonical agent definitions state a deny rule for destructive shell commands (`registry/agents/subagent-*.md`, the `guard:` line of 12 agents): `rm -rf` and `sudo` and `shutdown` in all 12, `DROP`/`DROP DATABASE` in 5, `az group delete` in 1. On the Claude-native lane that rule was only a sentence in a role's text. The shared PreToolUse guard ([ADR 0035](0035-claude-guards-as-script-files.md), [ADR 0068](0068-guard-failure-mode-and-claude-floor.md)) blocked three things: a forced `git push`, `vercel --prod` and writes to `.env` files.

The new devops-engineer role runs with `permissionMode: acceptEdits`, which auto-approves `mkdir`, `touch`, `rm`, `rmdir`, `mv`, `cp` and `sed` inside the working directory ([permission-modes.md](../../host-library/claude/pages/permissions/permission-modes.md), line 271). The Host still prompts for recognised `rm`/`rmdir` removals of critical paths such as `rm -rf /` and `rm -rf ~` (same page, lines 277 and 793), but not for deleting the project itself (`rm -rf .`, `rm -rf .git`), and its page lists no prompt for `sudo`, `shutdown` or `az` under that mode (not in the library). The maintainer had decided "Text now, guard later" and "Keep acceptEdits, say so"; this record is the "guard later".

## Decision

1. **One pattern set for every role and the session guard** (option A; AI session). The script text is the same one; the session guard adds its hint to it as before. A stricter opt-in script for some roles (option B) would need a second guard kind with its own file, ownership and doctor state; path scoping (option C) cannot be done from the command string. Both are not done.
2. **What it blocks**, for the Bash and the PowerShell tool alike:
   - a recursive delete (`rm`, `rmdir`, `rd`, `del`, `erase`, `ri`, `Remove-Item`, `rimraf`) **of a dangerous target only**: `/`, `~`, `$HOME`, `$env:USERPROFILE`, `%USERPROFILE%`, `.`, `..`, `*`, `.git`, a drive root, a system folder (the POSIX ones `/bin`, `/boot`, `/dev`, `/etc`, `/home`, `/lib*`, `/opt`, `/root`, `/sbin`, `/usr`, `/var`, and on any drive `\Windows`, `\Users`, `\Program Files`, `\Program Files (x86)`, `\ProgramData`), each with or without a trailing slash or `/*`. Maintainer: recursive deletes "Dangerous targets only"; the list of targets is the orchestrating AI session's, not his. `rm -rf node_modules`, `dist`, `build`, `.next`, `*.log` and `"$DIR"` keep working;
   - privilege escalation: `sudo`, `doas`, `pkexec`, `runas`, `su`, `Start-Process -Verb RunAs`;
   - `shutdown`, `reboot`, `halt`, `poweroff`, `Stop-Computer`, `Restart-Computer`, `init 0|6`, `systemctl poweroff|reboot|halt`;
   - `az group delete`, `gcloud projects delete`, `aws organizations close-account|delete-organization` (the AWS pair was included by the orchestrating AI session as account-level deletion, the class the maintainer's question described);
   - `mkfs`, `wipefs`, `diskpart`, `dd of=/dev/...`, `format X:`, `Format-Volume`, `Clear-Disk`, `Initialize-Disk`, `shred /dev/...`.
3. **Left out, on purpose.** `terraform destroy`, `kubectl delete namespace` and `aws cloudformation delete-stack`: maintainer, "Not now, decide later" (they are ordinary work in test environments). `git reset --hard` and `git clean -fdx`: maintainer, "Leave them out" (the `workflow-implement` Skill tells agents to roll back with `git reset --hard HEAD`). SQL `DROP DATABASE` (named by five canonical agents; AI session): a shell regex cannot see it in a `psql` argument, a file or an MCP tool call (`execute_sql`), so a rule for it would be a false comfort.
4. **Where the new rules match** (AI session). The three old rules keep matching anywhere in the string, so `echo git push --force` is still blocked. The new rules match only where a command starts: at the start, after `;`, `&&`, `||`, `|`, `(`, `$(`, a backtick or a newline, behind the wrappers `env`, `command`, `exec`, `nohup`, `time`, `xargs`, `nice`, `timeout` and variable assignments (one function looks through them and also skips a wrapper's own flags and flag values: `timeout -s KILL 5 sudo x`, `nice -n 10 sudo x`, `env -i bash -c "..."`, `FOO="a b" sudo x` all block; `timeout 60 npm test` passes). The verb loses its path only when the path is absolute or starts with a backslash (`/usr/bin/sudo`, `\rm`, `C:\Windows\System32\shutdown.exe`); a relative path with a separator is the project's own program (`./scripts/su`, `bin/reboot` pass). The new rules read the string after `-c`, `-Command`, `/c` or `eval` when it is quoted, and also when it follows unquoted (`cmd /c rd /s /q .`, `pwsh -c Restart-Computer`), and inside the string that follows `-c`, `-Command`, `/c` or `eval` **when the command is a real shell or evaluator**: `bash`, `sh`, `zsh`, `dash`, `ksh`, `fish`, `pwsh`, `powershell`, `cmd` or `eval` (the wrappers above are looked through, so `xargs sh -c "..."` is read). For any other program that string is data: `grep -c "sudo" file`, `python -c "print('sudo')"` and `rg -c shutdown .` pass. Text inside other quotes is data: `echo rm -rf /`, `git commit -m "sudo fix"` and `grep shutdown app.log` pass. A word that is part of another word or a path (`sudoku`, `./scripts/shutdown-test.sh`, `docs/sudo.md`) passes. Line continuations are folded and `\r` is dropped. An unquoted `#` at the start of a word begins a comment that is not read and does not change quote state (PowerShell block comments `<# ... #>` are not handled). A here-document body is read as commands only when the command it feeds is a real shell or `eval`, or when the line pipes into one (`bash <<'EOF'`, `cat <<EOF | sh`); for every other command (`cat`, `tee`, `git`, `gh`, `node`, `python`) the body is data and is not read at all, so the standard `git commit -m "$(cat <<'EOF' ... EOF)"` and `gh pr create --body "$(cat <<'EOF' ... EOF)"` forms pass whatever their text says. Inside a double-quoted string only an unescaped `$( ... )` (with nested parentheses counted) and an unescaped backtick pair are read as commands; escaped ones (a backslash before the backtick, or before `$(`) are data, and so is everything inside single quotes. A `<<` whose delimiter line is never found is not a here-document: nothing is skipped and the text is read as commands (over-reading is the safe direction), which also covers `$((1 << n))`, a `<<` in a quoted string or in a comment. Here-documents are cut out before backslash-newline folding, so a body line ending in a backslash cannot swallow its terminator. Under the PowerShell tool a backslash is not an escape inside double quotes; under Bash it is. Nesting: a shell inside a shell is read three levels deep; a fourth is not.
5. **The message** keeps its marker sentence and gains one: "Blocked by agents-united guard: <what> requires explicit human approval outside the agent session. If you mean it, run it yourself in your own terminal." (AI session).
6. **Fail closed.** A script error while judging a command blocks it with "a command the guard could not analyse". The new rules work on bounded tokens (a flag over 63 characters and a target over 4,096 are never matched against a pattern), and tests bound them for 100,000-character commands. The three old rules are unchanged and are not linear on adversarial repetition; the Host's hook timeout bounds them, and a timed-out guard blocks (`onFailure: "block"`).
7. **Existing installs** keep the earlier script until `agents update`; the doctor reads it as outdated, and nothing is renewed by force (AI session). The script of the version before is entry `[2]` of `EARLIER_GUARD_SCRIPTS`. The earlier session scripts are now built from that entry and not from the current script, so a session script written by the version before reads as outdated and is renewed (it would otherwise have read as modified, and never been renewed).
8. **Lanes.** The Claude lane and the session guard now; the Cline and Antigravity guard files and texts follow in their own change. Maintainer: "Claude now, others follow".
9. **Role texts.** One sentence in the 15 Claude role files that describe the guard: "A guard blocks forced pushes, `vercel --prod`, `.env` writes and the common forms of destructive shell commands (a recursive delete of a root, home or project folder, privilege escalation, shutdown, disk formatting, cloud resource-group, project or account deletion); it is a seat belt, not a boundary." The old claim "production deploys" is gone: the guard blocks `vercel --prod` and nothing else about deploys.

## Consequences

- **A seat belt, not a security boundary.** The guard sees a command string. It does not see variables and substitution (`X=rm; $X -rf /`), aliases, a verb split by quoting, code run through an interpreter (`node -e`, `python -c`, PowerShell `-EncodedCommand`, base64 into `sh`), a script written with Write or Edit and then run, tools that delete without naming `rm` (`find -delete`, `xargs rm` where the target is not literal, `git rm -r`, `rsync --delete`, `robocopy /MIR`), a target reached by glob or name (`rm -rf src`), or MCP tools. It reduces a model's slip; it does not contain a confused or hostile agent. Under `acceptEdits`, `rm`, `mv` and `sed` inside the working folder are still auto-approved, so for such a role the guard and the role's text rule together are the protection.
- **Not read:** a command handed to another program (`ssh host "sudo x"`, `python -c`, `node -e`, `docker exec ... sh -c`) is not looked into.
- **Recursion test:** an `rm`-family command with any flag that contains an `r` (`-r`, `-rf`, `-R`, `-Recurse`, and also `-Force`) is treated as recursive, and still needs a dangerous target to be blocked, so `rm -Force file` passes.
- **`su`** is blocked in every form as a command; words that merely begin with it (`sum`, `sudoku`, `subl`) pass. `su-exec` is its own verb and passes: it drops privileges to run a command as another user, usually in a container, and is not an escalation.
- **`dd` and `mkfs`:** `dd of=/dev/null`, `zero`, `stdout`, `stderr`, `tty` and `fd/N` pass; any other `of=/dev/...` blocks. `mkfs` on a plain image file blocks too (it cannot tell a file from a device).
- **Known over-blocks:** a here-document fed to a shell, and `echo "$(sudo id)"` (the text is executed by the shell, so this is not an error). A here-document that writes a file is data: `cat > install.sh <<'EOF'` with `sudo` in the body passes, as a call of the Write tool with the same text would.
- **Known misses, kept on purpose:** a pipeline that feeds `Remove-Item` (`Get-ChildItem | Remove-Item -Recurse -Force`), `rm -rf ./.` and `rm -rf .*`, `npx rimraf .`, `iex` and `Invoke-Expression`, a fourth nested shell, a command handed to another program, PowerShell block comments, a target reached through a variable. The orchestrating session chose to list them instead of growing the rules.
- **Shell expansion in a data body:** an unquoted here-document delimiter (`cat <<EOF`) lets the shell expand `$( )` and backticks in the body, which the guard treats as data.
- **Not read, or not targets:** `watch sudo x`, `~/bin/sudo`, `$HOME/bin/reboot`, `node_modules/.bin/rimraf .`, `/c/Users` and `/mnt/c/Windows`, `bash <<< "..."`.
- **PowerShell here-strings:** a here-string whose body holds unbalanced quotes may be read line by line (a possible false block).
- **Size:** the script is about 6 KB. The inline form of a global install embeds it in each role file's hooks block, and a headless run prints the whole command line in front of each refusal (the reason the project scope names a file instead).
- **Lines and sentences that were true and are now narrower:** the here-document line above, the wrappers line, and "linear" are the three claims a review found the first build did not keep; they are fixed in the code and in the text. `sudo apt-get install -y ffmpeg`, offered as a non-recommended option by the `audiovisual-review` Skill, is blocked by design and needs a human; the Skill text can say so in a follow-up.
- Every role that holds a shell or a file writer is stricter at once after `agents update`, including roles that never ran `rm`.
- The factory byte checks (`claude-factory-binding.ts`, `claude-factory-start.ts`, `factory-check.ts`) compare a member's guard to the current `GUARD_SCRIPT`, so they follow the new script and refuse the old one with their existing reasons; a factory member installed before the update fails the start check until it is updated.
- **Follow-ups:** the Cline plugin and the Antigravity hook copy the three old regexes and need the new block (a shared template would keep the lanes from drifting); the strict set (`terraform destroy`, `kubectl delete namespace`, `git reset --hard`, any `rm -r`) and SQL are open; the devops-engineer role (branch `feat/devops-engineer-claude-lane`) must say "seat belt" in its boundaries once both land.
