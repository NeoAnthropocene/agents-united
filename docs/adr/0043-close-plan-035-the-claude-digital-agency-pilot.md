# ADR 0043: Close Plan 035: the Claude digital-agency pilot after the live hardening

- **Status**: Accepted, 2026-10-07 (Plan 035, session N3). The maintainer took the decision on the `experimental` label in chat on 2026-10-07; the rest records what the plan found and what it leaves open. Everything below rests on one account (Claude Pro), one machine (Windows 11), Claude Code 2.1.288 to 2.1.292 and, for most cells, one run.
- **Context**: prior art searched first: ADR 0039 (the full native roster, its seven "not established" items and decision 6, which left the label to the maintainer), ADR 0040 (the skill rewrite policy and quality gate), ADR 0041 (the integration routes and the optional extras), ADR 0042 (the mode-line gate), Plan 032, `docs/live-test-protocol.md`, the observations of 2026-10-04 to 2026-10-07 under `host-library/claude/observations/`, and the plan's decisions D1 to D64 and ledger. Plan 035 asked for skills fit for purpose, a way to prove behaviour in a real host session, and then the label. Its work: 30 agency skills rewritten to the Claude Code skills layout with a ratchet test and an `evals/` folder kept out of installs; a session-report helper that reads the host's own records; a protocol of nine live scenarios (H1 to H9); and, from what the sessions showed, rules in the nine specialists and the lead, the lead's Preflight with three routes to an MCP server (manual, plugin, connector), the narrowed mode counts (six required servers, two optional extras), the launcher fix for the `agents start` kickoff, and the mode-line gate.
- **Decision**:
  1. **Plan 035 is closed.** All nine scenarios were run and read from the records. H1: seen (H1a on the hard case only, with the sentence "Consult ava read-only first."; H1b and H1c seen; one re-read violation was fixed); the regression run of the full roster on the final build (R2) is pending, because the first attempt (R1) stopped at the delegation-map question. H2 and H7: met (the lead on its pinned Opus, a team, a structured shutdown). H3 and H5: pass. H4: the host accepts a blocked task started early, so the roles now refuse it in text; whether a teammate questions an early-start brief was not seen. H6: pass. H8: six of six rewritten skills beat no skill (four at once, two after their evals were fixed with a fixture; one run each). H9: pass after four rounds. The per-scenario evidence and the open items are in the plan's "Close-out checklist".
  2. **The `experimental` label is removed from `digital-agency`, and no status is set** (decision D12). The bundle claims only that it is usable and still being hardened, like the thirty other bundles; README, PROJECT.md, CONTEXT.md, the category text and the CLI heading no longer call it experimental. Draft #137 was folded into the pull request of N3 as a slice of its own. `stable` is a separate decision.
  3. **What is open stays open and is not started here**: the gate's reach (no inline form, so a global install has none; a held call followed by `claude --continue` was not read), the lead's own gaps (six questions at once, no "who supplies each"), H4's fix and a `TaskCompleted` hook (unverified live and not built), the two refusal prompts, the inputs-first rule on the other seven roles, the third eval of each skill, the 39 failing skills outside the bundle, the Cline and Antigravity Tier-2 packages, and the desktop app and the VS Code extension. The plan's checklist lists each with what would close it.
  4. **The findings go to parked Plan 033** (the `agent-factory` bundle) as an addendum: a rule that must hold on the first action needs a hook and a probe of what the hook can see; provisioning is a procedure with routes; proof against a real host has a price; a prompt rule is measured against a control.
  5. **The practice that came out of the plan stays**: a behaviour is read from the host's own records, never from the model's answer; a prose rule that lost to the user turn gets a hook; a fix is built test first and tried on the prompt that failed; parallel pull requests are tested as a combination before they merge.
  6. **The mode-line gate is left as built, with one text change** (ADR 0042 is amended): the duplicate line is accepted, with no `Stop` backstop and no `UserPromptSubmit` reminder (the maintainer, 2026-10-07); and because the host shows the hold to the user as an error line, which was read as a failed spawn in the regression run, the message now says in its first line that the hold is expected and happens once.
- **Consequences**:
  - Positive: the label no longer understates a pilot that was run end to end nine ways; every behaviour the catalog claims for the lead has a record behind it or is listed as open; the live-test kit, the session-report helper and the ledger of what a real run costs (about 3 USD and 13 points of a 5-hour Pro window for a nine-role team, 0.5 to 0.6 USD for an Opus kickoff) are reusable for the other hosts.
  - Limits: "usable" rests on one account, one machine and mostly one run per cell, with Sonnet leads except in H2 and H7. The live runs were all on Windows and CI is Linux. A prose rule can still lose to a user turn wherever there is no hook, and the mode-line gate only holds a call: it does not check what the lead writes, and it cannot be measured headless.
  - To consider before `stable` (the executor's proposal, not decided): close or accept each open defect; one full-roster run on a task other than the H1 brief; a read of the Cline and Antigravity packages; a second machine.
  - Open: whether sessions N4 (the items that were not started) run at all, and whether a JSON `deny` shows the hold more gently than the host's error line (not tried).
