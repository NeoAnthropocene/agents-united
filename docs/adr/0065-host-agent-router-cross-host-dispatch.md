# ADR 0065: Host Agent Router: a user-asked, read-only-by-default dispatch to the user's other Host CLIs

Status: Accepted for the local implementation, 2026-11-07. Offline gates are green; the capped live smoke is recorded in [Plan 049](../../plans/049-host-agent-router.md) and is the only evidence of live behaviour. Numbered 0065 because 0062 to 0064 are reserved by in-flight branches that have not reached `dev`.

## Context

The maintainer asked for a skill that, when run, uses the Hosts in the order Cline, Antigravity, Codex, Claude, runs on the side (Windows or WSL Ubuntu) with the higher remaining 5-hour or weekly limit, and picks a model by task tier. It was first built as a user-global skill and verified on the maintainer's machine; this ADR brings it into the catalog.

Prior art searched on 2026-11-07, and what it showed:

- `src/core/cline-launcher.ts`, `doctor.ts`, `claude-capabilities.ts`, `antigravity-capabilities.ts`: each probes or launches one Host; none routes across Hosts or reads limits.
- ADR 0008 (Cline activation), ADR 0009 (conformance targets) and [ADR 0010](0010-universal-orchestration-bundle-and-domain-atlas.md): 0010 rejected **stay-and-delegate** as the base contract (in-session persona swap and sub-agent masking on projected Hosts), kept "zero runtime network calls", and left auto-launching a session as a deferred spike.
- `registry/skills/` (`subagent-driven-development`, `handoff`, `grill-me`), `plans/` and the translation ledger: nothing runs a task on a different Host CLI.
- Open and closed pull requests for `host-agent-router` and `0065`: none.

Facts observed on 2026-11-06 (Claude Code 2.1.319, Codex 0.167.0, Antigravity `agy` 1.5.2, Cline 3.0.74), each by a command that starts no model:

- Limits can be read locally: `claude -p "/usage"`, `agy -p "/usage" --output-format json`, and Codex's `app-server` method `account/rateLimits/read` (300-minute and 10080-minute windows). Cline Pass exposes no readout.
- Model names: Codex and Antigravity list theirs (`models_cache.json`, `agy models`); Cline's names were read from its bundled Cline Pass catalog. Codex has `gpt-6-astra` and no `gpt-6.1-astra`; the maintainer confirmed the first is meant.
- Claude and Codex reported identical figures on both sides, so each is one account. Cline runs only on Windows (in WSL it resolves to the Windows install and fails `--version`). `agy` exists only in WSL.
- Discovery of a global skill was confirmed by the hosts themselves: Cline (`cline config --json`) and Codex (`codex debug prompt-input`) read `~/.agents/skills`; Antigravity CLI lists it with `/skills`; `claude plugin validate` accepts it.

## Decision

1. **Add the skill `host-agent-router` to `universal-orchestration` and `full`.** No new bundle, no `src/` change: it travels through the existing lanes (the Claude lane, and the `.agents/skills` store that Cline and Antigravity read and that Codex was observed to read). The repository's own `codex` install target is still under development and refuses `--fanout`, so Codex availability here means "reads the canonical store", not an installer-made Codex projection. `orchestrator-universal` lists it and has one new phase that loads it only when the user explicitly asks, and only after naming the Hosts it will use and getting a yes.
2. **It is not the stay-and-delegate that ADR 0010 rejected.** That contract masked a sub-agent or swapped the persona inside one session. This skill starts a **separate headless process of another Host CLI**, with that Host's own model, for one self-contained task, and returns text. Route & Instruct stays the default and unchanged; this is the opt-in layering 0010 allowed "later as an enhancement".
3. **The script makes no network call of its own.** It reads local command output and starts Host CLIs. Network use is the Host's (Codex's app-server asks its account endpoint; `/usage` asks its own). "Zero runtime network calls" in 0010 is preserved for the product's code.
4. **Selection rule.** Hosts in configured priority. For one Host, the side with the larger `min(5-hour, weekly)` remaining; a tie keeps the current side; a floor of 10% skips an exhausted side; unknown headroom is usable but ranks below a known figure. The next candidate runs only after a failure that did no work (limit, login, unknown model, missing binary, timeout); a real task failure is never re-run elsewhere, because the first Host may already have changed files. For an edit run the router also looks: see 9.
5. **Safety.** Read-only by default (`plan`, `read-only`, `plan`, `--plan`); `edit` maps to `acceptEdits`, `workspace-write`, `accept-edits` and Cline's act mode, which is not a sandbox (every tool auto-approved, shell commands included; `-c` only sets the directory); no `--dangerously-*` flag exists in the code. A recursion guard (`HOST_AGENT_ROUTER_DEPTH` and a prompt marker) stops a worker routing again. Prompts go to Claude and Codex on stdin, to Cline after `--`, and Cline starts as `node <entry>`, never through its `.cmd` shim.
6. **Runtime.** One dependency-free Node `.mjs` written for Node 20 or later (the layout gate requires `.mjs`; WSL images often ship Node 20). Crossing between Windows and WSL stages the file and a payload in the Windows temp directory and uses `wsl.exe --exec` (the `--` form passes the line through the outer shell, which expands `$0` and `$@`; found by running it).
7. **Configuration.** The skill ships `assets/config.default.json` with the maintainer's tier-to-model table, and a user file (`~/.agents/host-agent-router/config.json` or `HOST_AGENT_ROUTER_CONFIG`) overrides it key by key. A Host that is missing or logged out is skipped, so a user without Cline Pass degrades cleanly. `router.mjs models` checks names against the Hosts' own lists.
8. **One difference from the hand-installed copy:** it set `disable-model-invocation: true`, which would stop `orchestrator-universal` preloading the skill. The shipped skill instead restricts itself by an explicit-request description, a read-only default and the consent step.
9. **Delegating an edit: the orchestrator plans, briefs and reviews; the router checks the disk.** Added after the maintainer asked for Cline to work as a code-writing subagent, not a read-only one. (a) The lead writes a brief (goal, context, may change, must not touch, requirements, acceptance command; `references/delegation-brief.md`) and gives each editing run its own git worktree. (b) The router tells an editing worker to finish with a handoff report in its reply, in the shape of the `handoff` skill (which ships in every bundle that carries this skill); the instruction is self-contained, so a worker that cannot see the skill still reports. (c) Before the first attempt and after each, the router fingerprints the working directory (path, size, mtime, git HEAD). It returns `changed`, and a failed attempt hands over to the next Host only if the tree is exactly as found; otherwise it stops with `stopped` and starts no other Host, and a directory too large to compare counts as changed. Read-only runs are not fingerprinted. (d) The lead checks the report against `changed`, reads the diff and re-runs the acceptance command itself. (e) Cline runs with `--json` and the router returns its final text and measured token usage, or a short `partial` summary if the run did not finish.
10. **One worker contract for every host, enforced where the host allows (`references/worker-contract.md`).** The maintainer asked that the `handoff` and guardrails skills be essential for the called Hosts and standardised. The contract is the `git-guardrails` rules (no push, no commit, no protected branch, no secrets, stay in the directory) plus the `handoff` report. It travels three ways: (a) the same words in the prompt of every edit run on all four Hosts, naming both skills, so a worker that cannot see them still follows it; (b) both skills ship in every bundle that ships the router (a test holds that; `git-guardrails` was added to `universal-orchestration` and the mock bundle); (c) enforcement with each Host's own controls: a `PreToolUse` hook for Cline in a throwaway `--config` directory with the real `--data-dir` (Cline's act mode has no allow or deny list), `--allowedTools` / `--disallowedTools` for Claude, the sandbox for Codex (edits go to WSL where one exists, because the Windows sandbox lost its working directory and PATH), and exact `command(...)` rules with `--sandbox` for Antigravity. The commands a worker may run are `workerCommands.allow` plus the lead's `--allow-cmd`. A run is judged by what it did, not by its exit code: a guard block, an unfinished Cline run, an Antigravity run with a denied command, and a silent exit-0 run are all not ok (found live: each exited 0).
11. **Timeouts follow the tier, and a bad Cline model id is refused before it starts.** `timeoutSeconds` is per tier (simple 300, medium 900, high 1800 s; `--timeout` overrides; a plain number in a user file still applies to all). A `cline-pass/...` id that the installed Cline's own catalog does not list is refused as `failure: model` and the next Host runs. Both came from one observation: a nonexistent id left Cline silent for five minutes, ignoring its own `-t`.

## Consequences

- The catalog gains a capability that spends the user's other accounts. Consent and the read-only default carry the risk for read-only work. An `edit` run is bounded by the Host: Codex by a sandbox, Claude and Antigravity by their edit permission modes (not tested live here), Cline by nothing but its own behaviour, so editing belongs in a throwaway worktree and the router's `changed` is the independent record.
- The skill count is 218 (205 in `full`). `universal-orchestration` is `stable`; this ADR records that the new skill's live behaviour is evidenced only by the Plan 049 smoke.
- Established live on 2026-11-07 (Plan 049, one trivial read-only run per Host, within the maintainer's 1% ceiling): the simple-tier model strings of all four Hosts are accepted, the prompt reaches each Host by stdin or argv, and the Windows to WSL bridge carries a translated working directory and both prompt forms.
- Cline's quota, checked on 2026-11-07 (docs, `--help`, the installed 3.0.74 code, one low-effort `--plan` run): no CLI command reports ClinePass usage, a model asked for it answers `UNKNOWN`, and the account REST routes were not called (they need the stored token and would be a network call the script does not make). Headroom stays unknown by construction. The same reading showed that `classifyFailure` missed Cline's own refusal wording (`You have reached your … ClinePass limit`, no subscription, organization account); that was fixed test-first and now matches the strings in Cline's source. A hung Cline (a nonexistent model id, once) ended only by the router's timeout is a `timeout` failure: the next Host runs if the tree is unchanged.
- Established live for Cline as an editing worker (Plan 049, 11 sessions, `references/hosts.md`): headless act mode created and changed files correctly under a brief, fixed a bug in a git worktree with the main checkout untouched, added two functions and a test file inside a stated scope and left an out-of-scope README, `package.json` and the old tests alone, made no commit, ran the tests itself, and reported accurately in the handoff shape (without the `handoff` skill in E1 to E3, which it said it could not see; with it in E6). The router's `changed` matched the disk every time, two runs in parallel did not interfere, a timeout killed the whole process tree and left the tree unchanged, and the `glm-5.3` and `kimi-k3.1-pro` strings are accepted. A run costs 150k to 300k input tokens (mostly cache reads), which the flat subscription meters in an unknown unit.
- Established live in the second round (2026-11-07): Cline completed a five-module feature with 17 new tests in 146 s and an ambiguous design task in 60 s, both verified by running the code; the guard cancelled a `git commit` that no prompt rule stood in front of; a kill after some files were written reported `changed` correctly and started no other Host; Claude, Codex (WSL) and Antigravity each completed a one-line bugfix in edit mode, with tests passing on an independent run. Found by doing it: Cline exits 0 when its guard cancels a call; Antigravity exits 0 with an empty result when a command is not allowed, ignores wildcard rules, and ends the whole run on one denial; Codex's Windows sandbox is unusable for editing; a Codex worker misquoted its own test count. Each is handled in the router with a test.
- Not established: how a real limit refusal reaches stdout, stderr and the exit code on any Host (never provoked, by choice: it would mean exhausting a window; the one refusal seen, an unauthorised Cline run, exited 1 with a JSON error line); a large task on Claude, Codex or Antigravity; the medium and high strings of those three; Claude's and Antigravity's denial of a forbidden command inside a router run (their controls were checked directly); Codex editing on Windows; the guard against a creative shell command (it is a token check). Also open: the classifier for limit refusals is a text heuristic checked against sample messages and, for Cline, the wording in its source; the WSL to Windows direction of `run`; Cline's headroom (unknown by construction); the Windows Antigravity desktop app (no command line to probe); the side choice with two different accounts (only unit-tested, since both sides here share accounts); a Windows profile path with spaces under WSL.
- Nothing here changes a Host's login or configuration, and `models` and `status` are read-only.
