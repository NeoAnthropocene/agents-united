# ADR 0041: Claude integration routes and optional extras

- **Status**: Accepted, 2026-10-07 (Plan 035, session N1). The mode counts and the doctor change were the maintainer's decisions; the routes, the allowlists and the search script were decided by the executing session on the conservative default. Every point is reversible and is listed as D53 to D58 in the plan.
- **Context**: prior art searched first: ADR 0039 (the native roster), ADR 0036 (Agent Teams), Plan 029 A3 (the doctor's declared-but-unconfigured warning), Plan 035 D44 to D52 (the H9 provisioning loop), `registry/bundles.json`, `src/core/doctor.ts`, `src/core/prerequisites.ts`, `src/core/claude-projector.ts`, the host docs (`mcp.md`, `plugins-components.md`, `commands.md`) and the session records of 2026-10-05 to 07. Three problems. (1) The lead's mode listed eight integrations, the maintainer decided on six, and the bundle's data and the doctor still treated all eight as required, so the doctor warned and the install gate chose Limited Operational where the lead would report Fully Operational. (2) An integration can reach Claude Code by three routes (`claude mcp add`, `claude plugin install`, a claude.ai connector) under three different tool names, while a role's `tools:` line names one server; the H9 loop needed a restart, and a restart ends the team (a resume restores no teammate). (3) `claude plugin` has no search command.
- **Decision**: (1) **The suite is eight servers, six are required and two are optional extras**, as data: `optional: true` on an entry of a bundle's `requiredMcps`. The lead's text, the doctor (`optionalMcpNames`), the install gate (`allSatisfied`), the panels and the list all follow that one flag. (2) **Three routes.** Manual is the recommended default: pinned commands and the names the roles carry. The plugin route is put in the same install question as the no-restart option (the user types `/reload-plugins --force`; seen to load a plugin's server into a running session). A connector is the user's own act: a directory link, checked afterwards with `claude mcp list` and `ToolSearch`. (3) **The roles name more than one form.** `src/core/claude-mcp-routes.ts` adds the plugin server form for the five integrations whose plugin carries an MCP server (github, playwright, context7, figma, chrome-devtools-mcp, whose server key is `chrome-devtools`) and Firecrawl's CLI connector form; the nine agency roles and the lead take their `tools:` lines from it, the engineering roles are untouched. (4) **The lead searches the two plugin catalogs on disk** with a read-only script (`mcp-setup/scripts/find-plugin.mjs`), because the host offers no search.
- **Consequences**:
  - Positive: the plugin route needs no restart (seen on 2.1.292: two plugin servers loaded into a running session, and the teammates made 27 calls to their tools); the doctor stops warning about extras; the routes, their names and their limits are in one table of the `mcp-setup` reference.
  - Limits: a plugin floats with its own version (the playwright plugin runs `@playwright/mcp@latest`) and its server may ask the user to authenticate (context7, figma); the firecrawl plugin ships skills and no MCP server; a connector connected in the desktop app is named by its directory id (`mcp__<uuid>__`), which no allowlist carries, and no connector name but Firecrawl's was seen in the CLI; the allowlists are longer (the lead holds 47 entries, 33 built-in); `requiredMcps` now lists the prerequisites of a bundle, some of them optional.
  - Not established: the plain `/reload-plugins` in a session with a prompt cache (the host docs say it warns and skips); the desktop app and the VS Code extension (the docs say `/reload-plugins` does not apply plugin MCP server changes in the desktop app); the refined install question, built after the live runs; the github and figma plugins.
  - Open: whether the engineering roles get the same forms; whether the connector names of the other integrations are observed and added.
