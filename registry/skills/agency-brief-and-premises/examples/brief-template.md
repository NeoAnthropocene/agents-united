# Brief templates

Used in the conversation first, and written to one short file only after the client has accepted the brief. A line you cannot fill is an open question with a named owner.

## The first message

```text
CLASSIFICATION  <Quick | Standard | Programme> because <reason>   (you can overrule it)
YOU SAID        <the client's words, close to verbatim>
I ASSUME        <each assumption, labelled>
UNKNOWN         <what nobody has told me>
QUESTION        <one question that would change the plan>, with two to four plain options
```

## The premises (three to five)

```text
| Premise the request depends on | Agree or disagree (the client) | If shaky: the cheapest check, and who runs it |
```

## The approaches (two or three)

```text
| Approach | What the client gets | Specialists | Effort (S, M, L) | Main risk |
| A minimal (the smallest thing that tests the idea) |
| B ideal |
| C lateral (only if another framing exists) |
RECOMMENDATION  <one approach>, because <a reason tied to the client's stated goal>
```

Then stop and wait for the choice.

## The brief

```text
OBJECTIVE      <what changes, by how much, by when>
AUDIENCE       <who>
SUCCESS METRIC <a number and a date>
SCOPE          <in>              OUT OF SCOPE <out>
CONSTRAINTS    <date, budget, channels, approval path>
SOURCES        <where each fact came from: a sentence of the client's, a document page, a file>
NEXT ACTION    <the one thing the client provides or decides this week>
```

Review it with fresh eyes before it goes to the client: no placeholder, no contradiction, no word two people would read differently ("soon", "more traffic", "premium"), no metric without a number and a date, no scope big enough to split.
