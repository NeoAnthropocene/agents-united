# Reuse, authoring and scoped repair

Search the supplied source registry's core directory before inventing a role. Read the actual core and companion and compare identity, mission, scope, output, safety, invariants and capability classes with the requested job. Reuse a compatible pair; lists of permitted affordances are not reasons to add unused Skills or widen a grant.

The companion has exactly these four fields, explicitly including empty lists:

```json
{
  "definition": "subagent-review-notes",
  "workflows": [],
  "skills": [],
  "hooks": []
}
```

The definition is the core filename stem. Affordance ids are unique lowercase semantic identifiers separated by hyphens. A spelling accepted by the schema does not establish an implementation, source licence, loading edge or execution. Host frontmatter, concrete tools, guard kind/registration, recipient consent and invocation do not belong in these four fields.

For create, author the five scalar core fields, invariant list and justified optional capability classes. Use complete statements that change decisions for this job. The helper safely quotes structured values into YAML; it never interprets templates. Run the actual shared validator on the written file, including its body, rather than assuming quoted text is semantically valid.

For exact reuse, validate the original source pair, pin both files and keep line endings, formatting and notes. Do not reserialize a reused contract. Source disposition and required notices still need inspection, even when shared-schema validation succeeds.

For update, agree the semantic change, snapshot every baseline file and retain unrelated notes. `coreText` is the complete already-authored replacement; the helper cannot judge whether a mission change is justified. Historical YAML extensions can survive unchanged, while a new structured core accepts only its documented fields. An applicable shared-floor change needs shared review and later consumer realization; no native file is rewritten here.

Anti-patterns: treating a valid pair as installed support; changing safety text because one Host lacks a primitive; adding native permission fields to the contract; replacing a baseline with only the edited paths; resolving an unknown owner by inventing one. Preserve the draft and hand off the exact missing decision or source evidence.
