# Research, Personas & Measurement

In-house adaptation, credited to
[ui-skills.com/skills/mrstev3n/balise-ux-writing](https://www.ui-skills.com/skills/mrstev3n/balise-ux-writing)
(Apache-2.0 source: `github.com/mrstev3n/balise-skills`).

Read this when a task involves personas, user research, content hypotheses, usability testing, A/B
testing, analytics, or success metrics for interface copy.

## What this skill can and cannot claim
- It can cite **direct evidence** actually provided (a usability test transcript, an analytics
  export, a documented persona).
- It can make a **reasonable inference** from that evidence, clearly labeled as inference.
- It can make a **recommendation**, clearly labeled as a recommendation, not a finding.
- It must never claim usability, accessibility, localization, legal approval, or conversion impact
  without the evidence actually supporting that specific claim — "this copy is clearer" is a
  reasonable design judgment; "this copy increases conversion by 12%" requires an actual test result.

## Working with `ab-test-setup` and `growth-experiment-design`
When a copy change should be validated experimentally, hand the hypothesis to `ab-test-setup` or
`growth-experiment-design` to design the test — this skill proposes the copy variants and the
rationale for each, not the statistical test design.

## Persona use
Use only personas actually documented for the product. If none exist and the task needs one, say so
and either ask for the real audience description or proceed with an explicitly labeled assumption —
never invent a persona and present it as research.
