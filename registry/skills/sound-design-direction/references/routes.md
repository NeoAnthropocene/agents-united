# Choose a production route through Chris

Read existing `media/project.json` first. Its `audioRoute` is local, api or hybrid; selected providers/models, output preset and spend remain unchanged unless Chris records an explicit approved change. Keep the selected visual renderer independent: Native and Remotion accept the same film Sound handoff. Standalone audio selects renderer null; schema-required video preferences remain unused defaults and require no renderer installation or video output.

| Route | Suitable when | Inputs to resolve | Honest limit |
| --- | --- | --- | --- |
| Local supplied/recorded | Client owns VO/music/SFX or a performer can record | Files, consent/release, edit rights, recording space and review time | Editing cannot recover a clipped recording or missing words |
| Local synthesis/editing | Original simple tones, noise, transitions, or an owned sound library meet the brief | Palette, duration, source provenance and finishing tools | Bundled synthesis is not speech or a music-performance generator |
| Optional local model | Covered language/style and available hardware fit a preflighted model | Model/weight licence, downloads/storage, CPU/GPU/runtime compatibility, language and voice test | A model page is not proof it runs on this machine or sounds suitable |
| API | An opted-in provider capability is necessary and uploads are authorized | Provider/model, account route, consent, data handling, per-job ceiling and retries | Network/auth, cost and performance remain unknown until tested |
| Hybrid | Locally recorded speech plus approved generated bed/effects, or other deliberately divided work | Route per asset, permitted upload boundaries, common timebase and provenance | Each asset retains its own source and usage conditions |

Ask Chris for one concrete decision when blocked: "Can the supplied voice recording be used in paid social for this campaign? Evidence is missing; an owned new recording avoids using that source." Chris consolidates the human question. Do not initiate account connection, install a model, upload a source or substitute a cloud provider while waiting. A failed local route leads to a documented option and explicit route approval, never a hidden fallback.

For optional models, the audio-generation Skill contains a dated source-based preflight. Select a project-scoped environment only after hardware, storage, licence, language and usage review. Installation and successful inference are separate evidence from source research. For API/hybrid, use the installed approved provider setup and its capability card; a Skill title alone does not prove configuration, credentials or account access.

Before proposing any of these routes, [probe the machine](../audio-generation/references/system-capability.md): a measured CPU/RAM/disk/GPU report decides whether a local model is `recommended`, `viable-with-caveats` or `not-recommended`. The bundled local route needs no model and stays available on any supported machine. A probe verdict is a fit estimate, not proof that a model runs.

Estimate separately: creative iterations, recording/generation, editing, sync, finishing and review. Include downloads, queue/poll costs and retry ceilings when relevant. A zero external-spend route still needs human review time. Present include/defer/decline for optional ambience, music or premium voice variants so the production scope stays deliberate.
