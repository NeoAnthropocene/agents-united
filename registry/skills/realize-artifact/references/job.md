# Fixed job and enforcement limits

Read the entire caller-supplied record and retain its digest before editing. `assets/job.schema.json` fixes every object field; unknown fields fail. The bundled helpers interpret only that schema's small vocabulary and fail for unsupported keywords. They are installed Node >=24 programs with no external imports or downloads. Run `--help` first. Without a shell, report this required prerequisite unavailable; there is no prose substitute for execution.

The caller prepares the job outside the draft: absolute workspace/source-registry/validation-checkout, actual checkout HEAD, separate draft/evidence, managed/protected destinations, complete create/update scope, constraints, required acceptance/check ids and a zero-spend budget. A private source registry may be outside the validation checkout; each input has its own byte hash. Snapshot every baseline file into evidence before work, retaining its hash/length. The baseline is complete, including unrelated notes. Create starts empty; update matches those bytes at preflight. Postflight compares against those same snapshots, not against a newly captured baseline.

Inputs name a guide and all its cited locked snapshots, relevant observations, profile/tool policy, core/contract, loader, guard/support and the actual built validator/runtime. Cite sections and mark held evidence. Include the host-library lock as a support input. Loading and guard entries are required even for an agent that relies on a baseline safety guard. The supplied guide/library verification and host profile govern applicability; an observation supplements them without silently upgrading their baseline. Caller checks applicable library citation/lock verification before dispatch.

The check allowlist fixes executable, argv, cwd and per-check timeout. Include the exact built CLI native check and the input-pair preflight as named offline checks within six checks/ten minutes total for this worked case. Helpers never execute supplied checks; their only subprocess is a fixed read-only checkout HEAD query. Check/runtime file presence is not execution. A missing required validator blocks acceptance. When the source registry holds the canonical agent `agents/<definition>.md`, the job pins it as a `canonical` input and the native check gets `--canonical <that file>`. A job that lists `<agent path without .md>.coverage.json` in its create or update scope gets `--coverage <draft>/<that file>` on the same check, and a finished draft must contain it.

The digest sorts object keys recursively and preserves array order; it pins content, not identity or filesystem authority. The caller retains its own original job/digest outside the worker's returned text and compares both before accepting anything. An edited job plus matching worker claims cannot authorize a change. The shell/edit grants and existing destructive-command guard do not sandbox source/draft paths; roots, spending and publication limits are guidance plus offline checking, not transport or OS isolation. No new production source guard is claimed.
