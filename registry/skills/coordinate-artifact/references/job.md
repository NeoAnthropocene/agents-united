# Fixed brief and immutable inputs
Read the complete fixed brief before dispatch. Keep original job bytes and caller-held digests independently of worker-returned text. The caller supplies objective, literal fixed values and explicit unknowns; create/update and local/upstream intent; shared pair and target identity; allowed changes; separate authoring/target Host contexts; actual validation checkout HEAD, selected source registry, Node>=24 and built CLI pins; reviewed guides/locked citations/observations/profile/policy/loading/guard evidence; clear provenance/notices and unresolved holds; exact executable/argv/cwd/time/log checks; acceptance/rubric and complete immutable baseline including preservation-only notes.

Require fixed absolute draftRoot/evidenceRoot, disjoint from each other and source/checkout/managed/protected paths. Preserve evidence brief.json and immutable r0/, optional r1/, each with P2 job/baseline snapshots, producer return, separate caller check receipts and P5 review job/result/checks. Review roots obey P5 disjointness. This layout is guidance, not a new filesystem service or sandbox. Do not put coordination-only properties into strict P2/P5 jobs. A missing shared pair returns author-contract/rework rather than invoking it implicitly. Pass every path argument to a checker or to `git` as an absolute path in the platform's own form: on Windows a drive letter, never a `/c/...` form or `$PWD`. Save any helper script you write to assemble a record in the evidence folder and name it in the report. When the source registry holds the canonical agent `agents/<definition>.md`, the P2 job pins it as an input of kind `canonical` and declares `<agent path without .md>.coverage.json` beside the agent among its allowed changes; `check-job.mjs` then expects `--canonical` and `--coverage` in the native check (ADR 0072).

Use intersection candidate limits: <=32 files, <=1MiB total, <=256KiB each; ordinary selected review evidence <=64 files/8MiB/1MiB each; result <=256KiB/32 findings/16 open items; pinned executable <=128MiB. Larger inputs require explicit partition/review, never truncated full-coverage claims. Require the accepted repair count (default zero, maximum one); a journey has no aggregate process, time or output budget. Missing required input blocks only its dependent action; optional gaps stay named.
