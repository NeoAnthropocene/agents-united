# Reviewed ordinary foreground dispatch
For native startup use the installed receipt-driven main selection, not a manifest orchestrator fallback. When manually entering with claude --agent orchestrator-agent-factory, do this before first dispatch. Run the pinned checkout's built CLI, `node <checkout>/dist/cli.js start agent-factory --host claude --dry-run`, never a bare `agents` from the path, and save its output in the evidence folder. The planned agent must be `orchestrator-agent-factory`; anything else, or a nonzero exit, is recorded and the route stops there and reports, without a workaround. The launcher turns agent teams off for the factory's own session and does not refuse a dry run because `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` is set; with direct `claude --agent` entry that switch does not apply, so a worker that starts as a teammate is refused and reported. Direct Host entry bypasses launcher enforcement: this is guidance, not a guaranteed pre-start barrier. Inspect the actual native main/header. Background/worktree entry, an unavailable required closure or the wrong main blocks this journey.

Inspect the reviewed surface/configuration for ordinary foreground non-fork workers. Current fork defaults vary; do not change user settings, invent a per-call fork flag or switch to teams/workflows. Request Agent({subagent_type: "factory-realizer", run_in_background: false, prompt: complete fixed job plus caller-held digest}), with no teammate name or model override. Inspect actual Host return/mechanism and error/partial state; intended arguments alone do not prove ordinary foreground execution. Unsupported/asynchronous/fork/teammate mechanisms remain unavailable.

After actual final-byte checks, call a fresh independent factory-evaluator with complete P5 job and caller-held job/candidate digests using the same foreground/no-name pattern. Assume no inherited conversation history. Worker SubagentHandback is conditional; ordinary final-response data is the fallback. Do not grant workers Task tools or ask the read-only evaluator to run checks, persist records or repair. No team shutdown frames, peer-session discovery, mailbox polling or nested CLI/provider workaround.

For host-update sync, after the sync checker's preflight passes, request Agent({subagent_type: "factory-sync", run_in_background: false, prompt: the absolute sync job path plus the preflight jobDigest, nothing else}) with the same foreground/no-name pattern and the same inspection of the actual return. factory-sync is read-only: it cannot run the sync checker, write the plan or repair it. Save the returned plan unedited in the evidence folder and run the postflight check yourself, as in [host-update sync](host-sync.md).

Only the main owns accepted progress tracking: discover actually available Task tools and reuse returned IDs. Consultation does not authorize assigning a deliverable. Before authorized revision reopen the assigned task or link an owned fix, invalidate dependent acceptance and close after changed-byte readback and applicable rechecks. If Task tools are absent use supplied TodoWrite, otherwise concise briefs/handoffs. Missing tools are not permission for retries, invented IDs, status polling or expanded scope.
