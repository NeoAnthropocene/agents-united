# One Skill draft through a typed fork and a checked return
This route coordinates one Skill draft written by the `author-skill` fork. This coordinator holds no Skill tool and does not start the fork: the maintainer types `/author-skill <absolute task path>`, then the coordinator imports the files the fork wrote and checks them. Nothing is installed, committed, pushed or published, and no check here starts a Host session. Each step below names what enforces it: tool pool, hook, deterministic script or prose. Prose is an instruction, not a barrier.

## Task and return
The task is `skill-task.json` at `<evidence>/skill-task.json`, valid against `assets/skill-task.schema.json`. It carries every `draft.mjs` job field except `changes` as `draftJobTemplate`, because the fork authors `changes`; a repair job saved by the fork also holds a `baseline` object (path to sha256) that the checker derives from the task's top-level `baseline[]`, so the template has none. An upstream task names the contribution template twice: as `draftJobTemplate.contributionTemplate` (a path inside the checkout) and as the top-level `contributionTemplate` pin (path, bytes, sha256); a local task has neither (the top-level field is `null`). The return is `skill-return.json` at `<producer>/skill-return.json`, valid against `assets/skill-return.schema.json`; every field in it is a claim. The fork saves the exact `draft.mjs` job, stdout, stderr and exit code under the producer root, and the return echoes `taskId` and `taskDigest`. A mismatch is reported as `DIGEST_MISMATCH`. `taskDigest` is the sha256 of the task's canonical JSON (keys sorted at every level, no whitespace). The preflight success line prints it, and the fork computes it from the task file, because the invocation text carries only the path.

Place the evidence, producer and draft roots under a path with no managed Host directory segment, never this worktree (`draft.mjs` rejects a `.codex` ancestor). Give the draft folder a dedicated parent that holds nothing else, because `draft.mjs` stages beside it. For a repair, copy every existing file into the evidence root before dispatch and pin it as the baseline.

## Sequence
1. Entry. Run `agents start agent-factory --host claude --dry-run` or start through the launcher. Enforced by script when the launcher starts the session; by prose when `claude --agent` is typed directly.
2. Fix the roots, the baseline for a repair, and the pins, each as path, bytes and sha256: the eight installed `author-skill` files, `dist/cli.js` (it must also be a `requiredTools` entry of the template), the frozen corpus, the checker, and Node (the physical path of the running binary). Record `source.head`, the checkout's HEAD, which the checker reads once with `git rev-parse --verify HEAD`. Prose; the checker verifies the pins in the next step.
3. Write the task, then run `node "${CLAUDE_SKILL_DIR}/scripts/check-skill-return.mjs" --job <absolute task>` (preflight). Read stdout, stderr and the actual exit. A nonzero exit blocks dispatch. Preflight alone checks the state before the run: a create needs an absent draft root, a repair needs the live draft to equal the pinned baseline, and the draft parent must hold nothing else. Deterministic script.
4. Ask the maintainer to type `/author-skill <absolute task path>`. The text after the skill name is the invocation text. Prose plus a maintainer action; the coordinator cannot make this call.
5. Inspect what the Host actually returned: foreground, returned text, no background or teammate. Intended settings prove nothing. Prose.
6. The fork reads the task, authors `changes`, saves the draft job, runs `draft.mjs` once, saves stdout, stderr and exit, writes `skill-return.json` and answers with the paths. `draft.mjs` enforces its own roots, scope, baseline and atomic replace; everything else the fork does is prose.
7. The caller never reruns `draft.mjs`. A create against an existing draft root fails, and a repair against the r0 baseline is stale. Read the files yourself. Prose.
8. Run the same checker with `--job <absolute task> --result <absolute return>` (postflight). It does not repeat the live-state checks of step 3, so step 3 must have passed before the fork ran. The task must be `<evidence>/skill-task.json` and the return exactly `<producer>/skill-return.json`. A nonzero exit or a missing return is rework; only a new authorized revision may run the helper again. A fork that never ran the helper returns `status` blocked with `helper.runs` 0, null helper pins and exit code, and an open item; the draft root must then be exactly as before. Deterministic script.
9. Run `agents skill-check --artifact <draft> --corpus <absolute corpus> --policy <policy>`, with `<policy>` one of `agents-united-original`, `private-owner` or `adapted-source`, the one that matches the task's recorded provenance. Save the command, cwd, stdout, stderr and exit. The checker's `candidate.candidateDigest` (absent for a blocked return, where `candidate` is null) must equal the digest of `skill-check`. Deterministic script; writing the receipt is prose.
10. Build the P5 `skill` review job from the task's objective, fixed values, acceptance and roles, with step 9 as its checks, then run `check-review.mjs --job`. Deterministic script.
11. Call `factory-evaluator` in the foreground with no name and the complete job. Save its result, run `check-review.mjs --job --result`, inspect cited lines and coverage, and rehash the candidate. The evaluator's read-only pool and hook are native; the record check is a script; usefulness is judgment.
12. Repair only if the accepted brief already authorized one. Create a new `r1` evidence directory, snapshot the current candidate including the user's notes, and write a new task whose `previous` records the r0 task id and digest, the r0 return sha256 and the r0 review result sha256 (null if that review did not run), with narrowed `allowedPaths` and a new baseline. The maintainer types the path again; repeat steps 3 to 11. r0 acceptance is invalid. Prose for the count and authorization and for the `previous` values, which the checker records but does not verify; script for the revision pairing (r0 has no `previous`, r1 has one) and the baseline.
13. Deliver the candidate with evidence, or precise rework. Local intent stops. Upstream intent only prepares the pinned `.github/PULL_REQUEST_TEMPLATE/artifact-contribution.md`, base `dev`, `sent: false`, following the checkout's `docs/artifact-contribution.md`; no commit, push, pull request or publication follows. A human continues from [contribution](contribution.md).

## Checker output
Success is one JSON line on stdout and exit 0: `phase`, `taskDigest`, `baselineDigest` (null for a create), `pins`, and after a postflight `result`, `helper`, `candidate` and `claimsNotAccepted`. It always carries `quality: pending`, `executionProof: unverified`, `live: unverified` and `acceptedDraft: false`, so a pass is consistency of bytes and records, not acceptance. Failure is one JSON line on stderr and exit 1: `status` (`failed` for a contradiction, `unavailable` for a missing, oversized or drifting input), `phase`, a stable `code`, `reason` and `path`. Only the first failure is reported. Match on `code`, not on `reason`. `--help` alone prints usage on stdout and checks nothing; duplicate or unknown flags, positionals and relative paths are `USAGE`. Codes: `USAGE`, `JOB_INVALID`, `TEMPLATE_INVALID`, `ROOT_CONFLICT`, `CLOSURE_MISSING`, `LOADER_MECHANISM`, `RUNTIME_MISMATCH`, `BASELINE_MISMATCH`, `CHECKOUT_HEAD`, `LIMIT`, `STALE_INPUT`; after a return `RESULT_PATH`, `RESULT_INVALID`, `DIGEST_MISMATCH`, `HELPER_RECORD`, `DRAFT_JOB_MISMATCH`, `SCOPE_VIOLATION`, `PRESERVATION`, `BYTES_MISMATCH`, `INVENTORY_MISMATCH`, `DIFF_MISMATCH`, `PROVENANCE_MISMATCH`, `EXTERNAL_ACTION`, `BLOCKED_STATE`.

## Budgets
Every checker run, `skill-check` run and rerun counts toward the aggregate in [repair](repair.md): at most 24 processes, 1800 seconds and 8MiB of raw output. At most one repair.

## What stays unproven
The checker compares final bytes with the baseline, the saved job and the return. It cannot show who ran `draft.mjs`, that it ran exactly once, that nothing outside the draft and producer roots was written, or that the fork followed any prose rule. The `raw` pins inside `claimedChecks` are not resolved, hashed or checked to exist. Provenance truth, licence effect, usefulness and loading are not proved by `skill-check` or the evaluator either. Unverified in a live session: that the Host passes the typed path to the fork as the invocation text, that the fork is foreground, which tools the fork holds, whether this coordinator's hook applies to it, and that the evaluator's judgment of a Skill is useful and independent. No Skill-tool route, pointer file or argument field is part of this route.
