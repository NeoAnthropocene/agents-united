# One Skill draft through a typed fork and a checked return
This route coordinates one Skill draft written by the `author-skill` fork. This coordinator holds no Skill tool and does not start the fork: the maintainer types `/author-skill <absolute task path>`, then the coordinator imports the files the fork wrote and checks them. Nothing is installed, committed, pushed or published, and no check here starts a Host session. Each step below names what enforces it: tool pool, hook, deterministic script or prose. Prose is an instruction, not a barrier.

## Task and return
The task is `skill-task.json` at `<evidence>/skill-task.json`, valid against `assets/skill-task.schema.json`. Its `draftJobTemplate.allowedPaths` and its `roles` must include `evals/evals.json` with the role `support` (the file `skill-check` requires under `agents-united-original` and `private-owner`, and that postflight refuses to miss with `EVALS_MISSING`; the fork writes it as `references/quality.md` of `author-skill` describes). The task pins the `skill-check` policy as `skillCheckPolicy`: `agents-united-original` or `private-owner`. A task offers no other policy: `adapted-source` is not in the schema, and preflight refuses it with `JOB_INVALID` and a message saying it is for `agents skill-check` run by hand. A task without the field is refused with `JOB_INVALID`, and step 9 runs `skill-check` with that policy. It carries every `draft.mjs` job field except `changes` as `draftJobTemplate`, because the fork authors `changes`; a repair job saved by the fork also holds a `baseline` object (path to sha256) that the checker derives from the task's top-level `baseline[]`, so the template has none. An upstream task names the contribution template twice: as `draftJobTemplate.contributionTemplate` (a path inside the checkout) and as the top-level `contributionTemplate` pin (path, bytes, sha256); a local task has neither (the top-level field is `null`). The return is `skill-return.json` at `<producer>/skill-return.json`, valid against `assets/skill-return.schema.json`; every field in it is a claim. The fork saves the exact `draft.mjs` job, stdout, stderr and exit code under the producer root, and the return echoes `taskId` and `taskDigest`. A mismatch is reported as `DIGEST_MISMATCH`. `taskDigest` is the sha256 of the task's canonical JSON (keys sorted at every level, no whitespace). The preflight success line prints it, and the fork computes it from the task file, because the invocation text carries only the path.

Place the evidence, producer and draft roots under a path with no managed Host directory segment, never this worktree (`draft.mjs` rejects a `.codex` ancestor). Give the draft folder a dedicated parent that holds nothing else, because `draft.mjs` stages beside it. For a repair, copy every existing file into the evidence root before dispatch and pin it as the baseline. Pass every path argument to a checker or to `git` as an absolute path in the platform's own form: on Windows a drive letter, never a `/c/...` form or `$PWD`. Save any helper script you write to assemble a record in the evidence folder and name it in the report.

## Sequence
1. Entry. The session is started through the launcher or with `claude --agent`. Run the pinned checkout's built CLI, `node <checkout>/dist/cli.js start agent-factory --host claude --dry-run`, from the workspace root (the folder the session was started in, which holds the installed bundle; not a subfolder), never a bare `agents` from the path, and save its output in the evidence folder. The planned agent must be `orchestrator-agent-factory`; anything else, or a nonzero exit, is recorded and the route stops there and reports, without a workaround. The launcher turns agent teams off for the factory's own session and does not refuse a dry run because `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` is set; with direct `claude --agent` entry that switch does not apply, so a worker that starts as a teammate is refused and reported. Enforced by script when the launcher starts the session; by prose when `claude --agent` is typed directly.
2. Fix the roots, the baseline for a repair, and the pins, each as path, bytes and sha256: the nine installed `author-skill` files, `dist/cli.js` (it must also be a `requiredTools` entry of the template), the frozen corpus, the checker, and Node (the physical path of the running binary). Record `source.head`, the checkout's HEAD, which the checker reads once with `git rev-parse --verify HEAD`. Prose; the checker verifies the pins in the next step. The task's `roots` holds exactly `draft`, `producer`, `evidence`, `managed` and `protected`: copy no other key of the brief's `roots` into it (the schema refuses `workspace`).
3. Write the task, then run `node "${CLAUDE_SKILL_DIR}/scripts/check-skill-return.mjs" --job <absolute task>` (preflight). Read stdout, stderr and the actual exit. A nonzero exit blocks dispatch. Preflight alone checks the state before the run: a create needs an absent draft root, a repair needs the live draft to equal the pinned baseline, and the draft parent must hold nothing else. Deterministic script.
4. Ask the maintainer to type `/author-skill <absolute task path>`. The text after the skill name is the invocation text. Prose plus a maintainer action; the coordinator cannot make this call.
5. Inspect what the Host actually returned: foreground, returned text, no background or teammate. Intended settings prove nothing. Prose.
6. The fork reads the task, authors `changes`, saves the draft job, runs `draft.mjs` once, saves stdout, stderr and exit, runs `skill-return.mjs` once to write `skill-return.json` (never by hand) and answers with the paths. `draft.mjs` enforces its own roots, scope, baseline and atomic replace; everything else the fork does is prose.
7. The caller never reruns `draft.mjs` or `skill-return.mjs`. A create against an existing draft root fails, and a repair against the r0 baseline is stale. Read the files yourself. Prose.
8. Run the same checker with `--job <absolute task> --result <absolute return>` (postflight). It does not repeat the live-state checks of step 3, so step 3 must have passed before the fork ran. The task must be `<evidence>/skill-task.json` and the return exactly `<producer>/skill-return.json`. A nonzero exit or a missing return is rework; only a new authorized revision may run the helper again. A fork that never ran the helper returns `status` blocked with `helper.runs` 0, null helper pins and exit code, and an open item; the draft root must then be exactly as before. Deterministic script.
9. Before this check, write the review spec without its checks and take the candidate digest with the installed `evaluate-artifact/scripts/review-job.mjs --digest --spec <absolute spec>`; step 10 records it with the check. Run `node <checkout>/dist/cli.js skill-check --artifact <absolute draft> --corpus <absolute corpus> --policy <policy>`, with `<policy>` the task's `skillCheckPolicy` (`agents-united-original` or `private-owner`; `skill-check` itself also accepts `adapted-source`, which is for a hand run only). Save the command, cwd, stdout, stderr and exit. The checker's `candidate.candidateDigest` (absent for a blocked return, where `candidate` is null) must equal the digest of `skill-check`. Deterministic script; writing the receipt is prose.
10. Build the P5 `skill` review job with the installed `evaluate-artifact/scripts/review-job.mjs --spec <absolute spec>`: the spec holds the task's objective, fixed values, acceptance and roles, step 9 as its checks (each with the candidate digest taken before it ran, its exit code and saved output) and the task file as `provenance` evidence; never assemble or edit the job by hand. Then run `check-review.mjs --job`. Deterministic script.
11. Call `factory-evaluator` with no name and the complete job. Start it as an ordinary subagent and, when it runs in the background, wait for its hand-back as the waiting rule in [dispatch](dispatch.md) says. Save its result unedited as `<review root>/result.json` (beside `job.json`), run `check-review.mjs --job --result`, inspect cited lines and coverage, and rehash the candidate. The evaluator's read-only pool and hook are native; the record check is a script; usefulness is judgment. When `check-review.mjs --job --result` refuses a review result, never edit the result. You may start ONE fresh evaluator for the same review job, with the checker's reason quoted in the prompt, if the journey's one additional evaluator turn is still unused (it counts as that turn of the worker-turn limit, so no evaluator turn is then left for a repair's review); that is a new evaluator turn, not a repair of the candidate, and needs no other authorization. First move the refused result to `result.refused.json` beside it; if that name already exists, stop and report instead of overwriting; only then save the fresh evaluator's result unedited as `result.json`, and report both. A second refusal is reported, not retried.
12. Repair only if the accepted brief already authorized one. Create a new `r1` evidence directory, snapshot the current candidate including the user's notes, and write a new task whose `previous` records the r0 task id and digest, the r0 return sha256 and the r0 review result sha256 (null if that review did not run), with narrowed `allowedPaths` and a new baseline. The maintainer types the path again; repeat steps 3 to 11. r0 acceptance is invalid. Prose for the count and authorization and for the `previous` values, which the checker records but does not verify; script for the revision pairing (r0 has no `previous`, r1 has one) and the baseline.
13. Deliver the candidate with evidence, or precise rework. Local intent stops. Upstream intent only prepares the pinned `.github/PULL_REQUEST_TEMPLATE/artifact-contribution.md`, base `dev`, `sent: false`, following the checkout's `docs/artifact-contribution.md`; no commit, push, pull request or publication follows. A human continues from [contribution](contribution.md).

## Checker output
Success is one JSON line on stdout and exit 0: `phase`, `taskDigest`, `baselineDigest` (null for a create), `pins`, and after a postflight `result`, `helper`, `candidate` and `claimsNotAccepted`. It always carries `quality: pending`, `executionProof: unverified`, `live: unverified` and `acceptedDraft: false`, so a pass is consistency of bytes and records, not acceptance. Failure is one JSON line on stderr and exit 1: `status` (`failed` for a contradiction, `unavailable` for a missing, oversized or drifting input), `phase`, a stable `code`, `reason` and `path`. Only the first failure is reported. Match on `code`, not on `reason`. `--help` alone prints usage on stdout and checks nothing; duplicate or unknown flags, positionals and relative paths are `USAGE`. Codes: `USAGE`, `JOB_INVALID`, `TEMPLATE_INVALID`, `ROOT_CONFLICT`, `CLOSURE_MISSING`, `LOADER_MECHANISM`, `RUNTIME_MISMATCH`, `BASELINE_MISMATCH`, `CHECKOUT_HEAD`, `LIMIT`, `STALE_INPUT`; after a return `RESULT_PATH`, `RESULT_INVALID`, `DIGEST_MISMATCH`, `HELPER_RECORD`, `DRAFT_JOB_MISMATCH`, `SCOPE_VIOLATION`, `PRESERVATION`, `BYTES_MISMATCH`, `EVALS_MISSING`, `INVENTORY_MISMATCH`, `DIFF_MISMATCH`, `PROVENANCE_MISMATCH`, `EXTERNAL_ACTION`, `BLOCKED_STATE`.

## Budgets
A journey has no aggregate process, time or output budget; see [repair](repair.md). At most one repair.

## What stays unproven
The checker compares final bytes with the baseline, the saved job and the return. It cannot show who ran `draft.mjs`, that it ran exactly once, that nothing outside the draft and producer roots was written, or that the fork followed any prose rule. The `raw` pins inside `claimedChecks` are not resolved, hashed or checked to exist. Provenance truth, licence effect, usefulness and loading are not proved by `skill-check` or the evaluator either. Unverified in a live session: that the Host passes the typed path to the fork as the invocation text, that the fork is foreground, which tools the fork holds, whether this coordinator's hook applies to it, and that the evaluator's judgment of a Skill is useful and independent. No Skill-tool route, pointer file or argument field is part of this route.
