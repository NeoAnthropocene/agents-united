Verify actual final bytes against caller-held digests and baselines. Before dispatch run the pinned built `node <checkout>/dist/cli.js factory-check --registry <absolute> --definition <stem> --host claude` for the supplied pair and installed realize-artifact/scripts/check-job.mjs --job <absolute>. Read full output and actual exit; absence/nonzero required checks block dispatch. A target must already fit the current P2 adapter; scoped-delegate main-role candidates are unavailable through generic factory-check. This coordinator's own delivery is a separate binding/launcher contract. Pass every path argument to a checker or to `git` as an absolute path in the platform's own form: on Windows a drive letter, never a `/c/...` form or `$PWD`. Save any helper script you write to assemble a record in the evidence folder and name it in the report.

After realization independently list/read/hash candidate, support and preservation-only files, compare original pins/baseline and actual complete diff, then run installed check-handback.mjs --job <absolute> --result <absolute>. Execute the trusted pinned final-byte validators, including `node <checkout>/dist/cli.js factory-check --artifact <absolute> --loading <declared> --required-skills <JSON>` as applicable. Worker command/exit strings are claims, not caller execution receipts.

Require independent review at the current candidate digest. Build the existing P5 claude-agent job with unchanged objective/fixed values/acceptance, complete subject/support/preservation inventory, actual check evidence, provenance/notices and reviewed source/installed pins. Build it with the installed evaluate-artifact/scripts/review-job.mjs --spec <absolute> from your own decisions alone (its spec keys are in that Skill's references/job.md); it computes every pin, writes the receipts and the copies described next and runs no check, and the evaluator never runs it. Take the candidate digest with its --digest mode before each check runs: the builder refuses a check whose digest differs from the candidate's. Pin every saved check output the evaluator is told to read (raw log and receipt) as an input in `inputs[]` with all eight fields of `assets/job.schema.json`: `id` (lowercase kebab-case, for example `native-check-raw`), `kind` `validator`, `path`, `bytes`, `sha256`, `sections` (`[]`), `status` `clear` and `required` (`true`). Keep that copy byte-identical in a folder of its own that is a sibling of the review root, never its parent or the review root itself, declare that folder alone in `roots.read` (a read root that contains the review root is refused) and keep the originals in `checks[]`. A citation names only `candidate` or the id of an input the job pins as clear; anything else you want to mention, including a saved check output the job does not pin, goes into prose, never into a citation. Run evaluate-artifact/scripts/check-review.mjs --job <absolute> before dispatch. After the fresh evaluator returns, save its data unedited as `<review root>/result.json` (beside `job.json`) and run that checker with --result <absolute>. Rehash input/candidate bytes, inspect actual cited lines/coverage/findings and complete logs. Missing/stale/partial/contradictory/blocked records return rework. Never widen P5 beyond shared-pair, skill and claude-agent or substitute producer self-review.

Retain who executed QA and which revision it reviewed. A structurally valid no-blocking opinion is neither human acceptance nor installability/live proof. Hashes establish byte identity, not authentication or legal clearance. Guards and a final filesystem recheck are not an atomic snapshot or source-root sandbox.
