# One shared definition-and-contract draft through a typed fork and a checked return
This route coordinates one shared definition-and-contract draft written by the `author-contract` fork. This coordinator holds no Skill tool and does not start the fork: the maintainer types `/author-contract <absolute task path>`, then the coordinator imports the files the fork wrote and checks them. Nothing is installed, committed, pushed or published, and no check here starts a Host session. Each step below names what enforces it: tool pool, hook, deterministic script or prose. Prose is an instruction, not a barrier.

## Task and return
The task is `contract-task.json` at `<evidence>/contract-task.json`, valid against `assets/contract-task.schema.json`. It selects `operation` (`create`, `reuse` or `update`) and `intent` (`local` or `upstream`), fixes `definition` (`core/<definition>.core.md` and `core/<definition>.contract.json`), and carries `draftJobTemplate` (with `mode` equal to `operation`). For `create` and `update`, `draftJobTemplate` omits `proposal` because the fork authors it (`core`, `body` and `contract` for `create`; `coreText` and/or `contract` within `allowedPaths` for `update`); for `reuse`, `draftJobTemplate.proposal` pre-fills `coreFile` and `contractFile` pins from `source.registry`. A repair is an `r1` `update` revision, at most one; `create` and `reuse` have empty `baseline[]` and `draftJobTemplate.baseline[]`, while `update` carries the full baseline in both (each `draftJobTemplate.baseline` entry holds `{ path, sha256 }` as `snapshot`). An upstream task names `.github/PULL_REQUEST_TEMPLATE/artifact-contribution.md` inside the checkout twice: as `draftJobTemplate.contributionTemplate` (path, sha256) and as the top-level `contributionTemplate` pin (path, bytes, sha256); a local task omits the template field and sets the top-level field to `null`. The return is `contract-return.json` at `<producer>/contract-return.json`, valid against `assets/contract-return.schema.json`; every field in it is a claim. The fork saves the exact `draft-pair.mjs` job (`helper.draftJob`), `helper.stdout`, `helper.stderr` and `helper.exitCode` (plus optional `report`) under the producer root, and the return echoes `taskId` and `taskDigest`. A mismatch is reported as `DIGEST_MISMATCH`. `taskDigest` is the sha256 of the task's canonical JSON (keys sorted at every level, no whitespace). The preflight success line prints it, and the fork computes it from the task file, because the invocation text carries only the path.

Place the evidence, producer and draft roots under a path with no managed Host directory segment (`.agents`, `.claude`, `.cline`, `.cursor`, `.codex`, `.opencode`, `.gemini`), disjoint from each other and from the source checkout, source registry, managed and protected roots (`draft-pair.mjs` also rejects a `.codex` ancestor). Give the draft folder a dedicated parent that holds nothing else, because `draft-pair.mjs` stages beside it. For an `update` or `r1` repair, copy every existing file into the evidence root before dispatch and pin it in `baseline[]` and `draftJobTemplate.baseline[]`. Pass every path argument to a checker or to `git` as an absolute path in the platform's own form: on Windows a drive letter, never a `/c/...` form or `$PWD`. Save any helper script you write to assemble a record in the evidence folder and name it in the report.

## Sequence
1. Entry. The session is started through the launcher or with `claude --agent`. Run the pinned checkout's built CLI, `node <checkout>/dist/cli.js start agent-factory --host claude --dry-run`, never a bare `agents` from the path, and save its output in the evidence folder. The planned agent must be `orchestrator-agent-factory`; anything else, or a nonzero exit, is recorded and the route stops there and reports, without a workaround. The launcher turns agent teams off for the factory's own session and does not refuse a dry run because `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` is set; with direct `claude --agent` entry that switch does not apply, so a worker that starts as a teammate is refused and reported. Enforced by script when the launcher starts the session; by prose when `claude --agent` is typed directly.
2. Fix the roots, the baseline for an `update`, and the pins, each as path, bytes and sha256: the eighteen installed `author-contract` files in `installed[]` (also mirrored as `{ path, sha256 }` in `draftJobTemplate.loading.entry`, `attribution`, `binding` and `requiredFiles`), `runtime.validator` at `<checkout>/dist/cli.js` (also in `draftJobTemplate.validator.cli`), `runtime.checker` (this installed `check-contract-return.mjs`), and `runtime.executable` (the physical path of the running Node >=24 binary, also in `draftJobTemplate.validator.runtime`). Record `source.head`, the checkout's HEAD, which the checker reads once with `git -C <checkout> rev-parse --verify HEAD`. Prose; the checker verifies the pins in the next step.
3. Write the task, then run `node "${CLAUDE_SKILL_DIR}/scripts/check-contract-return.mjs" --job <absolute task>` (preflight). Read stdout, stderr and the actual exit. A nonzero exit blocks dispatch. Preflight alone checks the state before the run: `create` and `reuse` need an absent draft root, `update` needs the live draft to equal the pinned baseline, and the draft parent must hold nothing else. Deterministic script.
4. Ask the maintainer to type `/author-contract <absolute task path>`. The text after the skill name is the invocation text. Prose plus a maintainer action; the coordinator cannot make this call.
5. Inspect what the Host actually returned: foreground, returned text, no background or teammate. Intended settings prove nothing. Prose.
6. The fork reads the task, authors `proposal` (or keeps the pinned `reuse` `proposal`), saves the complete `draft-pair.mjs` job, runs `draft-pair.mjs` once, saves stdout, stderr and exit code, writes `contract-return.json` and answers with the paths. `draft-pair.mjs` enforces its own roots, scope, baseline, protected notes and atomic replace; everything else the fork does is prose.
7. The caller never reruns `draft-pair.mjs`. A `create` or `reuse` against an existing draft root fails, and an `update` against the pre-run baseline is stale. Read the files yourself. Prose.
8. Run the same checker with `--job <absolute task> --result <absolute return>` (postflight). It does not repeat the live-state checks of step 3, so step 3 must have passed before the fork ran. The task must be `<evidence>/contract-task.json` and the return exactly `<producer>/contract-return.json`. A nonzero exit or a missing return is rework; only a new authorized revision may run the helper again. A fork that never ran the helper returns `status` `blocked` with `helper.runs` 0, null `draftJob`, `stdout`, `stderr` and `exitCode`, and a named `openItems` entry; the draft root must then be exactly as before and `changed` empty. Deterministic script.
9. Run `node <checkout>/dist/cli.js contract-check --registry <draft root> --definition <definition>` (and before a `reuse` task, also against `<source.registry>`). Save the command, cwd, stdout, stderr and exit. `contract-check` prints JSON with `valid`, `files`, `findings`, `delivery: "unverified"`, `quality: "pending"` and `live: "unverified"`, exiting 0 when `valid` is true and 1 when `valid` is false. Deterministic script; writing the receipt is prose.
10. Build the P5 `shared-pair` review job from the task's objective, fixed values, acceptance and roles, with `target` null and step 9 as its checks, then run `check-review.mjs --job <absolute review job>`. Deterministic script.
11. Call `factory-evaluator` in the foreground with no name and the complete job. Save its result, run `check-review.mjs --job <absolute review job> --result <absolute review result>`, inspect cited lines and coverage, and rehash the candidate. The evaluator's read-only pool and hook are native; the record check is a script; usefulness is judgment.
12. Repair only if the accepted brief already authorized one (at most one). Create a new `r1` evidence and producer directory, snapshot the current candidate including preserved notes, and write an `r1` task with `operation: "update"` whose `previous` records `taskId`, `taskDigest`, `returnSha256` and `reviewResultSha256` (null if that review did not run), with narrowed `allowedPaths` and the new baseline. The maintainer types the path again; repeat steps 3 to 11. r0 acceptance is invalid. Prose for the count and authorization and for the `previous` values, which the checker records but does not verify; script for the revision pairing (`r0` has `previous: null`, `r1` requires `previous` and `operation: "update"`) and the baseline.
13. Deliver the candidate with evidence, or precise rework. Local intent stops. Upstream intent only prepares the pinned `.github/PULL_REQUEST_TEMPLATE/artifact-contribution.md`, base `dev`, `sent: false`, following the checkout's `docs/artifact-contribution.md`; no commit, push, pull request or publication follows. A human continues from [contribution](contribution.md).

## Checker output
Success is one JSON line on stdout and exit 0: `version`, `kind`, `phase`, `recordValid`, `task`, `taskId`, `revision`, `operation`, `intent`, `definition`, `pairPaths`, `taskDigest`, `baselineDigest` (null for `create` and `reuse`), `pins`, and after a postflight `result`, `helper`, `candidate`, `claimsNotAccepted` (`["inventory", "changed", "claimedChecks"]`) and `producerIdentity: "unauthenticated"`. It always carries `quality: "pending"`, `executionProof: "unverified"`, `live: "unverified"` and `acceptedDraft: false`, so a pass is consistency of bytes and records, not acceptance. Failure is one JSON line on stderr and exit 1: `status` (`failed` for a contradiction, `unavailable` for a missing, oversized or drifting input), `phase`, a stable `code`, `reason` and `path`. Only the first failure is reported. Match on `code`, not on `reason`. `--help` alone prints usage on stdout and checks nothing; duplicate or unknown flags, positionals and relative paths are `USAGE`. Codes: `USAGE`, `JOB_INVALID`, `TEMPLATE_INVALID`, `ROOT_CONFLICT`, `CLOSURE_MISSING`, `LOADER_MECHANISM`, `RUNTIME_MISMATCH`, `BASELINE_MISMATCH`, `CHECKOUT_HEAD`, `LIMIT`, `STALE_INPUT`; after a return `RESULT_PATH`, `RESULT_INVALID`, `DIGEST_MISMATCH`, `HELPER_RECORD`, `DRAFT_JOB_MISMATCH`, `SCOPE_VIOLATION`, `PRESERVATION`, `BYTES_MISMATCH`, `INVENTORY_MISMATCH`, `DIFF_MISMATCH`, `PROVENANCE_MISMATCH`, `EXTERNAL_ACTION`, `BLOCKED_STATE`.

## Budgets
Every checker run, `contract-check` run and rerun counts toward the aggregate in [repair](repair.md): at most 24 processes, 1800 seconds and 8MiB of raw output; each draft job stays within `maxChecks: 6`, `maxSeconds: 600`, `maxLogBytes: 262144`, `maxFiles: 32`, `maxFileBytes: 262144` and `maxTotalBytes: 1048576`, with zero Host/model/provider calls, prompts and USD. At most one repair.

## What stays unproven
The checker compares final bytes with the baseline, the saved job and the return. It cannot show who ran `draft-pair.mjs` (`producerIdentity` stays `unauthenticated`), that it ran exactly once, that nothing outside the draft and producer roots was written, or that the fork followed any prose rule. The `raw` pins inside `claimedChecks` are not resolved, hashed or checked to exist, and no command in a task, return or candidate is executed. Provenance truth, licence sufficiency, optional binding availability, semantic usefulness and live loading are not proved by `contract-check` or the evaluator either. Unverified in a live session: that the Host passes the typed path to the fork as the invocation text, that the fork runs in the foreground, which tools the fork holds, whether this coordinator's hook applies to it, and that the evaluator's judgment of a `shared-pair` is useful and independent. No Skill-tool route, pointer file or argument field is part of this route.
