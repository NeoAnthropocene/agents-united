# Prerequisites and leader responsibility

The manifest's `prerequisites` uses `requiredMcps` entries with `name` and optional `purpose`, `optional` and `optionalForBrainstorming`; `requiredPackages` and `requiredEnvVars` are required string lists. `optionalForBrainstorming` is mode-specific, not the same as `optional`. Do not invent optional package/env objects. Per-task dependency, provider, authorization, evidence and reload details belong in the leader brief and `bindings.json`.

For every Organization leader, even if the list is empty: inspect the actual task and available tools; identify required and optional integrations and dependent actions; reuse existing human authorization for the same scope and obtain only missing authorization before changes. Keep credentials out of prompts, configuration reads and logs. The human enters secrets and authorizes sign-in. Verify actual availability in the lead's session using the reviewed target surface's route. A required unavailable integration blocks its dependent action; an optional unavailable integration may allow clearly disclosed degraded work. Static/mock output is not integration output. A configured or detected entry, stored authorization, elapsed time or a catalog record does not prove current tool availability or authorize paid invocation.

For Claude, consult the exact pinned `mcp-setup/references/claude-code.md` and target Host guide before proposing commands. The observed manual CLI route needs a fresh session; the plugin route needs the user to type the reviewed reload and a subsequent ToolSearch; connector setup is the user's action with selected connection status and ToolSearch evidence. Keep user-reported status distinct from observed tool results. CLI, Desktop and VS Code are distinct surfaces; do not generalize observed mechanics. Do not read credential-bearing MCP configuration or environment values. Held Claude MCP and VS Code source candidates and the Antigravity web changelog remain quarantined; no source hold is cleared by this task.

For a proposed Claude leader, discover the actual task-tool pool and reviewed role grants. Track accepted multistep work with actual returned IDs and truthful dependencies; only assign an owner when execution is authorized, not for consultation alone. Complete after evidence/readback. Before an authorized revision reopen the assigned task or link an owned fix, invalidate affected acceptance and recheck; a worker unable to update relays the real ID and requested status. If Task tools are unavailable, use TodoWrite only when actually available, otherwise briefs and handoffs. Ordinary background workers, in-process and split-pane teammates can have different pools. These instructions grant no tools, add no other-Host API and prove no live adherence. A reviewed operation-mode gate precedes TaskCreate.
