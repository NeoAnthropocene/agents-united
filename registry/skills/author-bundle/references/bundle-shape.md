# Bundle shape and delivery boundaries

Use the existing `BundlesManifest` envelope (`version`, `bundles` keyed by name) and `BundleDefinition` fields from the pinned validation checkout. Replace template placeholders; a parseable template is not an installable manifest. Do not add secret values, native tool names or invented prerequisite fields. The existing resolver validates selected invariants and rule sources, not complete native delivery or actual runtime availability.

Domain uses `tier: domain`, explicit domain/status and any applicable essentials/addon relationship. A leader follows the reviewed planner-orchestrator posture and Planning Aid Boundary; do not copy Tier-2 consultation caps. Identify applicable prerequisites even when none exist. Organization uses `tier: organization`, a cross-functional roster and leader, and the reviewed subagent-first posture/budget where selected. Its leader brief always records provisioning responsibility, even when the present list is empty.

Every proposed Bundle declares `host-agent-router`, `handoff` and `git-guardrails` exactly once. They are available under declared ownership; do not preload the router or imply permission to use another Host. Cross-Host execution requires the user's explicit request, the named proposed Hosts and an account-spending explanation; retain consent already given for that same scope. Live non-invocation without a request remains unverified.

Record each source, installed location, loading tuple, registration, ownership, enforcement, dependency and evidence edge in `bindings.json`, including unavailable edges. This is a proposal record, not a consumed installer schema. A new proposed subagent needs its own `core/<stem>.core.md` and `<stem>.contract.json`, authored or reused via the separate author-contract task, with exactly definition, workflows, skills and hooks. Native output requires a separately reviewed target realization. No template invents a shipped Workflow, hook, native binding or companion contract.

For a Tier-2 leader, preserve the accurate opening Operation Mode and independently reviewed target-native mode gate; elapsed time is not authorization. Cross-session contact requires human authorization, not mere discovery. Team shutdown policy applies only to a leader with an actual team lifecycle. Do not grant the authoring fork a new role, sandbox or first-action guarantee.
