# Cline CLI 3.0.68: the pilot bundle in real interactive sessions (2026-10-03)

**These are observations of one installed build, not documentation.** The guides in `../guide/` cite the vendor's docs snapshots; where this file disagrees with a guide, the guide's authoring notes say so. Nothing here is a vendor promise, and it may change in any release. Re-run the checks when the version changes.

- **Build:** Cline CLI `3.0.68`, interactive TUI (`cline -i`).
- **Account and model:** provider `cline-pass` (ClinePass), model `cline-pass/glm-5.3-flash` in every session. On 2026-10-02 the same machine was refused on ClinePass for lack of a subscription, so the account state changed since; the model is a small, fast one, which matters for the weaknesses below.
- **Install:** `agents add software-engineering -t cline --native -y` with the CLI built from branch `chore/plan-032-close-out`, into fresh scratch git projects outside the repository (`D:\AI\scratch-pilot\cline`, later `cline3`). `cline config` listed the four configured agents (`backend-architect`, `code-reviewer`, `frontend-architect`, `repo-index`), the `agents-united-guard` plugin, nine workflows (three of them native) and the skills (78 to 81, with the maintainer's global ones).
- **How the sessions ran:** the maintainer typed in the TUI from a checklist (the harness cannot send keystrokes into a TUI). What follows was read from the session records under `~/.cline/data/sessions/` (messages, tool calls, per-message token metrics), not from the model's account, except where marked. Cline does not record a price.

## What was established

- **Delegation and a small real task (S1).** The lead called `subagent_backend_architect`. The specialist wrote `index.test.js` first, the run was red (an import `SyntaxError`, "does not provide an export named slugify": a weaker red than a failed assertion), then implemented and went green (6 of 6). The lead re-read both files and re-ran the suite itself. No `code-reviewer` call was made.
- **The guard plugin blocks (S1).** `Run this exact command: echo git push --force` came back `Blocked by agents-united guard: git push --force requires explicit human approval outside the agent session.` and the run ended with that error, as the plugin is designed to (a block ends the run). Cline's own hook log recorded the calls.
- **A native Cline workflow is expanded by the host (S2, S3).** With no skill of the same name in the way, typing `/workflow-test` put the native workflow file into the conversation as the user message (the session's first message starts `<!-- managed-by: agents-united | profile: cline-native | canonical: skills/workflow-test/SKILL.md`), the lead ran the suites itself with `run_commands`, and closed with `Verdict: Green` and no delegation, as the workflow says for a green run. So the Cline TUI does expand `.cline/workflows/<name>.md` as `/<name>`.
- **A same-named skill wins over a workflow (S1).** With both installed, the first action after `/workflow-test` was a `skills` tool call and the text the lead received was the generic registry skill ("Systematic workflow for running unit, integration, and e2e test suites…", a Mermaid flowchart, "Phase 1: Context & Reconnaissance"), not the native workflow. This matches the Cline docs (every enabled skill is a `/<name>` command).
- **Listing without a model call.** `cline config agents|workflows|skills|plugins` list what is installed: the four agents, the guard plugin, nine workflows. After the fix the three skills `workflow-implement`, `workflow-review` and `workflow-test` are absent from `cline config skills`.

## Defects found, and what became of them

1. **Doctor reported "Installed Agents: 0" and "Configured Agents: 0 active natively in any Cline session"** on a healthy `--native` install, because the count read only the store's agent list and the native lanes replace those copies. Found while preparing S1, before any model call. Fixed, test first (`tests/native-doctor-agent-count.test.ts`), commit `a6921fa`.
2. **A Cline-only `--native` install wrote the Antigravity native lane into `.agents/`** (agents, rules, guard hook, `hooks.json`, `mcp_config.json`): the store is only there for Cline, and the install flag covered "every host in the store". Found while preparing S1. Fixed with defect 3.
3. **The native workflows were unreachable by their names** (S1, above). Fixed, test first (`tests/native-cline-store-gate.test.ts`), commit `5d12a0f`, ADR 0034: the installer records whether Antigravity is a target (`implicitStore`); an implicit store gets no Antigravity lane and leaves the three skills out; with Antigravity as a target they stay and doctor warns. Re-tested in S2 (skill removed by hand) and S3 (standard install made by the fixed CLI, nothing removed by hand).

## Model weaknesses seen (not package defects)

The model is small. It answered the roster question muddled (said two agents were configured, then corrected itself to four), declined to delegate a file write to the read-only reviewer and wrote the file itself with `run_commands` (the rule allows a trivial non-code action), and in S1 wrote a coverage line ("brief & detection & acceptance-rule sync checks all green … SKIP_NET=1") that appears nowhere in the workflow text. The Windows PowerShell execution policy blocks `npm.ps1`, so the model switched to `npm.cmd` each time; an environment trait, not a package one.

- **`/workflow-review` and `/workflow-implement` by slash command**, fix rounds, the `medium` and `large` sizes, and a red `/workflow-test` run (only the green path was run).
- **Whether the three skill copies still written under `.agents/plugins/<bundle>/skills/` could shadow.** They did not in S2 and S3 (the native workflow answered), which is one observation per build.
