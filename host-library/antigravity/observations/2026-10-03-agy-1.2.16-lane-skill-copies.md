# Antigravity CLI (`agy`) 1.2.16: skills installed by the native lane (2026-10-03)

**One observation of one installed build on one machine, not documentation. Read "Not established" before relying on it.** Environment: Windows, `agy` 1.2.16, headless `-p`, default settings, the maintainer's own sign-in, a scratch git project outside the repository.

Ledger: 1 headless session (the maintainer allowed one), run on Windows. With the earlier 31 headless sessions and the 2 accidental calls that makes 32 headless sessions plus the 2 accidental calls; quota use was not measured; ceiling 10 USD.

## What was run

Setup, with the CLI built from the branch that adds ADR 0033: `agents add software-engineering --native -y` into a scratch project (the default method, so the lane's own rule decides how skills are installed). `.agents/skills/` held 36 folders, none of them a link. A second scratch project with `--native --copy` was installed too (no model call) and its `.agents/skills/` tree was identical to the first, so the plain `--native` run stands for the `--native --copy` one.

One session, no tool allowed: IN or OUT for six names against the skills list in context, and a total. Three of the names (`backend-api-design`, `database-design`, `code-refactoring`) are project skills that are not global ones, and were OUT when installed as junctions (probe (b) of `2026-10-03-agy-1.2.16-probes.md`); `workflow-implement` and `test-driven-development` are in the bundle, and `brainstorming` is a global skill.

## Result

All six names were reported IN, and the total was `COUNT=83`. The exit status was 0 and the run took about 24 s.

What it shows: **the skills the lane installs as real copies are listed by agy 1.2.16 on Windows**, including the three that were not listed when the same skills were junctions. The cause of the earlier absence is therefore the link, and the lane's copy removes it.
