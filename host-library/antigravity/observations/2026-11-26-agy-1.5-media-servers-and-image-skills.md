# Antigravity CLI (`agy`) 1.5: the hosted media servers and the image skills of ADR 0079 (2026-11-24 and 2026-11-26)

**These are observations of one installed build, not documentation.** The guides in `../guide/` cite the vendor's docs snapshots; where this file disagrees with a guide, the guide's authoring notes say so. Nothing here is a vendor promise, and it may change with the next build.

[ADR 0079](../../../docs/adr/0079-media-servers-in-the-base-roles-and-the-image-tool-shared-with-marketing.md) wires the four hosted media servers (Higgsfield, Kling, ElevenLabs, Fish Audio) on Antigravity and gives the agency and marketing leads an Antigravity-only image paragraph. This file records three runs, each with who sat it. No image was generated in any of them, and no provider was charged.

## Run 1: OAuth sign-in to the four hosted servers (2026-11-24)

- **Who sat it:** the maintainer, by hand, in an interactive `agy` 1.5.16 session on Windows, on his own Antigravity account.
- **Setup:** a new throwaway git folder outside the repository, trusted at agy's prompt, whose `.agents/mcp_config.json` named the four servers as `serverUrl` entries under the names `au-test-higgsfield`, `au-test-klingai`, `au-test-elevenlabs` and `au-test-fish-audio`.
- **Seen in `/mcp`:**
  - `au-test-fish-audio` and `au-test-klingai` offered a sign-in, which he completed: both showed `[Authed]`, with 62 and 18 tools.
  - `au-test-elevenlabs` first showed `error: calling "initialize": sending "initialize": Unauthorized [Auth Needed]`, and connected after a reload.
  - `au-test-higgsfield` showed `error: calling "initialize": sending "initialize": Not Found` at `https://mcp.higgsfield.ai`, and connected at `https://mcp.higgsfield.ai/mcp`.
- **Probes without sign-in, by the coordinating Claude session (not a person):** an MCP `initialize` POST to `https://mcp.higgsfield.ai` answered 404 and to `https://mcp.higgsfield.ai/mcp` answered 401; Higgsfield's `/.well-known/oauth-protected-resource` names `"resource":"https://mcp.higgsfield.ai/mcp"`. ElevenLabs answered 401 with a `www-authenticate` header pointing at its protected-resource metadata, whose resource is `https://api.elevenlabs.io/v1/mcp`. These probes led to the `/mcp` address fix in the repository.
- **Not established:** why ElevenLabs needed a reload before it offered a sign-in.

## Run 2: starting the digital-agency lead (2026-11-26)

- **Who sat it:** the maintainer, by hand, in an interactive `agy` session.
- **Install:** `agents add digital-agency --native -y` from origin/dev `24dcc77c`, into a new trusted git folder. Before the session the coordinating session checked that `.agents/mcp_config.json` held the four hosted servers as bare `serverUrl` entries (Higgsfield at the `/mcp` address), that `.agents/agents/orchestrator-digital-agency.md` held the Antigravity paragraph with no host-section marker, and that `agents doctor` reported the install healthy.
- **Seen:** `/agents` listed only `● default  Default agent`; `orchestrator-digital-agency` was not offered. The run stopped there.
- **Reading (the maintainer's):** the digital-agency Bundle has no Antigravity native agent files yet (only the engineering roles do, under `registry/hosts/antigravity/agents/`), and that work comes after the Claude projections are confirmed. `agy --agent orchestrator-digital-agency` was not tried in this run. An earlier observation started a native lead with `agy --agent orchestrator-engineering` ([2026-10-04](2026-10-04-agy-1.2.16-pilot.md)).
- **Also seen while preparing:** an install of the same Bundle without `--native` wrote no `.agents/mcp_config.json`, and its 72 skills were links that the installer warns agy does not list. Only the `--native` install wires the servers.

## Run 3: the image skills, headless (2026-11-26)

- **Who sat it:** nobody typed. The coordinating Claude session started one read-only headless `agy` run through the `host-agent-router` skill (`--pin-host antigravity --pin-side windows`, tier medium), which ran `gemini-pro-orchestrator-neon` (fixed configuration) in the Run 2 folder. `agy --version` read 1.5.18 just after the run.
- **Brief:** list the image and `mcp-setup` skills; name the image tools and subagents in the session's own tool list without calling them; load `image-creation` for "a photograph of a barista pouring latte art in a sunlit cafe, nobody supplied a photo, give the options first, generate nothing"; quote the skill sentence that ordered the options; list the MCP servers.
- **What the session reported (its own words, not checked further):**
  - `image-creation`, `image-generation` and `mcp-setup` were loaded and their `SKILL.md` files were readable (the `--native` install copies skills as real folders).
  - No built-in tool named `generate_image`; one subagent named `image-generator`. This agrees with a separate headless session on 2026-11-24 (Gemini 4 Hydrogen Low), which reported the same in a folder with no Bundle installed.
  - The four hosted servers were visible, with image tools among their lazy tools: `generate_image` on `higgsfield` and on `fish-audio`, `creative_generate_image` on `elevenlabs`, `text_to_image` and `image_to_image` on `klingai`.
  - Following `image-creation`, it offered the four rungs of the skill's ladder (supplied or owned, licensed stock, the `image-gen` MCP server with the user's key, a placeholder with an image brief) and recommended licensed stock. It did not offer Antigravity's own `image-generator` subagent, and it did not offer the hosted servers' image tools, saying the skill restricts generation to the `image-gen` route.
  - The sentence it cited: "A photograph reaches a design by one of four rungs. Take them in order and stop at the first that works." (`image-creation/references/ladder.md`).

## What this establishes, and what it does not

- **Established (Run 1, by the maintainer):** OAuth sign-in to all four hosted servers works in interactive agy 1.5.16 through workspace `serverUrl` entries; Higgsfield needs the `/mcp` address.
- **Established (Run 2, by the maintainer):** on this install `/agents` does not list the digital-agency lead. Starting it with `agy --agent orchestrator-digital-agency` was not tried, so whether ADR 0079's Antigravity image paragraph can be reached on this install is not established.
- **Reported, not verified (by two headless sessions: the one of 2026-11-24, outside the numbered runs, and Run 3):** the main agy session has no `generate_image` tool and reaches image generation through the `image-generator` subagent.
- **Gap found (Run 3):** the `image-creation` skill does not follow the order the maintainer chose for Antigravity on 2026-11-24 (Antigravity's own image generation first and recommended). A session that uses the skill directly gets the ladder written for Claude. The host-section marker of ADR 0079 decision 11 covers canonical agent bodies only, not skills.
- **Not shown:** a session in which an agency lead or the marketing lead runs on Antigravity; any image generation, by any route; a sign-in to Higgsfield from Claude Code.
