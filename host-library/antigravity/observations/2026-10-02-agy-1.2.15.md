# Antigravity CLI (`agy`) 1.2.14 / 1.2.15 — observed behaviour (2026-10-02)

**These are observations of installed builds, not documentation.** The guides in `../guide/` cite the vendor's docs snapshots; where this file disagrees with a guide, the guide's authoring notes say so. Nothing here is a vendor promise, and it may change in any release. Re-run the checks when the CLI version changes. Earlier probes on 1.2.13 and 1.2.14 (agent discovery, `hooks:` hiding an agent, `invoke_subagent` by name) are recorded in `plans/031-antigravity-agent-discovery-spike.md`.

- **Builds on this machine:** Windows `agy` reported `1.2.14` at the start of the session and `1.2.15` later (it updates itself); the WSL Ubuntu `agy` first printed `1.0.11` and, a few hours later, `1.2.15` ("You are already on the latest version" when the maintainer allowed `agy update`), so no update was run and the first reading is unexplained (most likely a self-update in between; the earlier note that a Linux run needs `agy update` first was wrong). The docs library baseline is CLI 1.2.11.
- **Free commands:** `agy --version`, `agy --help`, `agy changelog` and `agy [--add-dir <dir>] agents` produce no model call. `agy changelog` ran ahead of the docs snapshot (it listed 1.2.15).
- **`-p "/usage"` is not free.** The 1.2.15 release notes say `-p "/usage"` shows quota, but on the two builds tried the text was sent to the model: the WSL build (1.0.11) answered in prose that `/usage` is a TUI command, and the Windows build ran the model and reported a denied `command` permission ("jetski: no output produced, a tool required the command permission that headless mode cannot prompt for"). Two minimal model calls were made by mistake; their quota use was not measured. Do not use it to read quota headroom.

## The native agents, listed by the real CLI (no model call)

The five files of `registry/hosts/antigravity/agents/` were copied into `<workspace>/.agents/agents/` of a scratch git project, and `agy --add-dir <workspace> agents` (Windows, 1.2.15) was compared with a plain `agy agents` from a neutral directory:

- **Added by the workspace: `orchestrator-engineering` only.** It has `mainAgent: true`, a `tools:` list of tool names from the hooks page, and no `hooks:` key, and it is discovered.
- **The four specialists were not listed.** Each has `mainAgent: false`, and plan 031 already found that the listing is the set selectable as a primary agent; whether `invoke_subagent` reaches them by name from this layout was **not** re-tested here (it needs a model call).
- **A global set already exists.** `~/.gemini/config/agents/` on this machine holds agents named `backend-architect`, `code-reviewer`, `frontend-architect`, `repo-index` and others from an earlier install, and the baseline listing already shows `backend-architect` and `repo-index`. Which of a global and a workspace agent of the same name `invoke_subagent` reaches is **unknown**; a native install must not assume the workspace copy wins.
- **Linux gives the same listing.** The same check in WSL Ubuntu (agy 1.2.15, the files copied into a scratch git workspace on the Linux filesystem) added `orchestrator-engineering` only to the listing, the four `mainAgent: false` specialists again absent. The WSL home holds the same global agent names as the Windows one.

## The legacy rules, and what the native rules change (2026-10-02)

The legacy lane installs the registry rules into `.agents/rules/` byte for byte (checked by installing `software-engineering` into a scratch project with the built CLI: `git-guardrails.md`, `test-driven-development.md` and four more, plus `GEMINI.md`, none with frontmatter). The docs say a file in `.agents/rules/` without a valid `trigger:` is silently discarded. The native rules (`registry/hosts/antigravity/rules/`) are the same text behind a valid trigger. Whether the installed build really discards the legacy ones is answered by the first real session below.

## Real sessions (2026-10-02, agy 1.2.15, Windows, headless `-p`, default permissions)

Scratch git workspaces; the account is the maintainer's own `agy` sign-in, and the maintainer set a ceiling of 10 USD. `agy` runs on a plan quota and prints no per-call price, so the ledger counts sessions, not dollars: **6 headless sessions** for these probes (one of them spawning subagents), after **2 accidental calls** earlier (`-p "/usage"`). Quota use was not measured.

1. **Rules, legacy.** The legacy install (`.agents/rules/*.md` and `GEMINI.md`, no frontmatter) and the question "without any tool, list the first heading of every persistent rule in your context whose title starts with `Persistent Rule:`": the answer was `NONE`. **The legacy frontmatter-less rules are silently dropped, as the docs say.**
2. **Rules, native.** Only the six native rules in `.agents/rules/`: the answer listed exactly the two `always_on` rules (Git Guardrails, Test-Driven Development). The four `model_decision` rules did not appear, consistent with their reaching the agent as pointers.
3. **Delegation by name.** `agy --agent orchestrator-engineering -p` with the five native agent files in `.agents/agents/`, told to call `invoke_subagent` once with `TypeName "code-reviewer"`: the transcript shows the call with `Prompt`, `Role`, `TypeName` and `Workspace` (`inherit`), a created subagent, and a subagent answer that is the native code-reviewer's own "Boundaries of this host" first bullet verbatim. So **by-name delegation works from this layout, and the workspace agent won over the same-named agents in the global `~/.gemini/config/agents`** (observed once). In headless print mode the parent ended its turn ("Awaiting its response") before the answer arrived; the subagent's answer is in its own transcript under `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/transcript.jsonl`.
4. **Enforcement, probe.** A scratch agent with `tools: [view_file, list_dir, grep_search]`, asked to create `probe-out.txt`: it said no writing tool was available, and **no file was created**.
5. **Enforcement, control.** The same task for an agent whose list added `write_to_file`: it created the file (`PROBE`). **A `tools:` list is enforced by the host (the writing tool is withheld), on this build.**
6. **Several specs in one call.** The orchestrator, told to delegate in ONE `invoke_subagent` call with two specs (`code-reviewer`, `repo-index`): both subagents were created in the same second and both answered `OK`. Whether their runs overlap in time is **not proven** (the tasks were too short).

Not exercised: the guard hooks file (no hook was installed), the sandbox (Windows has the older system), the 2.0 and IDE surfaces, a Linux session, and whether the orchestrator follows its full text on a real task.

## Hooks, in real sessions (2026-10-02, agy 1.2.15, Windows, headless `-p`, default permissions)

A logging probe hook in a scratch workspace (`.agents/hooks.json` with a `PreToolUse` command hook on `run_command` and the file writers), answering according to a mode file; **8 more headless sessions** (14 in total on this build, plus the 2 accidental calls; quota use unmeasured, the maintainer ceiling is 10 USD). One attempt that used `--dangerously-skip-permissions` was refused by the harness before it ran and was not retried or worked around: no probe needed it.

- **`{}` (no `decision`) blocks the call.** A command the permissions would only ask about was denied with `tool call denied by pre-tool hook:` and an empty reason. The hook ran with the working directory `.agents/` (the folder holding `hooks.json`), and its payload keys were `artifactDirectoryPath`, `conversationId`, `modelName`, `stepIdx`, `toolCall`, `transcriptPath`, `workspacePaths`.
- **`ask` falls back to the user settings.** For a command, the result was the usual headless auto-denial (a `command` permission cannot be prompted for); for a workspace file write, the write went through.
- **`deny` carries its reason.** A hook answering `deny` with a reason for a command containing `FORBIDDEN` returned `tool call denied by pre-tool hook: Blocked by probe guard: FORBIDDEN is not allowed.` to the agent.
- **A subagent is covered.** The orchestrator delegated a command to `backend-architect`; the hook logged it under the subagent conversation id, denied it, and the denial text came back through the parent.
- **Failures block.** A hook that exited 1 gave `JSON hook ... failed: command failed: exit status 1, stderr: ...`, and one that printed non-JSON gave `failed to unmarshal result from hook ... via protojson`; in both the command did not run.
- **The shipped guard** (`registry/hosts/antigravity/hooks/`, installed by hand as `.agents/hooks.json` and `.agents/hooks/agents-united-guard.js`, command `node hooks/agents-united-guard.js`): `echo git push --force` and a `.env.test` write through `write_to_file` were denied with the guard message and no `.env.test` was created, while `ok.txt` was written normally.

Not exercised: macOS and Linux, a hook timeout, the 2.0 and IDE surfaces.
