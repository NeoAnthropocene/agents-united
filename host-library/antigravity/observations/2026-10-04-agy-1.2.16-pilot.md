**These are observations of one installed build, not documentation.** The guides in `../guide/` cite the vendor's docs snapshots; where this file disagrees with a guide, the guide's authoring notes say so. Nothing here is a vendor promise, and it may change in any release. Re-run the checks when the version changes.

- **Build:** `agy` 1.2.16, Windows, interactive TUI (`agy --agent orchestrator-engineering --model gemini-3.8-flash-medium`).
- **Account:** the maintainer's own Antigravity sign-in, on its plan quota. `agy` prints no price and shows no quota in these sessions, so cost is **not measured**.
- **Model:** Gemini 3.8 Flash (Medium), recorded by the session itself (`Model Selection` changed from none to that name).
- **Install:** `agents add software-engineering --native -y` (the default target, the `.agents/` library) with the CLI built from branch `chore/plan-032-close-out`, into a fresh scratch git project outside the repository (`D:\AI\scratch-pilot\agy`). Result: five native agents, six native rules, the guard hook in `.agents/hooks/` registered in `.agents/hooks.json`, `.agents/mcp_config.json` holding only `chrome-devtools-mcp` and `context7` (the four credentialed servers were printed, not written), 36 skills as real copies (none linked), no `GEMINI.md`. `agents doctor`: healthy, five agents. `agy --add-dir <workspace> agents` listed `orchestrator-engineering`.
- **How the session ran:** the maintainer typed in the TUI from a checklist; the harness cannot send keystrokes into a TUI. What follows was read from agy's own transcripts under `~/.gemini/antigravity-cli/brain/<conversation>/.system_generated/logs/` (steps, tool calls, errors, per-step token counts), not from the model's account, except where marked.

## What was established

- **By-name delegation reaches the right specialist.** For the small task the lead read the TDD skill, ran `git status`, and made one `invoke_subagent` call (`TypeName: backend-architect`, `Role: Backend Specialist`, `Model: inherit`); agy's subagent record for the new conversation says `typeName: backend-architect`. The specialist read the skill and `package.json`, wrote `index.test.js` first, ran it (exit 1: `SyntaxError`, `slugify` is not exported, a red from a missing export rather than a failed assertion), wrote the implementation, ran it green, ran `npm test`, and handed back with `send_message` to the lead's conversation. The lead then re-ran `node --test` and `git status` itself. No `code-reviewer` call was made.
- **The workspace specialist, not the global one, answered (inferred).** The maintainer's `~/.gemini/config/agents/` holds a global `backend-architect` in another format (`slug` / `roleDefinition`, a YAML file whose text has no "Backend Architect Report" heading). The subagent's report used that heading, which the native file carries, and every tool it called is in the native `tools:` list. That is consistent with the workspace file winning and is not a direct read of which file loaded.
- **The guard hook denies at the host, with the guard's own message (twice).** `Run this exact command: echo git push --force` and `echo x > .env.test` each reached a `run_command` call and came back `tool call denied by pre-tool hook: Blocked by agents-united guard: git push --force requires explicit human approval outside the agent session.` and `...: a .env write requires ...`. No `.env.test` exists. The lead had read `hooks.json` and the git-guardrails rule first, then ran the command anyway, so the denial is the hook's and not the model's.
- **The native rules reach the agent, once each, with the legacy entrypoint omitted.** Asked for the always-on rules, the lead listed `git-guardrails` and `test-driven-development` once each, plus a rule of the maintainer's own (`user_global`) and the orchestrator's directives; the policy did not arrive twice (the lane leaves `GEMINI.md` out). One observation, from the model's answer.
- **The roster question.** The lead named the four specialists and sorted them into two read-only (`code-reviewer`, `repo-index`) and two that edit and run commands, matching the files.
- **`/workflow-test` works on the generic skill copy.** The lead read `package.json`, ran `npm test` and `node --test --experimental-test-coverage`, and re-read the two files. Antigravity has no native workflow here, so this is the registry skill as installed.
- **MCP.** Asked for names only, the lead listed seven servers: the maintainer's global ones plus `chrome-devtools-mcp` and `context7` from the workspace file. No value was printed or read.
