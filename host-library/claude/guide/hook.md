# Claude Code — authoring guide: hooks

Distilled from the snapshots in `host-library/claude/pages/`. Primary source: [hooks](../pages/hook/hooks.md). Supporting sources: [sub-agents](../pages/agent/sub-agents.md), [plugins-components](../pages/plugin/plugins-components.md), [permissions](../pages/permissions/permissions.md), [tools-reference](../pages/tools/tools-reference.md).

Native output lands in `registry/hosts/claude/hooks/` as real scripts plus the JSON that registers them (agent or skill frontmatter, plugin `hooks/hooks.json`, or `settings.json`). Hooks are what turns a prose guard such as "deny run_command if ..." into an enforced one; a guard that only exists in an agent's prose is not a guard.

## Rules

### Shape: event, matcher group, handler

- **Three levels of nesting: event, matcher group, handler.** `hooks.<Event>[]` holds `{ "matcher": ..., "hooks": [ { "type": ..., ... } ] }`. All matching handlers run in parallel; an identical handler defined in several settings files runs once. [Configuration](../pages/hook/hooks.md#configuration), [Hook handler fields](../pages/hook/hooks.md#hook-handler-fields)
- **Five handler types**: `command` (shell or exec), `http`, `mcp_tool`, `prompt` (single-turn model call) and `agent` (a subagent that can use tools; experimental). Prefer `command` for anything that must be deterministic. [Hook handler fields](../pages/hook/hooks.md#hook-handler-fields)
- **Matchers: `*`, `""` or omitted match all; letters, digits, `_`, `-`, spaces, `,` and `|` are an exact list; anything else is an unanchored JavaScript regex.** `Edit.*` matches `NotebookEdit`; write `^Edit$` for a whole-string match. A `matcher` on an event without matcher support is silently ignored. [Matcher patterns](../pages/hook/hooks.md#matcher-patterns)
- **Each event matches a different field**: tool name for `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `PermissionDenied`; agent type for `SubagentStart` and `SubagentStop`; start reason for `SessionStart`; none for `UserPromptSubmit`, `Stop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted` and others. [Matcher patterns](../pages/hook/hooks.md#matcher-patterns)
- **Match MCP tools as `mcp__<server>__.*`; the `.*` is required** (a bare `mcp__memory` is an exact string and matches nothing). Tools of a plugin-bundled server are `mcp__plugin_<plugin>_<server>__<tool>`, so a matcher on the bare server key never fires. [Match MCP tools](../pages/hook/hooks.md#match-mcp-tools)
- **`if` narrows a handler with one permission-rule string and only runs on tool events** (`PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `PermissionDenied`); on any other event a handler with `if` never runs. There is no `&&` or list syntax, so write one handler per condition. The filter is best effort for Bash, so use permission rules for a hard allow or deny. [Common fields](../pages/hook/hooks.md#common-fields), [Bash if matching](../pages/hook/hooks.md#bash-if-matching)
- **Match `Bash|PowerShell` in any hook that inspects shell commands.** On Windows without Git Bash the Bash tool is not registered, so a hook matching only `Bash` never fires there. [PowerShell](../pages/hook/hooks.md#powershell), [PowerShell tool](../pages/tools/tools-reference.md#powershell-tool)

### Blocking and decisions

- **Exit 2 is the only exit code that blocks through the code alone.** Exit 1 is a non-blocking error and the action proceeds, even though 1 is the conventional Unix failure. Exit 0 with no output means no decision (the normal permission flow applies; staying silent does not approve). [Exit code output](../pages/hook/hooks.md#exit-code-output), [Other exit codes](../pages/hook/hooks.md#other-exit-codes)
- **A gate that cannot start fails open.** When the script path does not exist or is not executable the shell exits 127 and, for most events, the action proceeds with a non-blocking notice. Test the hook's first run, use `chmod +x` on macOS and Linux, and reference scripts through `${CLAUDE_PROJECT_DIR}` or `${CLAUDE_PLUGIN_ROOT}`. [Other exit codes](../pages/hook/hooks.md#other-exit-codes), [Reference scripts by path](../pages/hook/hooks.md#reference-scripts-by-path)
- **A timed-out `command`, `http` or `mcp_tool` hook does not block a `PreToolUse` call**; the call continues through the permission flow. Do not count on a stalled hook as a gate, and set `timeout` deliberately (default 600 s for command hooks). [Timeouts](../pages/hook/hooks.md#timeouts), [Common fields](../pages/hook/hooks.md#common-fields)
- **Choose one signalling style per hook: exit codes alone, or exit 0 with a JSON object on stdout.** stdout must be only the JSON object (a shell profile that prints on startup breaks parsing); a parse or schema failure is a non-blocking error on every exit code except 2. [JSON output](../pages/hook/hooks.md#json-output), [Exit code 0](../pages/hook/hooks.md#exit-code-0)
- **`PreToolUse` decides through `hookSpecificOutput.permissionDecision`: `allow`, `deny`, `ask` or `defer`.** Precedence across hooks is `deny` over `defer` over `ask` over `allow`; the reason is shown to Claude on `deny`, to the user on `ask`. The top-level `decision`/`reason` for this event is deprecated. `updatedInput` replaces the entire input object. [PreToolUse decision control](../pages/hook/hooks.md#pretooluse-decision-control)
- **Hooks cannot override permission rules.** Deny and ask rules are evaluated regardless of what a hook returns; a hook that exits 2 blocks before allow rules are evaluated. To allow everything except a few commands, allow `Bash` and add a hook that rejects those commands. [Extend permissions with hooks](../pages/permissions/permissions.md#extend-permissions-with-hooks)
- **Exit-2 effect differs per event.** It blocks `PreToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted`, `PostToolBatch`, `PreCompact` and `PreModelSwitch`; it only shows stderr for `PostToolUse` and `PostToolUseFailure` (the tool already ran); it is ignored for `PermissionRequest`, `Notification`, `StopFailure` and others. [Exit code 2 behavior per event](../pages/hook/hooks.md#exit-code-2-behavior-per-event)
- **`Stop` hooks can keep Claude working; guard against loops.** Input carries `stop_hook_active`, and Claude Code stops continuing after eight consecutive continuations. `Stop` in agent frontmatter is converted to `SubagentStop`. [Stop](../pages/hook/hooks.md#stop), [Hooks in subagent frontmatter](../pages/agent/sub-agents.md#hooks-in-subagent-frontmatter)

### Input

- **Every event receives `session_id`, `transcript_path`, `cwd`, `permission_mode` and `hook_event_name`; inside a subagent or `--agent` session also `agent_id` and `agent_type`.** Use `agent_type` to make one shared script role-aware (for example a read-only guard for reviewers only). `permission_mode` reports Manual as `"default"`. [Common input fields](../pages/hook/hooks.md#common-input-fields)
- **File-tool paths arrive absolute, expanded, and with backslashes on Windows.** A comparison written with forward slashes never matches; normalise separators before matching a segment such as `/src/`. `~` and relative spellings are expanded first, so they cannot bypass a path check. [PreToolUse input](../pages/hook/hooks.md#pretooluse-input)
- **Field names per tool**: Bash and PowerShell `command`; Write `file_path`, `content`; Edit `file_path`, `old_string`, `new_string`; Read `file_path`; Glob `pattern`; Grep `pattern`, `path`, `glob`; WebFetch `url`, `prompt`; Agent `prompt`, `subagent_type`, `model`. [PreToolUse input](../pages/hook/hooks.md#pretooluse-input)
- **`@`-referenced files and `EndConversation` never reach `PreToolUse`.** Blocking a path from `@` references needs a `Read` deny rule, not a hook. [PreToolUse](../pages/hook/hooks.md#pretooluse), [PreToolUse input](../pages/hook/hooks.md#pretooluse-input)
- **Outputs are capped at 10,000 characters** (`additionalContext`, `systemMessage`, plain stdout, each measured separately); overflow is saved to a file and replaced by a preview. Keep anything Claude must always see within the cap. Hooks have no controlling terminal, so use `systemMessage` for user-visible text and `terminalSequence` for notifications. [JSON output](../pages/hook/hooks.md#json-output), [Emit terminal notifications](../pages/hook/hooks.md#emit-terminal-notifications)

### Where hooks live and when they run

- **Locations**: `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, managed policy settings, plugin `hooks/hooks.json`, skill frontmatter, subagent frontmatter. Entries merge across levels; settings, managed and plugin hooks also run inside subagents. [Hook locations](../pages/hook/hooks.md#hook-locations)
- **A plugin's hooks register when the plugin loads and fire on their events from then on**, not only when one of its skills is used; narrow the `matcher` to limit them. `hooks/hooks.json` and the manifest `hooks` key both load and merge. [When plugin hooks fire](../pages/plugin/plugins-components.md#when-plugin-hooks-fire), [Hooks (plugin)](../pages/plugin/plugins-components.md#hooks)
- **Prefer exec form (`command` plus `args`) for any handler that references a path placeholder.** Each `args` element is one argument with no shell, so no quoting is needed; shell form needs `"${CLAUDE_PLUGIN_ROOT}"` in double quotes. On Windows, exec form needs a real executable (a `.exe`), not an npm `.cmd` shim; use `node` plus the script path. [Exec form and shell form](../pages/hook/hooks.md#exec-form-and-shell-form), [Environment, quoting, and matching MCP tools](../pages/plugin/plugins-components.md#environment-quoting-and-matching-mcp-tools)
- **Path placeholders**: `${CLAUDE_PROJECT_DIR}` (project root, stays put inside a worktree), `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`; the hook's `cwd` field follows Claude into a worktree. Hook scripts on Windows can set `"shell": "powershell"` and use `$env:CLAUDE_PROJECT_DIR`, never the bare `$CLAUDE_PROJECT_DIR` spelling. [Reference scripts by path](../pages/hook/hooks.md#reference-scripts-by-path), [Windows PowerShell tool](../pages/hook/hooks.md#windows-powershell-tool)
- **Workspace trust gates settings-file hooks in interactive sessions**, while `-p` and SDK sessions treat the folder as trusted and run hooks committed to the repository. Frontmatter hooks in a project subagent follow the stricter rule (the agent file's own folder must be trusted). Never ship a hook that assumes a trust prompt protected it. [Workspace trust](../pages/hook/hooks.md#workspace-trust), [What runs before you trust a folder](../pages/permissions/permissions.md#what-runs-before-you-trust-a-folder)
- **`SessionStart` at launch and `Setup` run before MCP servers exist**, so their `mcp_tool` hooks are skipped; use a `command` hook for launch-time work. [Events that fire before MCP servers are available](../pages/hook/hooks.md#events-that-fire-before-mcp-servers-are-available)
- **Debug with `claude --debug` and `/hooks`** (a read-only browser of configured hooks with their source); `disableAllHooks` cannot switch off managed hooks from a lower level. [Debug hooks](../pages/hook/hooks.md#debug-hooks), [The /hooks menu](../pages/hook/hooks.md#the-hooks-menu), [Disable or remove hooks](../pages/hook/hooks.md#disable-or-remove-hooks)

### Agent-team and workflow gates

- **Quality gates for teams**: `TeammateIdle`, `TaskCreated` and `TaskCompleted` accept exit 2 to send feedback and keep the teammate working or block the task change. [Enforce quality gates with hooks](../pages/orchestration/agent-teams.md#enforce-quality-gates-with-hooks), [Exit code 2 behavior per event](../pages/hook/hooks.md#exit-code-2-behavior-per-event)
- **A `Workflow` launch is a tool call**: in `-p` and SDK runs a `PreToolUse` hook returning `allow` approves it, and a permission rule `Workflow` or `Workflow(<name>)` does the same. [Approve the plan before it runs](../pages/orchestration/workflows.md#approve-the-plan-before-it-runs), [PreToolUse](../pages/hook/hooks.md#pretooluse)

## Authoring notes (agents-united, not host behaviour)

- A read-only guard for the reviewer role is one `PreToolUse` handler with `matcher: "Bash|PowerShell|Edit|Write|NotebookEdit"` that exits 2 unless the command is on a read-only list; keep the script in `registry/hosts/claude/hooks/` and register it from the agent's frontmatter (project scope) or plugin-level `hooks.json`.
- The shipped guards are `registry/hosts/claude/hooks/agents-united-guard.js` and `agents-united-readonly-guard.js` (the inline `src/core` guards written out unchanged), installed to `.claude/hooks/` and named by an agent as `node ${CLAUDE_PROJECT_DIR}/.claude/hooks/<name>.js` (ADR 0035). A user-level (global) agent has no portable placeholder, so it keeps the inline `node -e` guard. A missing script is a fail-open gate (rule above), so the doctor checks the file exists. Observed on 2.1.288 (`../observations/2026-10-04-claude-2.1.288-guard-file.md`): `${CLAUDE_PROJECT_DIR}` resolves in a project role's own `args`, a refused call comes back as a 200-character message, and a deleted script lets the call through with a one-line `hook_non_blocking_error` (exit 1).
- Observed on 2.1.288 (`../observations/2026-10-04-claude-2.1.288-agent-teams.md`): a hook in a subagent definition's frontmatter does not fire for an in-process Agent Teams teammate that reuses the definition (a write went through with no hook record), while a settings-level `PreToolUse` hook refuses the same teammate's call. A team's guard is therefore the settings-level one (ADR 0036).
- Ship each hook with a test that pipes a sample JSON payload (including a Windows-style backslash path) into the script and asserts exit code 2 or the JSON decision.
- The library snapshots `hooks.md` and `hooks-guide.md`; the "hooks-guide" examples were not used for any rule here.
