# Claude Code — authoring guide: MCP wiring

Distilled from the snapshots in `host-library/claude/pages/`. Primary source: [mcp](../pages/mcp/mcp.md). Supporting sources: [sub-agents](../pages/agent/sub-agents.md), [plugins-components](../pages/plugin/plugins-components.md), [hooks](../pages/hook/hooks.md), [permissions](../pages/permissions/permissions.md).

Native output lands in `registry/hosts/claude/` as an `.mcp.json` fragment (project or plugin scope), an agent's `mcpServers` frontmatter, or the exact `claude mcp add` command shown in install output. The install lane copies and hashes committed files; it never runs a model, and it does not decide trust for the user.

## Rules

### Where a server is defined

- **Three scopes plus plugins and connectors.** Local (default; `~/.claude.json` under the project path, private), project (`.mcp.json` in the project root, shared through version control) and user (`~/.claude.json`, all projects). Precedence when a name repeats: local, project, user, plugin-provided servers, claude.ai connectors; the whole entry from the winning source is used, fields are not merged. A managed `managedMcpServers` entry outranks all of them (v2.1.259+). [MCP installation scopes](../pages/mcp/mcp.md#mcp-installation-scopes), [Scope hierarchy and precedence](../pages/mcp/mcp.md#scope-hierarchy-and-precedence)
- **Ship team servers as project scope (`.mcp.json`).** Claude Code asks for approval before using them in interactive sessions (`claude mcp reset-project-choices` resets it), but `-p`, SDK and cloud sessions load them without asking, so a committed `.mcp.json` must be safe to run unprompted. A cloned repository cannot approve its own servers through committed settings. [Project scope](../pages/mcp/mcp.md#project-scope), [Project server approvals and workspace trust](../pages/mcp/mcp.md#project-server-approvals-and-workspace-trust)
- **To keep a project server out**: add it to `disabledMcpjsonServers` (blocks in every permission mode), exclude project settings with `--setting-sources`, or start with `--strict-mcp-config`. [Project scope](../pages/mcp/mcp.md#project-scope)
- **A plugin declares servers in `.mcp.json` at its root or inline in `plugin.json`.** They start automatically when the plugin is enabled and are added or removed by installing or uninstalling the plugin. [Plugin-provided MCP servers](../pages/mcp/mcp.md#plugin-provided-mcp-servers), [MCP servers](../pages/plugin/plugins-components.md#mcp-servers)
- **A subagent or `--agent` session can carry `mcpServers` in frontmatter**: an inline definition connects when the agent starts (and disconnects when it finishes) and keeps the tool descriptions out of the main conversation; a string reference shares the parent's connection. Project-agent inline servers load only after the folder is trusted, and plugin agents cannot declare `mcpServers` at all. [Scope MCP servers to a subagent](../pages/agent/sub-agents.md#scope-mcp-servers-to-a-subagent), [Frontmatter fields in plugin agents](../pages/plugin/plugins-components.md#frontmatter-fields-in-plugin-agents)

### Entry shape

- **Transports**: `http` (recommended for remote; `streamable-http` is an accepted alias), `sse` (deprecated; an `http` add falls back to SSE from v2.1.265), `stdio` (local process) and `ws` (WebSocket; `claude mcp add --transport` does not accept it, so use `add-json` or `.mcp.json`). [Option 1: Add a remote HTTP server](../pages/mcp/mcp.md#option-1-add-a-remote-http-server), [Option 2: Add a remote SSE server](../pages/mcp/mcp.md#option-2-add-a-remote-sse-server), [Option 4: Add a remote WebSocket server](../pages/mcp/mcp.md#option-4-add-a-remote-websocket-server)
- **Always write `type` for a URL entry.** An entry with `url` and no `type` is read as stdio and skipped with `has a "url" but no "type"`. `type: "sdk"` entries in `.mcp.json` are skipped, since only an SDK host can register them. Server names use only letters, numbers, hyphens and underscores; reserved names (`workspace`, `claude-in-chrome`, `computer-use`, `Claude Preview`, `Claude Browser`) are skipped. [Option 1: Add a remote HTTP server](../pages/mcp/mcp.md#option-1-add-a-remote-http-server), [From an mcpServers JSON block](../pages/mcp/mcp.md#from-an-mcpservers-json-block), [Configuration warnings](../pages/mcp/mcp.md#configuration-warnings)
- **For stdio, separate Claude's options from the server command with `--`** (`claude mcp add --env KEY=value --transport stdio name -- npx -y pkg`), and put another option between `--env` and the name. Claude Code sets `CLAUDE_PROJECT_DIR` in the spawned server's environment and answers `roots/list` with the launch directory plus added directories. [Option 3: Add a local stdio server](../pages/mcp/mcp.md#option-3-add-a-local-stdio-server)
- **Environment expansion in `.mcp.json`**: `${VAR}` and `${VAR:-default}` in `command`, `args`, `env`, `url` and `headers`. An unset variable without a default still loads with the literal text and a warning. In a remote server's `url` and `headers`, credential variables (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, cloud tokens, `NPM_TOKEN`, `HTTPS_PROXY`) read as empty, so copy a secret into a variable with a name of your own. [Environment variable expansion in .mcp.json](../pages/mcp/mcp.md#environment-variable-expansion-in-mcpjson), [Credential variables that read as empty](../pages/mcp/mcp.md#credential-variables-that-read-as-empty)
- **`${CLAUDE_PROJECT_DIR}` needs a default (`${CLAUDE_PROJECT_DIR:-.}`) in a project `.mcp.json` command or args**, because the variable lives in the server's environment; plugin-provided configs substitute it directly. Plugin configs also substitute `${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_PLUGIN_DATA}`. [Option 3: Add a local stdio server](../pages/mcp/mcp.md#option-3-add-a-local-stdio-server), [Plugin-provided MCP servers](../pages/mcp/mcp.md#plugin-provided-mcp-servers)
- **Never put a literal token in a committed entry.** Authenticate remote servers through OAuth (`/mcp`), `headers` with an expanded variable, or `headersHelper` (which is not run until the folder is trusted). Removing a remote server also deletes its stored OAuth tokens. [Authenticate with remote MCP servers](../pages/mcp/mcp.md#authenticate-with-remote-mcp-servers), [Trust a folder before its headersHelper runs](../pages/mcp/mcp.md#trust-a-folder-before-its-headershelper-runs), [Managing your servers](../pages/mcp/mcp.md#managing-your-servers)

### Tools, names and context

- **Tool names are `mcp__<server>__<tool>`; plugin servers register as `plugin:<plugin>:<server>` with tools `mcp__plugin_<plugin>_<server>__<tool>`.** Use the full name in permission rules, a skill's `allowed-tools`, a subagent's `tools` and hook matchers; a matcher on the bare server key never fires for a plugin server. [Plugin-provided MCP servers](../pages/mcp/mcp.md#plugin-provided-mcp-servers), [Match MCP tools](../pages/hook/hooks.md#match-mcp-tools)
- **Permission rules for MCP**: `mcp__server` and `mcp__server__*` cover a whole server, `mcp__server__tool` one tool; a parenthesised `mcp__` rule in a settings file is skipped (use `--disallowedTools` for that). Allow globs are accepted only after a literal `mcp__<server>__` prefix. [MCP](../pages/permissions/permissions.md#mcp), [Tool name wildcards](../pages/permissions/permissions.md#tool-name-wildcards)
- **Tool search defers MCP tools by default**: only names and server instructions load at start. `ENABLE_TOOL_SEARCH` (`true`, `auto`, `auto:N`, `false`) changes that, tool search falls back to upfront loading on a non-first-party `ANTHROPIC_BASE_URL` and on older Vertex models, and `alwaysLoad: true` on a server (or `anthropic/alwaysLoad` on a tool) exempts it at the cost of context. [Scale with MCP tool search](../pages/mcp/mcp.md#scale-with-mcp-tool-search), [Exempt a server from deferral](../pages/mcp/mcp.md#exempt-a-server-from-deferral)
- **Write short server instructions for tool search.** Each tool description and each server's instructions are truncated at 2,048 characters (`CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`, v2.1.280+), so put the critical detail first. [For MCP server authors](../pages/mcp/mcp.md#for-mcp-server-authors)
- **Output limits**: a warning above 10,000 tokens and a default cap of 25,000 (`MAX_MCP_OUTPUT_TOKENS`); an over-limit result is saved to a file and replaced by its path. A tool can raise its own limit with `anthropic/maxResultSizeChars` (up to 500,000 characters). [MCP output limits and warnings](../pages/mcp/mcp.md#mcp-output-limits-and-warnings), [Raise the limit for a specific tool](../pages/mcp/mcp.md#raise-the-limit-for-a-specific-tool)
- **A server can force a human prompt on a tool** with `_meta["anthropic/requiresUserInteraction"]: true` (v2.1.199+): the prompt shows on every call, even in `bypassPermissions`, allow rules and hook `allow` do not skip it, and `dontAsk` denies it. [Require approval for a specific tool](../pages/mcp/mcp.md#require-approval-for-a-specific-tool), [Extend permissions with hooks](../pages/permissions/permissions.md#extend-permissions-with-hooks)

### Verifying and operating

- **Verify a server with `claude mcp list` and `claude mcp get <name>`**: `✔ Connected`, `! Needs authentication`, `✘ Failed to connect`, `⏸ Pending approval`, `✘ Rejected` and `⊘ Disabled for this project` report different situations; WebSocket servers appear only in `get` and `/mcp`. A successful add prints `Added ...`, which only means the configuration was written. [Server status](../pages/mcp/mcp.md#server-status), [Managing your servers](../pages/mcp/mcp.md#managing-your-servers)
- **Toggling a server off in `/mcp` records the choice per project in `~/.claude.json`** (`disabledMcpServers` for regular, plugin and managed servers, `enabledMcpServers` for default-off built-ins); it is unrelated to the `.mcp.json` approval keys. [Disable a server without removing it](../pages/mcp/mcp.md#disable-a-server-without-removing-it)
- **Mid-session behaviour**: a dropped remote server is retried up to five times with exponential backoff, but stdio servers are local processes and are not reconnected automatically; a server that finishes connecting later is announced to Claude on its next request (with tool search) or awaited through `WaitForMcpServers` (without). Hooks on `SessionStart`/`Setup` run before servers exist, so their `mcp_tool` hooks are skipped. [Automatic reconnection](../pages/mcp/mcp.md#automatic-reconnection), [Tool availability](../pages/mcp/mcp.md#tool-availability), [Events that fire before MCP servers are available](../pages/hook/hooks.md#events-that-fire-before-mcp-servers-are-available)
- **Organizations can constrain servers** with `managed-mcp.json` (exclusive control), `managedMcpServers`, and `allowedMcpServers`/`deniedMcpServers`; those restrictions also cover servers declared in subagent frontmatter, and a blocked server is skipped with a warning. [Managed MCP configuration](../pages/mcp/mcp.md#managed-mcp-configuration), [Scope MCP servers to a subagent](../pages/agent/sub-agents.md#scope-mcp-servers-to-a-subagent)

## Authoring notes (agents-united, not host behaviour)

- Bundle wiring for a host is `install-time data only`: the lane may print a `claude mcp add` command or write a project `.mcp.json` entry, but the user's approval and any credentials remain theirs.
- Check every committed entry against the rules above: has `type` for URL entries, no literal secrets, expanded variables use non-credential names, plugin-scoped tool names in permission rules and hook matchers.
- Not snapshotted: `managed-mcp`, the settings reference and the environment-variable page. Add them to `sources.json` before authoring org-policy content.
