# Claude Code — authoring guide: agents (subagents)

Distilled from the snapshots in `host-library/claude/pages/`, for the `realize-for-host` skill. Primary source: [sub-agents](../pages/agent/sub-agents.md). Supporting sources: [plugins-components](../pages/plugin/plugins-components.md), [tools-reference](../pages/tools/tools-reference.md), [hooks](../pages/hook/hooks.md).

Native output lands in `registry/hosts/claude/agents/<role>.md` (Contract Floor synced from `registry/core/<role>.core.md`, everything above the floor written natively). A role is a Claude Code **subagent**; the same file also runs as the main session (`claude --agent <name>`) and as an agent-team teammate. Each rule below cites the snapshot section it comes from; when a snapshot is refreshed and a heading moves, `npm run hostlib:verify` fails until the citation is fixed.

## Rules

### File format and discovery

- **One markdown file per agent; only `name` and `description` are required.** The body is the system prompt. A subagent receives only that prompt plus basic environment details (working directory), not the Claude Code system prompt. [Write subagent files](../pages/agent/sub-agents.md#write-subagent-files), [Frontmatter reference](../pages/agent/sub-agents.md#supported-frontmatter-fields)
- **Spell frontmatter keys exactly (camelCase: `maxTurns`, `disallowedTools`, `omitClaudeMd`).** Claude Code ignores an unrecognised field without an error, so a typo silently drops the setting. [Frontmatter reference](../pages/agent/sub-agents.md#supported-frontmatter-fields)
- **Never ship a file that Claude Code silently skips.** A project, user or managed agent file is skipped without a session message when it has no `name` (it is treated as documentation), when the opening `---` is not the first line, when `name` starts with `-` or contains `:`, when it has a `name` but no `description`, or when the YAML does not parse. [Subagent files Claude Code skips](../pages/agent/sub-agents.md#subagent-files-claude-code-skips)
- **Validate the directory before shipping.** `claude plugin validate <dir>` (v2.1.233+) finds files whose frontmatter does not parse, but it does not flag a file that parses and has no `name`, so check `name` in our own conformance test. [Check an agents directory before a session](../pages/agent/sub-agents.md#check-an-agents-directory-before-a-session)
- **Keep `name` unique across the whole tree.** Two files in one `.claude/agents/` tree with the same `name` load only one, chosen by filesystem read order. Across nested project directories the definition closest to the working directory wins. The filename need not match `name`, and `name` is the value hooks receive as `agent_type`. [Choose the subagent scope](../pages/agent/sub-agents.md#choose-the-subagent-scope), [Frontmatter reference](../pages/agent/sub-agents.md#supported-frontmatter-fields)
- **Priority when names collide: managed settings, `--agents` flag, `.claude/agents/`, `~/.claude/agents/`, plugin `agents/` (lowest).** Project agents are meant to be committed; plugin agents are namespaced `<plugin>:<name>`, and a subfolder becomes part of that scoped name. [Choose the subagent scope](../pages/agent/sub-agents.md#choose-the-subagent-scope), [Organize agents in subfolders](../pages/plugin/plugins-components.md#organize-agents-in-subfolders)
- **A plugin agent cannot carry `hooks`, `mcpServers`, `permissionMode` or `initialPrompt`.** Claude Code ignores them for security. A package that needs them must ship the agent as a project/user file, or move the hook and MCP server to plugin-level `hooks/hooks.json` and `.mcp.json`. [Choose the subagent scope](../pages/agent/sub-agents.md#choose-the-subagent-scope), [Frontmatter fields in plugin agents](../pages/plugin/plugins-components.md#frontmatter-fields-in-plugin-agents)
- **Edits to `~/.claude/agents/` and `.claude/agents/` are picked up within seconds, with three exceptions that need a restart**: the first agent file in a directory that did not exist at session start, `--add-dir` directories, and sessions started with `--disable-slash-commands`. [Write subagent files](../pages/agent/sub-agents.md#write-subagent-files)

### Delegation

- **`description` is the delegation trigger.** Claude delegates from the task, the `description` field and current context; phrases such as "use proactively" encourage it. Keep descriptions short: a startup warning appears when the combined descriptions pass 15,000 tokens (every agent still loads). [Understand automatic delegation](../pages/agent/sub-agents.md#understand-automatic-delegation)
- **Choose a subagent for verbose output, enforced tool limits or self-contained work that can return a summary; stay in the main conversation for iterative, tightly coupled phases.** [Choose between subagents and main conversation](../pages/agent/sub-agents.md#choose-between-subagents-and-main-conversation)
- **A subagent starts with no conversation history.** Its context is its own prompt, the delegation message Claude writes, the CLAUDE.md hierarchy, a git-status snapshot and any preloaded skills. A rule that must reach it and is not in CLAUDE.md has to be restated in the delegation prompt. [What loads at startup](../pages/agent/sub-agents.md#what-loads-at-startup)
- **Subagent output is scanned before Claude reads it (v2.1.210+).** Text imitating `<system-reminder>` or `Human:`/`Assistant:` lines gets a backslash, and a marker line is prepended for instruction-shaped text. The scan is not a substitute for restricting what a subagent can reach. [Subagent output scanning](../pages/agent/sub-agents.md#subagent-output-scanning)
- **Resume, do not respawn, to continue work.** Each invocation is a new instance; `SendMessage` with the agent ID or name resumes one with its full history. Explore and Plan are one-shot and cannot be resumed. [Resume subagents](../pages/agent/sub-agents.md#resume-subagents)

### Tools

- **`tools` is an allowlist, `disallowedTools` a denylist, and omitting both inherits every tool available to subagents.** `disallowedTools` is applied first and a tool listed in both is removed. [Available tools](../pages/agent/sub-agents.md#available-tools), [Agent tool behavior](../pages/tools/tools-reference.md#agent-tool-behavior)
- **Some tools never reach a subagent, even when listed in `tools`**: `AskUserQuestion`, `EndConversation`, `EnterPlanMode`, `ExitPlanMode` (unless `permissionMode: plan`), `ScheduleWakeup`, `WaitForMcpServers`, `Workflow`, and `Agent` at the depth limit. A role that needs the user or a dynamic workflow must run as the main-thread agent (`--agent`), not as a subagent. [Available tools](../pages/agent/sub-agents.md#available-tools)
- **Background subagents (Claude's default; foreground only in the cases the page lists) keep every MCP tool but only a fixed set of built-in tools** (`Read`, `Grep`, `Glob`, `LSP`, `Bash`, `PowerShell`, `Edit`, `Write`, `NotebookEdit`, `WebFetch`, `WebSearch`, `TodoWrite`, `Skill`, `ToolSearch`, `EnterWorktree`, `ExitWorktree`, `Monitor`, `TaskStop`, `SendMessage`, `Artifact`, plus `SubagentHandback`). The same definition can resolve to different tools in foreground and background. [Available tools](../pages/agent/sub-agents.md#available-tools), [Run subagents in foreground or background](../pages/agent/sub-agents.md#run-subagents-in-foreground-or-background)
- **A `tools` list that resolves to nothing refuses to launch (v2.1.208+).** Every misspelt or unavailable entry is named in the error. Verify each name against the tools catalog in the tools guide. [Available tools](../pages/agent/sub-agents.md#available-tools)
- **A specifier in `disallowedTools` removes the whole tool.** `disallowedTools: Bash(git push *)` drops Bash entirely; to block one command keep Bash and add `Bash(git push *)` to `permissions.deny`, which applies to the main conversation and every subagent. [Available tools](../pages/agent/sub-agents.md#available-tools)
- **MCP grants use `mcp__<server>` or `mcp__<server>__*`** in `tools` or `disallowedTools`; `mcp__*` in `disallowedTools` removes every MCP tool. [Available tools](../pages/agent/sub-agents.md#available-tools)
- **On macOS, Linux and WSL, Glob and Grep are not in the default tool set.** A subagent gets them back when it lists `Glob` or `Grep` in `tools` and leaves `Bash` out; otherwise search runs through `find`/`grep` in Bash, where hooks and permission rules see it as `Bash`. A read-only role that keeps Bash therefore has no dedicated search tool on those platforms. [Glob tool behavior](../pages/tools/tools-reference.md#glob-tool-behavior), [Available tools](../pages/agent/sub-agents.md#available-tools)
- **`Agent(a, b)` limits spawnable types only for an agent running as the main thread (`--agent`).** In a subagent definition, listing `Agent` allows nested spawning and any type list is ignored; omit `Agent` from `tools` to stop spawning. Nesting defaults to three layers (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`) and 20 concurrent subagents (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`). [Restrict which subagents can be spawned](../pages/agent/sub-agents.md#restrict-which-subagents-can-be-spawned), [Let subagents spawn their own subagents](../pages/agent/sub-agents.md#let-subagents-spawn-their-own-subagents), [Concurrent subagent limit](../pages/agent/sub-agents.md#concurrent-subagent-limit)

### Enforcement

- **Prose is not enforcement; a `PreToolUse` hook is.** Use hook `matcher` plus a script that exits 2 to allow some operations of a tool and block others (the documented example is read-only SQL through Bash). [Conditional rules with hooks](../pages/agent/sub-agents.md#conditional-rules-with-hooks)
- **Frontmatter hooks run only while that subagent is active, and `Stop` becomes `SubagentStop`.** A project-level agent's frontmatter hooks are skipped until the folder containing the agent file is trusted (a parent's trust and `-p` do not count); agents from `~/.claude/agents/` and `--agents` are exempt. [Hooks in subagent frontmatter](../pages/agent/sub-agents.md#hooks-in-subagent-frontmatter)
- **Settings, managed and plugin hooks also fire inside subagents**, and their input carries `agent_id` and `agent_type`, so one shared guard can branch on the role. `SubagentStart` and `SubagentStop` accept an agent-type matcher; a plugin-scoped name contains `:` and is matched as an unanchored regex, so anchor it (`^my-plugin:reviewer$`). [Define hooks for subagents](../pages/agent/sub-agents.md#define-hooks-for-subagents), [Project-level hooks for subagent events](../pages/agent/sub-agents.md#project-level-hooks-for-subagent-events), [Common input fields](../pages/hook/hooks.md#common-input-fields)
- **`permissionMode` is only honoured when the main conversation is in `default`, `dontAsk` or `plan`.** Under `bypassPermissions`, `acceptEdits` or auto the subagent runs in the parent's mode, and a subagent that declares `bypassPermissions` keeps the parent's mode (v2.1.267+). Never rely on `permissionMode` alone for a read-only guarantee. [Permission modes](../pages/agent/sub-agents.md#permission-modes)
- **Turning on `memory` silently adds `Read`, `Write` and `Edit`.** A read-only role must not set `memory`, or must accept that it can write its own memory directory. Scopes are `user`, `project` (recommended) and `local`; auto memory being off disables the field. [Enable persistent memory](../pages/agent/sub-agents.md#enable-persistent-memory)

### Model, effort and isolation

- **Model resolves per invocation parameter, then `model` frontmatter (`inherit` = the parent's), then `CLAUDE_CODE_SUBAGENT_MODEL`, then the parent's model.** With `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` the definition's `model` is ignored altogether. Subagents inherit the session's extended-thinking setting; there is no per-subagent thinking key. [Choose a model](../pages/agent/sub-agents.md#choose-a-model), [Run every subagent on one model](../pages/agent/sub-agents.md#run-every-subagent-on-one-model)
- **Use the optional keys deliberately**: `maxTurns` (returns partial output, resumable), `effort`, `isolation: worktree` (a temporary worktree, cleaned up if unchanged), `background`, `omitClaudeMd` (v2.1.271+, keeps managed policy files), `color`. [Frontmatter reference](../pages/agent/sub-agents.md#supported-frontmatter-fields)
- **`skills` preloads the full content of each listed skill at startup**; it does not restrict which skills the agent can invoke (omit `Skill` from `tools` for that). A skill with `disable-model-invocation: true` cannot be preloaded, and a missing skill is skipped with a debug-log warning. [Preload skills into subagents](../pages/agent/sub-agents.md#preload-skills-into-subagents)
- **`mcpServers` takes a name (shares the parent's connection) or an inline definition (connected for this subagent only, keeping its tool descriptions out of the main context).** Inline servers from a project agent file load only after the folder is trusted; `--strict-mcp-config` and managed MCP policy still apply. [Scope MCP servers to a subagent](../pages/agent/sub-agents.md#scope-mcp-servers-to-a-subagent)
- **`claude --agent <name>` replaces the default system prompt with the agent's body** (unless the prompt is empty), while CLAUDE.md files still load. That is how an orchestrator gets the tools a subagent cannot have. [Invoke subagents explicitly](../pages/agent/sub-agents.md#invoke-subagents-explicitly), [Restrict which subagents can be spawned](../pages/agent/sub-agents.md#restrict-which-subagents-can-be-spawned)

## Authoring notes (agents-united, not host behaviour)

- Contract Floor sections (identity, mission, scope, output contract, safety) come from `registry/core/`; do not restate them natively.
- Derive `tools` from capability classes in `tool-policy.json` (Plan 032 Phase 5), then confirm each name against [guide/tools.md](tools.md). Enforce "read-only" with a hook, not only with the allowlist.
- The library has no snapshot of the settings reference, environment variables or errors pages; the keys and variables named above come from the sub-agents page. Add those pages to `sources.json` before relying on anything else about them.
