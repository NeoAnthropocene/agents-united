## What this shows and what it does not

- **Shown once, on this machine and Host version `Claude Code 2.1.325`:** the Host honours `onFailure: "block"` on a `PreToolUse` command hook declared in an agent's frontmatter, in three places: the main agent of a session started with an agent (`orchestrator-agent-factory`, part A step 3), a subagent started with the `Agent` tool in the foreground (`factory-realizer`, part A step 4), and a subagent of a plain session that the Host ran in the background (`probe-readonly-worker`, part B). Tools seen blocked: `PowerShell`, `Write`, `Bash`. The block message has the documented form (`failed; blocking because onFailure is "block"`, then Node's error output); one difference from the documentation's example was seen: the observed message names the hook as `[command hook]`, where the example names the command line in the brackets. A harmless command is blocked as well, as expected: a guard that cannot run blocks everything its matcher covers. This answers point 1 of the "Not observed on the real Host" list of [the P20 verification record](../../../docs/plan-033-p20-verification-2026-11-16.md) for the script-file form. It also shows the read-only guard handler's field working on `probe-readonly-worker`, which copies the shipped evaluator's hook; the shipped evaluator itself holds no tool the matcher covers except connected-server tools, so it cannot show this.
- **Not shown:** the inline (`node -e`) form of the handlers (global installs); a Host older than `2.1.295` (point 2 of the P20 verification list); a timeout; `Monitor`; connected-server tools of a read-only role while the script is missing; the JSON `null` case; hook failures other than a missing script (a crash inside the script, invalid output); `Edit`, `MultiEdit`, `NotebookEdit` and the delegation tools; managed settings; a second machine; a later Host version; and what a missing read-only guard script did before P20.
- **Not determinable from the records:** whether the block came from `onFailure: "block"` alone or also from something else in the session (the first sitting, without the field, on the same Host version, machine and permission mode, ran the command; the field is the one difference in the agent files, but the record cannot prove causation).
- **Unchanged limits of P20 (design limits, not observations):** the legacy inline guard and the settings-level session guard do not carry the field; the destructive guard still allows a call whose input it cannot read; the mode-line gate does not carry the field.
