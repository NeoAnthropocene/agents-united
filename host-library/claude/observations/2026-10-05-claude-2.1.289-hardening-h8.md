# Claude Code 2.1.289: six skills against no skill, and what the host does with `skillOverrides` and the skill listing (Plan 035 M3, H8, 2026-10-05)

**These are observations of one installed build, not documentation.** The guides in `../guide/` cite the vendor's docs snapshots; where this file disagrees with a guide, the guide's authoring notes say so. Nothing here is a vendor statement.

- **Build:** Claude Code `2.1.289`, Windows 11. The docs library is reviewed against `2.1.285`.
- **Account:** Claude Pro, extra usage off.
- **Iteration 1 (24 prompts):** a fresh scratch project `C:\github\scratch-pilot\h8-skills`, `agents add digital-agency -t claude --native --session-guard local -y` from the CLI built at `e4801a7`, `agents doctor --host claude` healthy. The maintainer typed each prompt in a fresh TUI session, `claude --agent <role> --model sonnet --effort medium` (permission mode `auto`), first with the skills as installed (12 sessions), then with the six skills set to `"off"` in `skillOverrides` of the scratch project's `.claude/settings.local.json` (12 sessions). The prompts are the first two evals of `registry/skills/<name>/evals/evals.json`, typed verbatim.
- **Iteration 2 (9 prompts: 7, then 2 more on 2026-10-06 for the funnel fixture, which the maintainer permitted):** headless, `claude -p <prompt> --agent <role> --model sonnet --effort medium --permission-mode auto --output-format json --max-budget-usd 0.8` with stdin from `/dev/null`, from fresh scratch projects installed from a local merge of the three pull requests below (#148 to #150). The no-skill runs had the skill's folder deleted from the project, not an override.
- **Grading:** by the executor, from the records and the answer, against assertions written from each eval's `expected_output` before any without-skill answer was read (65 for iteration 1, 11 new ones for the SEO fixture). Every verdict has its quoted evidence in `grading.json`; the workspace is at `C:\github\scratch-pilot\h8-workspace`, and a copy of the review pages, the assertions, `grading.json`, `timing.json` and `benchmark.json` of both iterations and the scripts is kept in this repository in `2026-10-05-h8-review/` (start with its `README.md` and the two `review-iteration-*.html` pages).

## What was established

- **With the skill 53 of 65 assertions, without it 36 of 65** (iteration 1, six skills, two evals each): ab-test-setup 11/11 against 7/11, growth-experiment-design 9/11 against 5/11, copywriting-frameworks 9/12 against 5/12, accessibility-audit 9/10 against 6/10, conversion-funnel-optimization 9/11 against 8/11, seo-audit 6/10 against 5/10. The with-skill runs cost 1.83 USD against 1.36 USD (+34%); growth-experiment-design is the heaviest (0.47 against 0.27 USD, 8,607 against 3,791 output tokens, 73 s against 32 s).
- **What the skills add is mostly the team's own contract**, not reasoning: named hand-offs (Emre, Defne, Kaan, Deniz), ICE reasons, decision rules, a claim audit, a per-URL intent table, a health score by the stated rule. The sample-ratio check, the paid-social diagnosis and the refusal of a ranking promise were the same without the skill.
- **`skillOverrides: "off"` blocks invocation, not reading.** The host answered the `Skill` call with `<tool_use_error>Skill growth-experiment-design is disabled for model invocation in skillOverrides settings</tool_use_error>` (also for `ab-test-setup`, and `conversion-funnel-optimization` and `copywriting-frameworks` in other runs), but one run read `.claude/skills/conversion-funnel-optimization/examples/worked-example.md` with `Read` and said so: that baseline is contaminated. Deleting the folder in a scratch copy is the clean no-skill baseline (iteration 2). The roles also fell back to neighbouring skills that stay on (`onboarding-cro`, `a11y-debugging`, `technical-seo-audit`), so a result is the marginal value of the target skill, not of skills in general.
- **The model sees the whole description.** The session record carries an `attachment/skill_listing` with the full text of the description: checked in an iteration 2 session for `accessibility-audit`, whose 740-character description appears in full in a 54-skill install. The docs say descriptions can be dropped to fit a budget of 1% of the context window when many skills are installed; that had not happened to this one (the other five were not checked).
- **A description is behaviour text when the skill is not loaded.** `accessibility-audit` and `seo-audit` were not loaded on the two prompts that ask for a claim (a WCAG compliance statement, a guaranteed ranking) in either iteration, even after the description named those requests as triggers (one headless run each). But one answer changed: after the description said the skill "declines it and hands the legal question to Defne", the compliance answer named Defne (4 of 4, was 3 of 4 with the old description and without the skill). The ranking answer scored 3 of 3 before and after (2 of 3 without the skill), so the tuned description did nothing measurable there. Single runs: the run-to-run noise measured here is one assertion (the same configuration, skill unloaded, scored 3/4 and 3/4 on one eval and 3/3 and 2/3 on the other).
- **Two evals were faulty and failed in both configurations.** `seo-audit` eval 1 audited `example.com`, a placeholder whose pages return 404, so a per-URL intent table, graded findings and a health score were impossible (4 of 7 assertions failed with and without the skill). On a static fixture site with six planted findings, the same skill scored **11 of 11 against 9 of 11 without it**; the two misses without it are the per-URL intent table and the score by the stated rule (the answer says "the `seo-audit` skill that defines the scoring rule is not installed, so I used a stand-in"). `conversion-funnel-optimization` eval 1 asks for graded findings from four numbers, which the skill's own rule (evidence is a count, a recording or a page element you read) cannot give.
- **The report shape the model never opened.** In both with-skill funnel runs the role did not read `examples/templates.md`, so the report order and the owners that sat there were never in front of it. After the shape moved into `SKILL.md` as a table (#150) the report followed the seven parts and named three of four owners (one of four before), but graded no finding without a page: 9 of 11 against 8 of 11, unchanged. **Given a page to read (a new eval 4: the same funnel plus a static three-page course site with one S1, two S2, an S3 and an S4 planted), the skill scored 8 of 12 against 6 of 12 without it, at the same cost** (0.2377 against 0.2210 USD, 6,483 against 6,602 output tokens): with it the findings were graded and S1 and S2 were labelled fixes, not tests; without it, most of the same defects were found but none was graded, no benchmark was flagged and no one was named for a hand-off. Its grades differed from the planted ones twice (a missing viewport graded S1, the free-lesson promise S3, both planted S2) and its findings table had no principle column.
- **Roles write into the project when a skill says to.** Three runs wrote `docs/cro/*.md` into the scratch project (the copywriting runs with and without the skill, and the iteration 2 funnel audit; a fourth wrote its playbook to the host's scratchpad); the next session of the same project would find them, so the first two were moved out between runs.
- **Headless runs work on the subscription** with the flags above (`MSYS_NO_PATHCONV=1` under Git Bash; the JSON result carries `total_cost_usd` and `session_id`); the records land in `~/.claude/projects/<cwd as ->/` like a TUI session and `npm run hostlib:session` reads them. A first attempt failed for a relative prompt path (no model call, no cost).

## Not established

- Whether the two grading differences of the funnel skill on its fixture (S1 for a missing viewport, S3 for the free-lesson promise) are stable; one run each way cannot say, and no rule was added.
- The other 24 skills of the layout: only six skills and their first two evals (three of them on a changed prompt) were run. The third eval of each was not run.
