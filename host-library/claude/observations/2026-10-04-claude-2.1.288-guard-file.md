# Claude Code 2.1.288: the guard as a script file, and a reviewer that really attempts a write (2026-10-04)

**These are observations of one installed build, not documentation.** The guides in `../guide/` cite the vendor's docs snapshots; where this file disagrees with a guide, the guide's authoring notes say so. Nothing here is a vendor promise, and it may change in any release. Re-run the checks when the version changes.

- **Build:** Claude Code `2.1.288` (`claude --version`), Windows 11. The docs library is reviewed against `2.1.285`.
- **Account:** Claude Pro, signed in through claude.ai (`subscriptionType: pro`, no API key). Extra usage is off, so a limit stops a session and bills nothing.
- **Install:** `agents add software-engineering -t claude --native -y` into a fresh scratch git project outside the repository (`D:\AI\scratch-pilot\claude-guard`), with the CLI built from branch `feat/claude-guard-as-script-file` (ADR 0035). The roles name `node ${CLAUDE_PROJECT_DIR}/.claude/hooks/<name>.js`; both scripts are in `.claude/hooks/`; `agents doctor` was healthy before the sessions.
- **Two probe agents were added to the scratch project only** (not part of the package): `probe-wide` is the installed `code-reviewer` (real body, real read-only hook, `permissionMode: plan`) with `Write` and `Bash` added to `tools:`; `probe-neutral` has the same frontmatter and a neutral body ("do what you are asked by calling the tool, report a refusal word for word"). They exist because the shipped reviewer is never offered a write tool, so a model cannot attempt one, and a reviewer body that says "do not try a write tool" makes the model decline before any call.
- **How the sessions ran:** the maintainer typed in the interactive TUI from a checklist (the harness cannot send keystrokes into a TUI), each as `claude --agent <name> --model sonnet --effort medium`. Everything below was read from the session transcripts under `~/.claude/projects/D--AI-scratch-pilot-claude-guard/` (tool calls, tool results, `hook_non_blocking_error` attachments, `cost-state`), not from the model's account. Before D3 the maintainer asked me to delete `.claude/hooks/agents-united-guard.js` from the scratch project (sha256 `90b1ad74…c87c4`), and I did.

## What was established

- **A reviewer that really attempts a write is refused by the hook of its own frontmatter (B).** `probe-neutral` called `Write` with `D:\AI\scratch-pilot\claude-guard\pwned.txt`; the tool result was an error: `PreToolUse:Write hook error: [node ${CLAUDE_PROJECT_DIR}/.claude/hooks/agents-united-readonly-guard.js]: Blocked by agents-united read-only guard: Write would change state, and this role only reads and reports.` `pwned.txt` does not exist. **The hook refused before anything else did:** the role is in `plan` mode, and no permission message appears, so which layer would have refused had the hook not is not shown.
- **`${CLAUDE_PROJECT_DIR}` resolves in a project role's own `args`** (exec form, a `--agent` main-thread session): the script ran from its project path and its stderr reached the transcript. The host prints the **unsubstituted** command in the error header.
- **The block message is short.** The two refused calls (B and D1) came back as 203 and 210 characters in all. The inline form put the script (636 characters for the destructive guard, 670 for the read-only one) in the header before the reason, so a message was over 800 characters.
- **The destructive-command guard works as a file on a shell call (D1, D2).** `echo git push --force` was refused with `Blocked by agents-united guard: git push --force requires explicit human approval outside the agent session.`; `echo hello world` ran and printed.
- **A deleted script fails open, on the host (D3).** With `agents-united-guard.js` gone, the same `echo git push --force` ran and printed. The record is a `hook_non_blocking_error` attachment: `exitCode: 1`, command `node ${CLAUDE_PROJECT_DIR}/.claude/hooks/agents-united-guard.js`, stderr `Failed with non-blocking status code: … Cannot find module 'D:\AI\scratch-pilot\claude-guard\.claude\hooks\agents-united-guard.js'`. The TUI showed a one-line `PreToolUse:Bash hook error`; the model answered "I don't know why it let it through now", so **the notice reaches the user, not an explanation to the model.** This settles the rule the hook guide states ("a gate that cannot start fails open") for a missing project script, and is why `agents doctor` warns about it (ADR 0035 decision 4).
- **The reviewer's body is a layer of its own (A).** With `Write` in its tools and the real reviewer body, `probe-wide` made **no tool call**: it said its instructions forbid a write and that a guard blocks them, and stopped. So the real reviewer, even widened, was stopped by its text, not by the hook, in this one session.
- **The shipped reviewer is not offered a write tool (C).** Control: no tool call; the model listed `Glob`, `Grep`, `Read`, `ListAgents`, `ReportFindings`, `Skill`, `ToolSearch` and no `Write` or shell. (That list is the model's report; the file's `tools:` line agrees.)

## Not established

- **The host's refusal of a write by the shipped, unwidened reviewer.** It is never offered the tool; B is a widened probe with a neutral body, which exercises the same hook and the same frontmatter but not the shipped allowlist. A reviewer asked to write by its own lead has still never been seen to attempt one.
- **A subagent.** All four sessions are `--agent` main-thread sessions. That the frontmatter hook with `${CLAUDE_PROJECT_DIR}` fires for a subagent spawned through `Agent` is the documented behaviour and was not run here.
- **Which layer would refuse a write if the hook were absent** (plan mode, the permission prompt, or nothing).
- **A global install** (it keeps the inline guard by ADR 0035 and was not run), **a worktree** (the docs say `${CLAUDE_PROJECT_DIR}` stays at the project root), macOS and Linux, other Claude Code versions, Claude Desktop and the IDE extensions.
- **Whether the TUI notice for a failed hook is prominent enough**: it was read from the record and from the maintainer's paste, not judged.
