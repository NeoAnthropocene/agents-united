# Claude Code 2.1.288: the pilot bundle in real interactive sessions (2026-10-03)

**These are observations of one installed build, not documentation.** The guides in `../guide/` cite the vendor's docs snapshots; where this file disagrees with a guide, the guide's authoring notes say so. Nothing here is a vendor promise, and it may change in any release. Re-run the checks when the version changes.

- **Build:** Claude Code `2.1.288` (`claude --version`). The docs library is reviewed against `2.1.285`.
- **Account:** Claude Pro, signed in through claude.ai (`claude auth status`: `subscriptionType: pro`, no API key). Extra usage is off, so a limit stops a session and bills nothing.
- **Install:** `agents add software-engineering -t claude --native -y` into a fresh scratch git project outside the repository (`D:\AI\scratch-pilot\claude`), with the CLI built from branch `chore/plan-032-close-out`. Five native agents, three native workflows, 33 skills (36 minus the three the workflows replace), six rules.
- **How the sessions ran:** the maintainer typed in the interactive TUI, driven from a checklist; the harness cannot send keystrokes into a TUI. What follows was read from the session transcripts under `~/.claude/projects/` (tool calls, tool results, workflow run records), not from the model's own account, except where marked.

## What was established

- **Delegation and a small real task (S1).** The orchestrator checked the installed state, made a `feature/slugify` branch, and made one `Agent` call to `backend-architect` (running `claude-sonnet-5-5`). The specialist wrote `index.test.js` first, the run was red (`slugify is not a function`), a first implementation failed one apostrophe case, the specialist fixed the implementation and left the test alone, and the orchestrator re-ran the suite itself (8 of 8). Nothing was committed. **No `code-reviewer` call was made**: the routing rule sends a small change to one specialist, and a workflow is for roughly eight or more files.
- **Skills (S1).** `/skills` lists the installed skills; `/reload-skills` answered "63 skills available (no changes)" (the project's 33 plus bundled, user and plugin skills).
- **The managed guard fires from a role's own frontmatter (R1).** The orchestrator was the main agent. `echo git push --force` and `echo x > .env.test` came back as `PreToolUse:Bash hook error: [node -e ...]: Blocked by agents-united guard: ...` (the same text for the two rules, exit 2); `.env.test` was not created; `echo hello world` ran. These are the model-proof commands of `docs/guard-testing.md`. In S1 the literal request `Run git push --force origin main` was declined by the model citing the `git-guardrails` rule, with no tool call, so it said nothing about the hook; that is why the echo form was used.
- **`/hooks` does not list a role's frontmatter hook (R1).** With the guard demonstrably firing, `/hooks` showed "No hooks configured for this event" for `PreToolUse`. `docs/guard-testing.md` said otherwise and now carries this observation.
- **Native workflows run (R1), once workflows are on.** `/workflow-test` ran 1 agent (8.4 s, 54k tokens) and returned `Green` (8 of 8). `Review the change ... with the workflow-review workflow` ran `Workflow` with `args.files` scouted by the orchestrator: 3 agents, 24.7 s, 86k tokens, verdict `Approve`, two `INFO` findings (a raw combining-character range in a regex, and letters such as `ß` that are dropped).
- **A command-line `--model` and `--effort` override the pinned posture.** `--agent orchestrator-engineering --model sonnet --effort medium` ran the main thread on `claude-sonnet-5-5` although the file says `opus`.
- **`/agents` is gone in 2.1.288.** It prints "The /agents wizard has been removed" and points at the agent files. `claude agents` manages background sessions and needs a terminal; `claude agents --json` is for sessions, not for configured subagents. `/list-agents` printed the session's own name. The plan's "`/agents` lists the roles" has no host-side replacement; the roster was checked through the orchestrator's answer (it named all four specialists and the three workflows) and through the files in `.claude/agents/`.

## Defects found, and what became of them

1. **`-t claude --native` wrote the Antigravity lane into a Claude-only project** (`.agents/agents`, `rules`, `hooks/`, `hooks.json`, `mcp_config.json`, lockfile `nativeLanes.antigravity`), and `doctor` then counted 0 agents. Found while preparing S1, before any model call. Fixed, test first (`tests/native-claude-only-install.test.ts`), commit `ee41378`.
2. **With dynamic workflows off, the three commands do not exist** (S1). The model said it had no tool to run them, `/workflow-test` was not found and `/workflow-review` was not on the slash menu; the native lane had replaced the skills of the same names. The docs page says that on Pro the feature is switched on in the Dynamic workflows row of `/config`. The maintainer switched it on and R1 passed; the same account's headless runs on 2.1.287 had worked, and why is **not established**. The toggle wrote `"enableWorkflows": true` and `"skipWorkflowUsageWarning": true` to `~/.claude/settings.json` (observed by diffing the config before and after; **neither key is in the docs snapshot**, so nothing relies on them). Fixed, test first (`tests/native-workflows-gate.test.ts`), commit `4523e04`: an install note, a doctor warning when the documented `disableWorkflows` or `CLAUDE_CODE_DISABLE_WORKFLOWS` is set, and orchestrator text that explains a missing `Workflow` tool.
3. **Noisy block message.** The host prints the whole `node -e` script inside the block message (about 600 characters of regular expressions per block, which also reaches the model). Not changed: a guard as a separate script file is already listed as not done. Follow-up.
4. **Maintainer decision, not a defect:** orchestrators are pinned to `opus` at `medium` effort for the native lane (ADR 0018 addendum, commit `eceb670`).
