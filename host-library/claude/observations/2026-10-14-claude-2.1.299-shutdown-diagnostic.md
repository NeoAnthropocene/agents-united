## Findings and limits

**ADR 0055's missing-notice reporting behavior passes these three flows.** Verified work reaches the user without waiting for an unobserved lifecycle notice; a later human turn preserves completion. The shutdown requests and approvals succeed, and the default case shows corresponding host membership removal. The repository's delivery hang is addressed for this scenario. This is not a fix to the host's notification pipeline or proof of universal communication reliability.

**A forced UUID is not necessary for the missing-notice symptom.** The earlier identity discrepancy explains the invalid captures but is insufficient to explain the default run. The remaining investigation concerns host lifecycle handling and what it exposes to the lead/TUI. The recorded SendMessage description labels the reply path as legacy and states that approval ends the teammate; it does not explicitly promise a conversational termination notice. Current [agent-team documentation](https://code.claude.com/docs/en/agent-teams#shut-down-teammates) describes graceful approval and automatic delivery, but does not explicitly specify a `teammate_terminated` display contract. Whether these protocol frames are intentionally consumed internally or a notification is lost remains **unverified**. A concrete [upstream report draft](2026-10-14-shutdown-upstream-draft.md) records that question; it has not been posted.

Ordinary peer exchanges worked. Native agency final revisions reached the lead in both runs, but the built-in control's final Kaan revision exists only in the peer record; the lead disclosed this and checked the updated file. That missing final handoff remains unresolved. The two native successes do not erase it. The naturally late lifecycle-notice, failed/declined-request and nine-specialist paths remain **unverified live**.

The control's Bash error was the deliberately blocked `cd deliverables && cat hypothesis.md email.md`; read-back recovered. The earlier native agency had one production mode-line hold: its log reached the 8000 ms cap with no saved text, then released the next call after the line became visible. The default case had no hold at the same setting. These do not establish that raising the wait to 10 seconds fixes the lag, so no timeout change is made.

Keep structured shutdown and stable completion. This evidence calls for neither renewed discovery restrictions nor a production mailbox reader, Stop gate or forced termination. Repeating the same paid probe without a new hypothesis is unnecessary. Track lifecycle visibility separately while continuing the image-route work for CLI, VS Code and Desktop **Code tab**.
