## What this shows and what it does not

Shown once each, typed by a human: the session guard in its file form and the inline role guard as an agent's own hook block a forced push, and both block when they cannot run, with the Host's notice `failed; blocking because onFailure is "block"`. This closes two limits the "Factory hooks" row was closed with on 2026-11-18: the inline guard as an agent's own frontmatter hook (for a main agent), and what a user sees for a blocked call.

It also corrects the weight of finding G6 of the headless record. That finding (the Host puts the hook's whole command line in front of every refusal, so an ordinary block begins with the words of the failure message) was the reason the session guard's script was moved into a file. In interactive sessions the notice says `[command hook]` and never showed the script, with the inline form as well (2A). So the long notice is, on what these sessions show, a property of the headless run that printed it and not of what a user at the terminal sees. The file form still shortens what a headless or scripted run prints and reads; it was not needed for the interactive notice.

Not shown: everything in the rows above marked so.
