## Slice (a): the kickoff prompt of `agents start` (test 1, session `3c47fef7`)

- The argv was `--agent <lead> --add-dir <workspace> <prompt>`. `claude --help` declares `--add-dir <directories...>`, a variadic option, so the prompt was read as a second directory and the input box stayed empty (seen on 2.1.291). It is now `--agent <lead> --add-dir=<workspace> <prompt>`: four elements, the value inside its flag. A test models the host's variadic rule on the argv (the old argv reads as `--add-dir [workspace, prompt]` and no operand).
- **Seen:** after `agents start digital-agency --host claude` the first record of the session is the bootstrap prompt, and the Opus lead answered on its own (8 `ToolSearch` calls, one `Bash`, an introduction), 0.6070 USD, one prompt. The kickoff reached the model; what the lead did with it is slice (b).

## Slice (b): the mode line, first

**What the text rule did.** The rule was moved from a bullet into a section of its own right after the floor, tied to the first call other than `ToolSearch`, extended to "search all six names" and to "an order about the work does not move the line", and the `agents start` kickoff names the section. Conclusive checks of the text alone: **3 of 11**.

**The probe** (`n2-hook`, `b164b3d5`): a logging-only script on the lead's frontmatter, never blocking.
- `UserPromptSubmit` in agent frontmatter **fires** for a `--agent` main session; its input carries `agent_type`, `prompt`, `session_id`, `transcript_path`; its `additionalContext` reached the model as a `<system-reminder>` record. The transcript file did not exist yet at the first prompt.
- `PreToolUse`: the transcript held the **current call's `tool_use` in 0 of 12 runs**, and it lagged seconds behind (29 lines at each of eight `ToolSearch` calls in two seconds, 53 at the next call). The host docs say the same ("written asynchronously and may lag"). A gate that waits for the line to show up would block a lead that did write it.
- The lead's frontmatter hook also fired for **Ava's** calls (they carry an `agent_id`), so the gate ignores any call that has one. The script ran in 1 to 2 ms.

**The gate** (`agents-united-mode-line-gate.js`, a PreToolUse group of the lead only, matcher `*`): the first main-thread call other than `ToolSearch` is held once per session (exit 2, a message that says what to write), a call within two seconds of that is held with it, later calls pass; the state is a marker under the temp directory; every error lets the call through. The script is module-neutral (no `require` at the top: a `.js` file in an ES-module project would crash and the host would let the call through; a test runs it in both scopes).

## Slice (c): the shutdown reply

- **The pattern.** Emre in test 3 (`6c86e269`): a consultation answered with `SendMessage` and a string at 10:01:49 with no load; the shutdown request at 10:02:01 carried the host's own text with the exact object form; two replies with the JSON as a string were refused at 10:02:03.6 and 10:02:05.8; `ToolSearch select:SendMessage` at 10:02:07.7; the object was accepted at 10:02:09.0. The second H9 retest (Emre, 14:27:49 to 14:27:57) has the same order. A teammate that had loaded `SendMessage` first replied with the object at once. The pair of examples and the template in the request (the first version of this slice) did not prevent it.
- **Tests 4 and 5 (before the fix, three task-flow teammates each):** 0 refused in 6; each ran `ToolSearch select:SendMessage` about two seconds before its reply, its first use of the tool. Not discriminating.
- **The fix:** the load is tied to the reply in the nine bodies, to the lead's brief template ("before your first reply, load `SendMessage` with `ToolSearch`") and to the request's reason. **After it** (tests 4b, 5b and the probe): 7 of 7 teammates loaded it at spawn, 10 to 25 seconds before the reply, and 0 were refused. The probe is the discriminating case (Ava consulted by `SendMessage`, then shut down): one sample.

## Slice (d): the route wording and the three loose ends (test 3)

- **Recommendation:** the install question offered "Manual install + restart (Recommended)" with the pinned reason (`@playwright/mcp@0.0.83`, `chrome-devtools-mcp@1.10.1`, no key, no browser download), "Plugin route, no restart" (floats with the plugin's version), "No MCP, Bash fallback", "Change the map first". Its manual option says a restart "ends the team", while no teammate existed (the consultant had been shut down): the rule against recommending for the team's sake held, the sentence is still loose.
- **Consultation first:** Emre was consulted at 10:01:43 and `mcp-setup` was loaded and its reference read after his answer and before the question.
- **`ToolSearch` after the reload:** after `/reload-plugins --force` the lead said it would run the check itself and called `ToolSearch` for three plugin tool names before any task or spawn; all three were found.
- **Plain `/reload-plugins`** (test 2, `6ab914da`): in a session with a model turn, with the context7 plugin installed from another terminal, it printed `Reloaded: 1 plugin ... 1 plugin MCP server` and listed `plugin:context7:context7` as needing authentication: no warning, no skip. That plugin adds no tools until the user authenticates, so the docs' skip condition (the reload would change the loaded MCP tools) did not arise. The case that can fail (the playwright plugin) was not run.

## Across the runs

- **Held:** the kickoff reaches the session; the route question recommends the manual route with its pinned reason; the consultation comes before the install question; the lead calls `ToolSearch` after the reload; 0 refused shutdown replies in 7 teammates after the load fix; the gate holds the first call and, once the message stopped offering a way out, the lead wrote the line.
- **Did not hold:** the mode line by text alone (3 of 11); the first version of the gate (a false claim); the mode line is written twice when the lead complies in the same message as the call, because the gate cannot see that message.
- **Found:** the lead's frontmatter hooks fire for its teammates' calls; the transcript is not a usable witness for a hook; `claude -p` skips the frontmatter hooks of a project agent (the host docs: `-p` does not count as accepting trust), so the headless checks cannot measure the gate; `claude -p` has no `--max-turns`, and an Opus session costs about 0.5 to 0.6 USD for one kickoff because of its 112k to 193k tokens of cache reads.
