## The probe (the maintainer, `h9-probe`, 0 model prompts)

A session of plain `claude` in a folder with no `.mcp.json` stayed open in terminal A; in terminal B `claude mcp add --scope project playwright -- npx -y @executeautomation/playwright-mcp-server` wrote the folder's `.mcp.json` (`type: stdio`, `command: npx`, `args`, `env: {}`).
- Terminal B, `claude mcp list` / `/mcp`: playwright listed, **Pending approval**.
- Terminal A, the running session, `/mcp`: **not listed.** `/mcp reconnect playwright`: **`MCP server "playwright" not found`**; `/mcp` again: still absent.
- After `/exit` and `claude --continue`: a startup prompt "New MCP server found in this project: playwright" with three choices ("Use this MCP server", "Use this and all future MCP servers in this project", "Continue without using this MCP server"); after the first, `/mcp` showed playwright **active under Project MCPs**.

So a running session never picks up a server added after it started, `/mcp reconnect` does not help for a server it has not loaded, and the way in is a restart that offers the approval prompt. The lead's design must end the install with a restart command, not a reconnect.
