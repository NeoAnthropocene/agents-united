## What these runs show and what they do not

- **Shown once, on this machine, Host version `Claude Code 2.1.325` and model `claude-sonnet-5-5`, in an interactive session:** the three fixes of P24 work on the Host (the entry dry run from the workspace root without help; the contract return written by the shipped script and accepted by the postflight; review jobs built by the shipped builder with the digest taken first and accepted at the first check). The P25 return script for `author-skill` is used by the fork and its return is accepted. The whole typed-route journey for a Skill and a shared pair reaches two reviews that pass the caller's check without any intervention by the sitter.
- **Shown once, in the headless session:** a whole realize-and-review journey runs headless to its end with the P22 to P25 texts and scripts: the coordinator uses the headless exception, the session waits inside each worker call, the review job is built by the shipped builder and accepted, and a review record passes the caller's check. Compared with the headless run of 2026-11-15 (before P16): there the launcher's dry run had been refused and the review record had failed its checker; neither happened here.
- **Shown once, in the headless sync run:** after P16 and P22 the host-update sync route runs headless to its end: the sync worker is started with the headless exception, returns inside the call, and its plan passes the installed checker and equals the prepared answer.
- **New findings (none fixed; no fix is designed):** C-1 (the briefs' `roots.workspace` field is refused by the task schemas; both sittings), C-2 (the shape of a `claimedChecks` entry is found only by reading the script's source) and C-3 (where the caller saves the evaluator's result; both runs). H7 (a wrong count in a final message) is a smaller point.
- **Not shown:** in the sitting, a repair on a typed route; reuse or update tasks; a worker that never reports and the stop-waiting exit; a refusal by a return script on a real alias of a protected folder; a session typed by a human on a screen; the same on `claude-fable-5-2`; another permission mode; a second machine; a later Host version. In the headless run, a repair; the typed routes; a worker that fails or never returns; the budget cap being reached. The quality of the drafts, the produced agent and the reviews was not judged.
- **Not determinable from the record:** in the sitting, whether the fixes or the second attempt at the same task by the same model explain each improvement over Sitting B; in the headless runs, whether the session would have waited without the prompt's sentence "ending your turn ends the session, so wait for each worker's result in the same turn", or without `run_in_background: false` (no such run was made), and why the final message counts four worker turns.

- The content and quality of the drafts, the produced agent and the reviews were not judged.
- Neither headless run was repeated without `run_in_background: false` or without the sentence at the start of its prompt, and the fixes were not observed in isolation from the second attempt by the same model.
