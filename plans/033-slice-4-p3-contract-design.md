## Purpose and independent delivery units

[ADR 0048](../docs/adr/0048-agent-factory-quality-and-contributor-tooling.md) requires an additional contributor Skill to reuse, author and check a shared definition and companion Subagent Contract. The authored pair has exactly `definition`, `workflows`, `skills`, `hooks` in its contract. Native loading, tool grants, guard kinds/registration and invocation stay outside it. A valid pair alone establishes neither installation nor Host support.

**P3a** is a host-neutral read-only CLI over the existing validators. It is the smallest independently reviewable implementation. **P3b** adds the compact `author-contract` Skill, bounded two-file draft helper, required Claude loading/resources and installed-package proof. P3b depends on P3a. Do not combine either with evaluator, templates, session-reader distribution, main-thread orchestration, another realization adapter or sync. Complete and review Claude before Codex → Antigravity → Cline; OpenCode remains later.

## P3a exact public seam

`agents contract-check --registry <absolute-selected-registry> --definition <semantic-stem>` emits JSON containing `valid`, selected definition, actual pair paths/hashes, deterministic findings and explicit delivery/quality/live limitations. A malformed/missing/mismatched pair exits nonzero. An unavailable native binding is not a shared-schema failure and cannot become a delivery success. No Host argument or profile/tool-policy requirement belongs in this command.

Implementation paths: `src/core/shared-pair.ts`; central input/result types in `src/core/types.ts`; CLI options, output and actual exit in `src/cli.ts`; public tests `tests/contract-check.test.ts`. Invoke the pinned selected checkout's built `dist/cli.js contract-check`; do not assume an older global CLI supplies it. Reuse `loadSemanticCore` and `validateSubagentContract`. This retains registry-wide fail-fast parsing: an invalid unrelated core in the selected registry is reported as that source error, rather than incorrectly blamed on the requested companion. A two-file standalone draft registry is a supported input. Do not refactor P2's native adapter in this slice merely to share code.

Require an absolute selected registry and a semantic identifier. Verify the selected registry/pair and their ancestors are real files/directories, within their resolved roots, without symlinks/junctions or traversal aliases. Read only; before/after full inventories must match. Preserve current legacy schema behavior. P3b's strict authoring-input schema may reject unknown fields for new material without turning that policy into a breaking rewrite of historical cores.

First red: the public command/result is absent. Meaningful subsequent reds: missing companion/core, mismatched definition, fifth contract key, non-array/duplicate/malformed affordance identifier, actual forbidden token in core fields or body, absent required core safety field, linked pair/root, path traversal, and source error in another core. Capability classes remain host-neutral and use the existing allowed/grantable-class validation. A syntactically valid but unknown permitted Skill/workflow/hook is not falsely described as structurally invalid; its source/binding availability is a separate unresolved finding for the authoring task.

P3a completion evidence: actual CLI red/green and exits, complete JSON result and hashes, no-mutation checks, a two-file registry with no native folders, failure classification, applicable typecheck/build/full tests and complete raw output. No installation or ownership code changes are planned; use the full lifecycle matrix if that scope changes.

## Fixed job, grants, output and acceptance

The caller fixes create/reuse/update mode, local/upstream intent, semantic objective/fixed values, artifact stem, existing-pair/source pins and disposition/licence evidence, selected validation checkout HEAD/runtime/CLI hash, source registry, permitted affordances, explicitly required dependent bindings, complete immutable baseline, exact permitted changes, draft/evidence/managed/protected roots, constraints, acceptance and check budget. Keep the canonical job digest outside the worker's mutable report. Shared-only authoring has no target Host; if subsequent realization is requested, name it separately from the Host running authoring. Resolve missing required inputs once; do not repeat intake already satisfied by the job.

Nominal task needs are read/search/edit/shell/report/hand-back. The built-in general-purpose fork inherits its actual tool pool and session policy; this proposal adds no class-derived restrictive tool grant or new preapprovals. Guidance excludes delegation, messaging, network/provider calls, installation/publication and protected-root writes. Offline path/scope checks constrain helper behavior; they do not isolate the entire fork, shell or other installed Skills. Do not claim transport isolation, a first-action gate or a custom guard. A narrower custom role would require its own concrete design instead of silently changing this pattern.

The helper applies **already-authored** core values/text and contract JSON to only the two declared source-draft paths. Structured new fields serialize as safely quoted YAML scalars/arrays; no arbitrary template evaluation, model/network/installation or job-supplied command execution. Reuse returns the supplied pair byte-identically. Update requires complete before bytes, proposed after bytes, fixed-value/protected-note pins and agreed change scope; helper checks paths/hashes/pins and reports the full diff. Semantic agreement with the requested changes still requires caller review and validation, rather than a promise of semantic enforcement by the file writer. Preserve every unrelated baseline file and explicit protected note.

The caller runs the pinned public validator on the actual proposed/final pair and reads complete raw output and actual exit. Return full inventory/lengths/hashes, complete before/after diff, reused-byte comparison, source/provenance disposition, validation commands and logs/exits, binding coverage/unavailable edges, quality findings and open items. The caller independently compares its job/digest, reads final bytes and reruns the validator. Helper presence and worker-authored check receipts do not establish execution. Deterministic validation, evaluator judgment and live Host proof remain separate fields; evaluator/quality pending and live unverified stay explicit.

Required versus optional binding intent is external to the four-field permitted lists. Unknown permitted identifiers need source/binding findings; an explicitly required missing edge blocks dependent realization. An optional permitted-but-unused Skill is not a mandatory preload. A valid shared-only draft can be delivered with native realization unavailable, with no installation claim. Core floor changes are shared semantic changes for review, not native workarounds.

Worked-case budget: at most six named offline checks/600 seconds with bounded raw log bytes; zero host/model/provider invocations, zero prompts/USD. Local intent ends at checked draft hand-back. Upstream intent prepares the complete pinned `.github/PULL_REQUEST_TEMPLATE/artifact-contribution.md`, base `dev`, `sent: false`, stating the pair and native delivery gaps; no publication follows.
