## Executable validator prerequisite

P2 also needs a small read-only adapter for the existing validators. Exact public seam: **`agents factory-check --registry <absolute-source-registry> --definition <core-stem> --host claude [--artifact <absolute-native-agent.md>]`**. Run it through the selected checkout's built `dist/cli.js`, pinned by the job; do not assume a globally installed CLI has this command. Without `--artifact`, it checks the supplied shared pair before authoring; with the option, it also checks the actual candidate native agent. Initial support is explicitly Claude agent artifacts. Other host/type validation needs its own complete reviewed adapter and is unavailable here; this does not begin another factory host stage.

Implementation paths are `src/core/factory-check.ts` (pure/read-only validation orchestration), shared input/result types in `src/core/types.ts`, and the command/JSON output in `src/cli.ts`. Reuse `loadSemanticCore`, `validateSubagentContract`, `checkFloor`, host profile/tool policy/grant resolution and existing native guard/residue checks. The command must detect an impure or missing core, mismatched/invalid four-field declaration, unknown native key or missing required field, floor/grant drift and ineffective required native guard/loading edges. It neither authors/repairs the pair nor starts the separately accepted contract-authoring helper.

The binding supplies loading context separately: `--loading subagent|main` defaults to subagent, and `--required-skills <JSON-array>` defaults to an explicit empty list. The latter names required preloads for this task; it is **not** inferred from the contract's permitted `skills` list. A permitted-but-unused Skill can remain optional. Every declared native preload must be permitted and have its source; every task-required preload must actually be declared. Source/registration checks do not prove runtime loading. Preserve the distinction between baseline native safety hooks and custom semantic hook affordances; ADR 0056's passive empty hook declarations do not disable native guards.

The initial class-derived adapter has no reviewed binding for implicit memory writes or a native deny overlay that changes its effective grant. It rejects `memory` and `disallowedTools` with explicit unavailable/grant findings. It does not infer an effective grant from the allowlist alone when those fields are present. The worker binding likewise rejects the deny overlay; broader bindings need their own concrete review.

The same bounded adapter accepts exactly the reviewed baseline guard registration. Additional hook events/groups are unavailable until their own source and binding review; merely containing the required subset cannot establish the effective hook behavior. The factory's own binding already applies exact registration equality. Keep custom semantic hook permissions distinct from that native baseline safety requirement.

Public tests: `tests/factory-check.test.ts` and CLI cases in `tests/agent-factory-realization.test.ts`. First red is the absent command/API; negative cases use actual mutated candidate bytes, not assertions mirroring the runbook. Results distinguish deterministic findings, quality review pending and live Host behavior unverified. No model call or file mutation belongs in this adapter.

The job/hand-back scripts validate record structure, input/output pins, roots, inventories and check receipts. They do **not** execute supplied check commands or treat worker-authored receipts as execution proof. The caller runs the pinned `factory-check` command on inputs before dispatch and the final artifact after return, reads complete output and actual exit, and rejects failures. Missing build/dependencies/checker or required binding resources block the dependent work; file presence is not execution. This adapter is a validation seam for P2, not the separate contract-authoring Skill, evaluator or packaged session reader.

Job version 1 fixes:

- `id`, `operation` (`create`/`update`), `intent` (`local`/`upstream`), `artifact` (type/definition/expected source-relative paths, native loading context and explicit task-required Skill preloads).
- `authoringHost` (Claude Code CLI/workspace/native/observed version) and separate `targetHost` (host/surface/scope/lane, observed version or explicit unverified reason, profile minimum/reviewed baseline).
- `source` (absolute validation checkout, actual HEAD SHA, absolute selected source-registry root). Source registry may be a separate private source root; do not pretend it is committed to the validation checkout. Pin every actual input independently. A fixed read-only Git query can verify checkout HEAD; no job/result-supplied command is run by a checker.
- `roots` (workspace, draft, evidence, managed destinations, protected roots) and complete output baseline. Physical ancestor resolution and explicit link rejection apply to existing and absent children; normalize Windows comparisons. Reject overlap of writable roots with source/managed/protected roots and ambiguous case-equivalent destinations.
- `inputs` with kind, absolute path, SHA-256, cited sections and clear/held status: required guide and cited locked snapshots, observations used, profile, tool policy, supplied core/contract and required skill/guard bindings. Missing/held dependencies block their action; script presence proves no validator execution.
- `baseline` is the complete pre-edit draft inventory, with hashes/lengths and pinned immutable snapshot bytes for reconstructing actual diffs; `preserved` pins source/input and task-specific untouched files. Create requires an empty baseline. Update must match the baseline before work; postflight compares changes against the same trusted baseline rather than demanding the draft still equal its pre-edit bytes.
- Disjoint `allowedChanges.create/update/delete` relative paths, `constraints` (fixed values, file/format/size limits, prohibited actions), `acceptance` records and a caller-fixed `checks` allowlist (id, executable/argv/cwd, limits).
- `budget`: at most six named offline checks and ten minutes for the worked case, bounded raw log bytes; host/model/provider permission false, USD and prompt caps zero. A ceiling is no spending authorization. Helpers perform no supplied check commands; the worker/caller runs only the agreed checks under that budget.

Canonical digest uses recursively sorted object keys and unchanged array order. Every worker/repair/evaluator brief carries that digest and the complete fixed record or its exact path. It is a content pin, not an authentication credential or execution sandbox.

Result version 1 fixes job id/digest; `status` draft/blocked/partial; complete artifact inventory (path/kind/bytes/hash); actual before/after diff; guide and binding/delta coverage; provenance; check receipts; separate quality findings, live evidence and open items. Check receipts name the job digest/revision, exact allowlisted argv/cwd, start/end, actual exit/classification and full stdout/stderr paths/hashes. A worker-written receipt is a claim: independent caller execution or a trusted executor record is still needed. A missing/skipped required check cannot become a draft acceptance. Blocked/partial results can be valid honest reports without becoming completed work.

Postflight enumerates actual draft bytes, rejects omitted/extra/duplicate/traversing/linked paths, compares all lengths/hashes and reconstructs diffs against the pinned baseline. It verifies preserved inputs and bounded logs, rejects mismatched job/commands/paths/exit classifications and never executes result text. It cannot establish semantic quality, actual host loading, execution from untrusted log text, or general filesystem isolation. Evaluator unavailable/quality pending remains explicit in P2.

Public tests in `tests/agent-factory-realization-job.test.ts`, `tests/agent-factory-realization-handback.test.ts` and `tests/agent-factory-realization.test.ts` exercise installed CLIs and actual validator APIs. Compare complete before/after inventories; use no real host/model/provider session. Package tests must run the actual production registration after P2, not mistake P1's explicit registry fixture for shipped content.

Reuse the current #208 reader later through its separate distribution delivery. P2 uses `SubagentHandback` only when supplied; otherwise ordinary final response. Foreground `Agent` call explicitly passes `run_in_background: false` and omits teammate `name`. No shutdown frame, notice wait, messaging grant or new team mechanics.

## Compatibility amendment before activation repair

The first production activation run exposed a real regression in `tests/agent-factory-lifecycle.test.ts`: the existing direct `author-skill` request was previously the complete one-Skill restricted bundle, and adding realization made it fail the partial-bundle gate. Preserve that approved direct loading route without silently adding the new worker. In `src/core/installer.ts`, only the existing sole `author-skill` item may retain `agent-factory` ownership/rules when the owner still has no parent, legacy agents, workflows or orchestrator. Its resolved Skills remain just `author-skill`; native factory registration stays inactive. Generic partial restricted bundles and direct `realize-artifact` requests remain refused. Public tests assert the old entry/support, owner and native lane, plus absence of realization files and refusal of the new partial entry before writes. This narrow compatibility exception still requires the full addon matrix because it touches installation/ownership resolution.

The actual upstream template is `.github/PULL_REQUEST_TEMPLATE/artifact-contribution.md` with base `dev`; no `dev.md` template is created. Postflight's valid-record flag never means acceptance: `acceptedDraft` remains false until independent caller checks/review outside that record checker. Worker quality findings are returned intact, separately from deterministic findings.

The existing native-ceiling test helper inferred a legacy stem and specialist model for every source. The full gate exposed that inference on the native-only worker. Its conformance review must resolve the definition from the real `agent-factory-realize.binding.json` and check the already-approved subagent posture (inherit/medium), rather than invent a legacy carrier or exempt the worker. Tests also mutate its model to prove that mapping does not approve arbitrary posture. This changes test-side conformance interpretation only; production binding validation remains strict.
