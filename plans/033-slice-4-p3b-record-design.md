## Fixed job schema

`draft-pair.mjs <absolute-job.json>` reads `../assets/job.schema.json` relative to its own module. Reject unknown top-level and nested keys; support only that bundled schema's small, reviewed vocabulary and fail on unknown schema keywords. No external schema references or network resolution. The job has these fields:

| Field | Required meaning |
| --- | --- |
| `version`, `id`, `mode`, `intent`, `definition` | Version 1; nonempty job id; create/reuse/update; local/upstream; semantic stem. Output names are derived from the stem, never supplied arbitrary paths. |
| `objective`, `fixedValues`, `constraints`, `acceptance` | Complete semantic task, literal values that must survive, scope constraints and observable acceptance criteria. Presence does not prove semantic compliance. |
| `source` | Absolute reviewed validation checkout, actual expected Git HEAD, selected input registry and pins for every required file read. Keep this separate from the output registry and from the Host running authoring. |
| `loading` | Pinned installed entry, attribution rule, binding receipt and required support/rule files. Built-in general-purpose/foreground and exact surface; no inferred prior conversation. |
| `validator` | Pinned Node executable and selected checkout's built `dist/cli.js`; caller uses only `contract-check --registry <actual-input-or-draft> --definition <fixed-stem>`. Availability is not execution. |
| `draftRoot`, `evidenceRoot`, `managedRoots`, `protectedRoots` | Absolute roots, disjoint from each other and validation/source inputs. Explicit protected locations supplement the managed-output path check. Evidence snapshots/logs are outside the mutable draft. |
| `baseline` | For update, complete relative file inventory with lengths/SHA-256 and immutable snapshot pins outside the draft. Create/reuse have an absent output root and empty baseline. |
| `allowedPaths`, `protectedNotes` | Only the derived `core/<stem>.core.md` and `core/<stem>.contract.json`, with an explicit update subset. Preserved literal note fragments are pinned to declared baseline files. No file deletion. |
| `proposal` | Exactly the mode-specific already-authored data below; not a prompt that the script interprets. |
| `bindings` | Explicit kind/id, required-for-this-job flag and source evidence pins for permitted Skills/workflows/hooks. A required missing source blocks this job; unlisted/optional permitted identifiers produce unavailable findings. Source checked never means loaded or executed. |
| `provenance` | Original/inspired/adapted, author/owner, inspected licence/source/comparison/notice pins as applicable, unresolved items. Read the actual evidence; its existence is not a legal or originality verdict. |
| `contributionTemplate` | Local: absent. Upstream: exact pinned `.github/PULL_REQUEST_TEMPLATE/artifact-contribution.md` inside the selected checkout, not a fabricated replacement. |
| `budget` | At most six named offline checks/600 seconds and bounded raw logs/files/bytes; host/model/provider false, prompts/USD zero. It authorizes no live spending. |

Every path/hash/length pin is checked against actual bytes. Resolve ordinary ancestors and reject links/junctions/traversal, reserved/case-colliding names, wrong file types and source/output/evidence/protected overlap. The helper verifies expected HEAD using a fixed read-only `git -C <checkout> rev-parse HEAD` call, never a command from the record. It executes no validator, install, publication, model or provider command. Its evidence report states that only this fixed source-identity check ran.

The small draft's file/byte ceilings must be explicit in the job/schema; a larger registry or unsupported file format is unavailable to this bounded helper. Preserve the draft and identify the needed manual/scoped workflow instead of truncating its baseline. A complete snapshot includes unrelated notes, not only the two changed files. A stale/missing/extra baseline entry blocks replacement. Recheck the complete baseline immediately before replacing the staged directory; recover the preserved original if replacement fails.

## Mode-specific proposals

**Create:** output root absent; `proposal` contains structured `core`, `body` and the exact four-field `contract`. Core keys are the five required scalar fields (`identity`, `mission`, `scope_boundaries`, `output_contract`, `safety`), `invariants`, optional capability classes. Reject unknown authored core keys and wrong types. Serialize scalar/array values using safe JSON quoting, which is valid YAML, rather than evaluating templates or accepting injected frontmatter. Append the supplied body as text. The caller executes the actual shared validator; the helper does not reproduce the entire Semantic Core policy.

**Reuse:** output root absent; `proposal` contains pins for the existing core and companion. Copy both byte-for-byte, including body notes/JSON formatting; do not normalize them. The caller has run `contract-check` against the pinned original input registry. Required missing source/binding evidence blocks the dependent task; optional unknown permitted affordances remain separate findings. Reuse compatible shared floors rather than editing them for a native preference.

**Update:** output root exists with a complete immutable baseline. `proposal` contains `coreText` and/or an authored four-field `contract`, exactly matching the allowed subset. No missing file or deletion is disguised as a successful repair. Preserve all other baseline bytes and every protected note. Full proposed core text allows existing YAML formatting/extensions to survive; the helper does not parse or validate arbitrary YAML. P3a intentionally preserves historical core schema behavior, so neither helper claims it rejects every unknown YAML key. The caller reviews the actual semantic diff and invokes the validator on final bytes. A new core key supplied through the structured-create object is a different case and fails its strict authoring schema.

Adaptation must retain required inspected licence/notice bytes in the supplied pair or unchanged baseline locations. If complying would require a new third file, this two-path helper cannot silently widen its scope. Prepare that complete source baseline through an explicitly scoped manual task, or return the precise unavailable edge. No waiver of attribution requirements follows from the two-file limit.

The executable `provenance.upstream` record for adapted work names repository/path/full commit and pinned source, licence and comparison files, plus declared required notices as `{ source: pin, targetPath, mode: "file" | "fragment" }`. At least one notice retains the inspected licence bytes. `file` requires exact final file equality; `fragment` requires those exact bytes inside the named final file, allowing a core's body to carry a complete notice. Missing pins or lost notices block writing. Original/inspired work cannot carry this adaptation record. These deterministic checks verify declared bytes, not whether the declaration is truthful, legally sufficient or audit-cleared; the report keeps attribution/legal review pending.

## Checked result and caller procedure

The helper emits a canonical full-job digest, mode/intent/source identity, actual complete inventory with paths/lengths/hashes, complete before/after text diffs for changed paths, unchanged baseline inventory, protected-note results, source/licence/notice dispositions and unresolved binding/quality findings. A prepared result reports deterministic writing only: `acceptedDraft: false`, validation execution unverified, quality pending, live unverified. Do not call a declared command executed or promote source-file presence to quality evidence.

Binding records are `{ kind: "skill" | "workflow" | "hook", id, required, evidence: [path/hash pins] }`. The helper checks kind/id against the final permitted contract, rejects duplicate declarations and returns one finding per permitted affordance. Required means required for this fixed authoring job; do not mark a future native edge required merely because it appears in a permitted list. Missing/changed optional source pins remain unavailable findings, not false execution proof. The caller retains the required/optional choices in its original digest.

The caller retains its original digest, reads the returned paths, reconstructs the entire inventory/diff and unchanged files, checks source pins and runs the pinned `contract-check` on the input pair when applicable and final output pair. Save full stdout/stderr, actual exits and log hashes within the budget; compare results with the helper's fixed definition and final hashes. Only the caller can complete that check. Evaluator findings remain unavailable until that separate delivery exists; no worker self-report substitutes for them.

Local intent stops at the draft/report. Upstream intent returns the complete existing contribution-template body plus final pair evidence, base `dev`, `sent: false`. Neither route installs the output registry, advances a host-library hold/baseline or publishes anything. The new loading binding concerns the helper's Claude entry; any required target realization/binding is a distinct input/output finding outside the four-field permitted lists.
