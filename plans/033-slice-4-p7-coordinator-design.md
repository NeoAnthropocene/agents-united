## 6. Fixed inputs, roots, budgets and runtime sequence

No new pipeline-check CLI or schema engine is proposed. The compact coordination brief/report is an audit structure referencing **existing executable P2/P5 records**, not a deterministic orchestration engine. A prompt can omit a step; offline fixtures cannot prove conversational adherence. Resolve ordinary factoring within this design; a new checker or expanded schema requires another explicit seam review.

The caller holds: original objective/literal fixed values and explicit unknowns; create/update and local/upstream intent; supplied shared pair/agent identity/allowed changes; authoring and target Host contexts separately; actual validation checkout HEAD and selected source registry with independent pins; clear guides/cited locked snapshots/observations/profile/policy/loading/guards/support; actual built validator and physical Node>=24 pins; exact allowlisted executable/argv/cwd/time/log checks; immutable complete baseline including preservation-only notes; acceptance/rubric; actual installed main/worker closure; authorized repair count and limits. Missing shared pair returns a separate author-contract task/rework, not silent invocation of a new fork. Held/unavailable required inputs block their dependent action; optional gaps remain explicit.

Use caller-selected absolute `draftRoot` and `evidenceRoot`, disjoint from each other, selected source/checkout and managed/protected paths. Under evidence retain `brief.json`/caller-held digests and immutable revision directories `r0/` and optional `r1/`, each containing original P2 job/baseline snapshots, producer return, separate caller checks, and P5 review job/result/checks. Each P5 review root is disjoint from candidate/read roots as its checker requires. Never overwrite previous jobs/results/logs on repair. Relative path layout is runbook guidance, not a new installed filesystem service. Unknown properties still fail existing worker schemas; do not insert coordination-only fields into those jobs.

Propose **default zero automatic repair, optional maximum one** only when the caller's accepted brief already authorizes within-scope repair and its account/dispatch budget. One initial realizer plus evaluator, at most a second of each: four sequential worker turns total; no parallel same-file actor. Aggregate all caller/producer offline execution for this journey: at most **24 actual validation processes, 1,800 seconds and 8 MiB complete raw output**, while each worker/review job retains its smaller <=6 check/600-second and log caps. Count preflight/postflight/caller reruns rather than resetting the aggregate when starting another revision. Missing budget stops with rework. This is a proposed runbook budget, not enforced OS limits or permission to spend.

Use the intersection of P2/P5 candidate limits: at most **32 files, 1 MiB total, 256 KiB each**; review ordinary evidence <=64 files/8 MiB/1 MiB each; result <=256 KiB, 32 findings/16 open items; separately pinned executable <=128 MiB. Complete selected inputs that exceed limits need explicit partition/review, never truncation labeled full coverage. Repository implementation full gates are outside this runtime-job budget.
